# Domain docs

本仓库采用 single-context 布局。

## 探索代码前

- 阅读根目录 GLOSSARY.md，了解领域术语。
- 阅读 docs/adr/ 中与当前工作相关的决策记录。

文件不存在时直接继续。领域术语或设计决策实际形成后，
由 domain-modeling 技能按需创建。

## 文档位置

- GLOSSARY.md：本仓库共享的领域术语。
- docs/adr/：架构决策记录，采用 0001-<主题>.md 等编号命名。

## 使用领域术语

Issue 标题、重构建议、假设和测试名称应使用 GLOSSARY.md
定义的术语，避免替换为词汇表明确排除的同义词。

缺少术语时，先判断是否引入了项目并不使用的概念；
确有缺口时，记录下来供 domain-modeling 处理。

## 决策冲突

建议与已有 ADR 冲突时，明确指出对应 ADR 和重新讨论的理由，
不要静默覆盖既有决策。
