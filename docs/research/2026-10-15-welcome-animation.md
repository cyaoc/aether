# 欢迎动画：讨论记录（未定稿）

2026-10-15：方案讨论完毕，直播姬实测完成；OBS 没有实测。已开 issue：[#125](https://github.com/cyaoc/aether/issues/125)（总）、[#126](https://github.com/cyaoc/aether/issues/126) Core 和 CLI、[#127](https://github.com/cyaoc/aether/issues/127) GUI、[#128](https://github.com/cyaoc/aether/issues/128) 人工验收。术语见 GLOSSARY.md 的“欢迎动画”分组，方案取舍见 ADR 0006。

标记说明：**已定**＝讨论中已经定下的方向；**实测**＝在直播姬里实际测过；**推测**＝没有可靠来源或没实测过；**待核对**＝需要用户确认。

## 需求

指定的观众（按 UID）进直播间时，在直播画面上播放这位观众专属的欢迎动画。主播用 B站直播姬或 OBS 推流，两种都要支持。动画是**普通 MP4**（不透明），分辨率和画面比例不统一。

## 实测结果（2026-10-15）

环境：直播姬 Windows 版 8.10.0.11171，显卡 RTX 5060 Ti；测试服务跑在开发用的 Mac 上，直播姬通过局域网访问（见第十节）。

| 项目 | 结果 | 对设计的影响 |
|---|---|---|
| 直播姬的内核 | 基于 OBS 32.0.4（`obs.dll`、`obs-filters.dll`）；浏览器素材用的是 OBS 的 `obs-browser.dll`，CEF 105（Chromium 105.0.5195.127） | 浏览器素材是 OBS 的那一套 |
| 外部控制接口 | 没有任何 `websocket` 组件 | bot 无法控制直播姬，**只能走浏览器素材** |
| H.264 + AAC 的 MP4 | ✅ 正常播放，150 帧没有丢帧 | **不需要转码，也不用带 ffmpeg** |
| 有声自动播放 | ✅ 没有被拦 | 不需要特殊处理 |
| 声音进推流 | ✅ 进了；但主播本机默认听不到 | 主播自己想听，要在直播姬里打开监听（选项名称**待核对**） |
| 带透明的 VP9 WebM | ✅ 正常播放，CPU 1% | 可以支持 |
| WebGL | ✅ 走显卡（D3D11）；绿幕、左右分屏、黑底三种抠图都没有丢帧 | 抠图可行，第一版不用（见第三节） |
| 竖屏 720×1280 | ✅ 居中显示，两边透明 | 比例不统一没问题 |
| 小分辨率 640×360 | ✅ 放大铺满素材框 | 分辨率不统一没问题 |
| 浏览器素材的默认尺寸 | 800×600 | 操作指南要写明改成 1920×1080 |
| 动画页打不开时加载素材 | 素材一片空白，**不会把报错页推到直播画面上**，但也**不会自己恢复**；右键刷新后正常 | 见第六节"动画页的运行时间" |
| 已经加载过、bot 重启 | ✅ 服务停 4 秒后再开，0.15 秒内自动重连，不用刷新 | — |
| 刷新素材 | 会加载两次页面，旧的那个 17 秒后断开 | 无影响，推送发给所有连着的页面即可 |
| 直播姬的滤镜 | 没有绿幕抠图，只有蒙版、LUT 等；蒙版用固定图片定透明区域，LUT 只改颜色、不改透明度 | 直播姬帮不上抠图，要抠只能在动画页里做 |
| 多媒体素材 | 能播本地 MP4，但什么时候播只有直播姬自己能决定 | bot 触发不了，用不上 |

## 一、和推流软件怎么配合（已定）

bot 在本机开一个**动画页**（`http://localhost:端口/`），主播在直播姬里把它加成**浏览器素材**，在 OBS 里加成**浏览器来源**。指定观众进场时，bot 推送给动画页，页面播放这位观众的视频。

**直播姬和 OBS 用同一个动画页**，bot 只需要一套实现。

排除掉的其他方式：

| 方式 | 结论 | 原因 |
|---|---|---|
| 直播姬的多媒体素材 + bot 控制 | 不行（**实测**） | 直播姬没有外部控制接口 |
| bot 模拟快捷键切场景 | 不推荐 | 直播姬的快捷键覆盖场景、音频、直播和录制，没查到可以单独显示/隐藏某个素材；每位观众要一个场景；还会打断主播自己的操作 |
| GUI 开窗口播放 + 窗口捕捉 | 不推荐 | Avalonia 没有视频控件，要引入 LibVLC（原生库几十到上百 MB），窗口还不能最小化，CLI 也做不了 |
| B站开放平台的互动玩法 | 不行 | 本质上还是在直播姬里加载网页，多了开发者资质和审核，没有额外好处 |
| 让直播姬直接打开本地 HTML 文件 | 不采用 | 好处是启动顺序无所谓；但发布包是带版本号的目录，每次升级文件路径都会变，主播每次都得去直播姬里改路径 |

## 二、谁播哪个视频（已定：映射关系）

一个 UID 对应一个视频，映射写进设置文件；文件**复制**到 `data/welcome-animations/`，**保留原文件名**。

```yaml
# 欢迎动画的视频，文件放在 data/welcome-animations/ 里，每行一位观众：UID: 文件名
welcome_animation_videos:
  12345: 小明进场.mp4
  67890: 老板驾到.webm
```

- **为什么复制、不直接引用原路径**：原文件被移动、改名或删除，动画就会悄悄失效；`data/` 是可以整体搬走的（ADR 0002），升级时也是拷贝 `data/`（ADR 0005），引用外部的绝对路径换台电脑就断了。复制以后，原文件随便怎么处理都不影响。
- **为什么用映射、不改文件名**：映射明确、可读；CLI 用户直接改 yml 就行。
- 符合 ADR 0004 的格式：顶层是分组，分组下每项一行。以后要加背景类型，可以把值扩展成 `[文件名, 绿幕]`，只写文件名的旧写法继续有效。
- GUI 添加视频时：复制文件、写一行映射。文件夹里已有同名文件、但属于另一位观众时，自动加后缀 ` (2)`。同一个 UID 再选一次就替换，旧文件一起删掉。删除观众时，删掉这一行和对应的文件。
- 读取时：映射里的文件不存在，启动时警告，这位观众不播；文件夹里没被映射用到的文件忽略。
- 代价：现在的设置代码只认事先登记好的固定键。要新增两项支持：一是读取以 UID 为键的分组；二是 GUI 删除整行（现在的逐行改写只做替换和插入）。

## 三、视频格式和显示（已定）

- **MP4（H.264）直接播**，不转码（**实测**）。带透明的 WebM（VP9）也支持，不需要任何处理（**实测**）。
- **第一版不做背景类型（抠图）**：用户的动画都是普通 MP4。WebGL 抠图已经实测可行，以后有人拿着绿幕、黑底或左右分屏的素材来，再加上：

| 背景类型（以后） | 动画页怎么处理 |
|---|---|
| 绿幕 | 接近绿色的像素变透明；边缘可能有绿边，动画里本身的绿色也会被抠掉 |
| 黑底 | 越暗越透明，适合光效、粒子 |
| 左右分屏 | 一半是画面，另一半记录透明度（礼物特效常用，类似 VAP）；透明效果完美，还能硬件解码 |

- **分辨率和比例不统一**：每个视频都等比缩放进素材框、居中显示（CSS `object-fit: contain`），多出来的地方透明（**实测**）。低分辨率的视频会被放大，稍微糊一点。
- 动画出现在哪、最大多大，由主播在直播姬里摆放浏览器素材决定，对所有视频一起生效。第一版不给每个视频单独设位置和大小，也不做"小视频保持原尺寸"（那样每个人的动画大小不一样）。
- 普通 MP4 不透明，播放时会盖住素材框里的画面。想让它小一点，就在直播姬里把素材缩小、拖到角落。
- **播放失败要回报**：MP4 来源杂，编码可能不统一（比如手机录的 HEVC）。动画页播不了时报回 bot，日志和 GUI 里显示"某某的欢迎动画播放失败：格式不支持"，加视频后试播一次就能发现。
- 动画页把视频整个下载成 Blob 再播放（测试页就是这么做的），不依赖服务端支持 Range 请求，开始播放时也不用缓冲。

## 四、和文字欢迎的关系（已定）

两条通道各自独立判断：文字欢迎看欢迎条件，动画看映射里有没有这个人。同一个人两样都要，就把他也加进 `welcome.uids`。不做"只播动画、不发文字"的选项。

播放规则：

| 情况 | 处理 |
|---|---|
| 重复进场 | 同一位观众在同一个直播间连接里 10 分钟内只播一次（常量）；真的推给了动画页才开始计时 |
| 几个人同时进场 | 队列在 Core 里，一次推一个，等动画页回报播完或失败再推下一个（页面全断开就不等，最长等 2 分钟）；从进场到轮到它超过 30 秒就跳过 |
| 没有推流软件连着动画页 | 记一条"没播：没有推流软件连着"，不补播，不计时 |
| 试播 | 走同一个队列，不检查也不更新 10 分钟 |
| bot 账号自己 | 映射里填了就播，和进场欢迎一致（#102 没做：bot 连接直播间不会触发自己的进场） |

## 五、CLI 和 GUI（已定）

按 ADR 0003，播不播、播什么在 Core 里决定，两个外壳都能用。

- **CLI**：启动时打印动画页地址；推流软件连上、断开、播放、跳过、播放失败都写日志。限制：必须和直播姬或 OBS 在同一台电脑上（远程服务器的用法不做）。
- **GUI**：设置页加"欢迎动画"分组，包括：
  - 开关、端口、"复制地址"按钮
  - **"已有 N 个推流软件连着动画页"**：显示 0 个时，主播就知道要去直播姬里刷新素材（原因见第六节）
  - 观众列表：UID、视频、试播、删除
  - 界面细节按设计流程先在画布上出稿
- **试播**：不等那位观众进场，直接在推流软件里播一次，用来看位置、大小、音量和视频能不能播。不发弹幕，也不占 10 分钟的次数。**GUI 开着就能用**，不用登录、不用连直播间。直播中试播，观众也会看到，要在按钮旁边提示。CLI 不做试播。

设置文件除了第二节的映射，还要新增一个分组。生效时机沿用现有设置的做法，具体在 issue 里定：

```yaml
# 欢迎动画
welcome_animation:
  # true 或 false，welcome_animation_videos 里有这位观众时，进场在直播画面上播放
  enabled: false
  # 动画页端口，直播姬或 OBS 的浏览器素材填 http://localhost:端口/
  port: 17890
```

## 六、动画页（已定）

### 运行时间

- **GUI：欢迎动画开关打开时，只要 GUI 开着，动画页就一直运行**，不只在连直播间时运行。
- **CLI**：进程本来就只在观看直播间时运行，动画页跟着进程走。
- 原因（**实测**）：直播姬只在启动或刷新素材时加载一次页面，加载失败就一直空白，不会自己重试；页面一旦加载成功，bot 重启后能自动重连。所以动画页开着的时间越长，直播姬加载时撞上它没开的机会就越小。
- 剩下的唯一问题：直播姬启动或刷新素材的那一刻 Aether 没开。操作指南写"先开 Aether，再开直播姬"；如果 GUI 显示 0 个连接，就去直播姬里右键刷新素材。

### 技术选择

- 服务端用 BCL 自带的 `HttpListener`。不能用 Kestrel，因为需运行时版的用户只装了 .NET Runtime，没装 ASP.NET Core Runtime。
- 推送用 SSE（`EventSource`），浏览器自带断线重连（**实测**）。
- HTTP 没问题：`localhost` 被浏览器当作安全来源，回环地址的流量不出本机。换 HTTPS 反而更糟：只能用自签名证书，CEF 会拒绝。
- 地址统一写 `http://localhost:端口/`，不写 `127.0.0.1`：Windows 上 `HttpListener` 用 `localhost` 前缀才不需要管理员权限，这时用 `127.0.0.1` 访问会返回 400（**推测**，在 #15 的 Windows 手动验证时确认）。
- 只监听本机，接口全部只读，检查 Host 头，挡住 DNS 重绑定。只监听本机还有一个好处：macOS 不会弹防火墙提示（测试时监听局域网就弹了）。
- 同一个 `data/` 跑多个进程时端口会冲突：第二个进程只记警告、不播动画，直播间连接照常。
- 实现时要注意：macOS 上的 `HttpListener` 收到没有 Content-Length 的 POST，会直接回 411 并关闭连接（测试时踩到过）。

## 七、直播姬操作指南

### 已确认（2026-10-15，直播姬 8.10.0.11171）

1. 直播姬里点【素材】→【浏览器】，URL 填 `http://localhost:17890/`。
2. **尺寸改成 1920 × 1080**（默认是 800×600，只占画面一小块）。
3. 声音默认就会进推流，不需要额外设置。
4. 素材显示空白、或 GUI 显示 0 个推流软件连着时：**右键素材 → 刷新**。
5. 想让动画小一点、放在角落：直接在直播姬里缩小、拖动这个素材。

## 八、直播姬内部组件的自查方法

直播姬升级后，想确认它有没有加上外部控制接口，可以重新查一次。只看、不改，不要往直播姬目录里拷任何东西。

1. **找到安装目录**：右键直播姬快捷方式 →【打开文件所在的位置】。
2. **列出关键文件和版本号**：在安装目录的地址栏输入 `powershell` 回车，粘贴：

```powershell
Get-ChildItem -Recurse -Include obs.dll,obs-websocket.dll,obs-browser.dll,obs-browser-page.exe,libcef.dll,obs-filters.dll | Select-Object Name, @{n='版本';e={$_.VersionInfo.ProductVersion}}
Get-ChildItem -Recurse -Filter *websocket*
```

| 找到的文件 | 说明什么 | 2026-10-15 的结果 |
|---|---|---|
| `obs.dll` | 直播姬用的 OBS 核心版本 | 32.0.4 |
| `obs-browser.dll` | 浏览器素材用的是 OBS 的浏览器插件 | 有（没有版本号） |
| `libcef.dll` | 内置的 Chromium 版本 | 105.3.39，Chromium 105.0.5195.127 |
| `obs-filters.dll` | OBS 的滤镜模块（直播姬界面只露出了一部分） | 32.0.4 |
| 文件名带 `websocket` | 有的话，bot 也许能直接控制直播姬，值得重新评估 | 没有 |

**不建议**把 OBS 的 obs-websocket 插件拷进直播姬目录：插件和直播姬内置的 OBS 核心版本对不上，直播姬可能直接崩溃，升级时也可能被覆盖。

## 九、OBS 方案（没有实测）

### 主方案：浏览器来源（和直播姬用同一个动画页）

1. 在【来源】面板点【+】→【浏览器】→ 新建，名称填"欢迎动画"。
2. URL 填 `http://localhost:17890/`，宽 1920、高 1080。
3. **勾选**"通过 OBS 控制音频"：声音会作为独立音轨出现在【音频混音器】里，并进入推流。主播自己也想听到，要在【高级音频属性】里把监听设为"监听并输出"。
4. **不勾选**"不可见时关闭源"。
5. 自定义 CSS 留默认值（默认就是透明背景）。
6. 把这个来源拖到来源列表的**最上面**。

中文选项名是凭记忆写的，以实际界面为准。

**待核对**：OBS 官方构建的浏览器能不能播 H.264 的 MP4。CEF 默认不带 H.264，要编译时打开才有，OBS 官方文档里没写。等有 OBS 用户时，用测试页跑一遍。

### 备选方案：obs-websocket 控制媒体源（只适用于 OBS，暂不做）

OBS 28 起内置 obs-websocket（【工具 → WebSocket 服务器设置】，默认端口 4455，可以设密码）。bot 连上去以后，可以修改某个媒体源的文件并让它从头播放（obs-websocket 5.x 的 `SetInputSettings` 和 `TriggerMediaInputAction`）。媒体源用 ffmpeg 解码，什么编码都能播。

代价：只适用于 OBS；主播要打开 WebSocket 服务器、把密码填给 bot、建一个约定名字的媒体源；bot 要再写一套输出，还要保存 WebSocket 密码（属于敏感信息）。

结论：先只做浏览器来源。只有实测发现 OBS 的浏览器解不了 H.264 时，再考虑这条路。

## 十、测试页（`scripts/probe-livehime/`）

和正式实现用同样的技术（`HttpListener`、SSE、`<video>`、WebGL），用来在写正式代码之前，先在直播姬里把不确定的地方测清楚。

| 文件 | 作用 |
|---|---|
| `make-clips.sh` | 用 ffmpeg 生成 7 个测试视频到 `clips/`，不进 git；每个视频的提示音频率不同，听声音就知道在播哪个 |
| `serve.cs` | `dotnet run serve.cs` 启动，端口 17890；打开 `/play` 或 `/play?clip=文件名` 就推送播放；页面的检测结果打印到终端 |
| `index.html` | 透明背景，左上角是诊断面板；文件名带 `.green.`、`.black.`、`.split.` 的视频用 WebGL 抠图 |

测试视频：`1-h264.mp4`（测试图）、`2-alpha.webm`（透明 VP9）、`3-ball.green.mp4`、`4-ball.split.mp4`、`5-glow.black.mp4`、`6-portrait.mp4`（竖屏）、`7-small.mp4`（640×360）。

这次的测法：开发机是 Mac，直播姬在另一台 Windows 上，所以测试服务监听局域网，直播姬填 `http://<Mac的IP>:17890/`。要测的都是直播姬浏览器这一侧的能力，和服务跑在哪台电脑上无关。用这种方式测不到 Windows 本机访问 `localhost` 的行为，留给 #15。

页面报告里区分来源：直播姬的浏览器标识带 `pc_app/livehime`。普通 Chrome 会拦截有声自动播放（报告里是 `sound:false`），这和直播姬无关。

## 新术语（已写进 GLOSSARY.md）

- **欢迎动画**：指定观众进场时，在直播画面上播放的这位观众专属视频。
- **动画页**：bot 在本机提供的网页，主播在直播姬或 OBS 里把它加成浏览器素材／来源，欢迎动画在这个页面里播放。
- 注意：直播姬也把画面里的元素叫"素材"，和 GLOSSARY 里的"素材 (Asset)"撞名。界面文案统一写"直播姬的浏览器素材""OBS 的浏览器来源"。
