# 盲盒播报只带 reply_mid 的现场验收

2026-10-11，在直播间 `1775714259` 验证 [#65](https://github.com/cyaoc/aether/issues/65)，
对应 [#62](https://github.com/cyaoc/aether/issues/62) 的盲盒播报显示要求。

**本次样本通过：不带 `replay_dmid`，仅用 `reply_mid` 指定送礼观众，服务端补全了回复信息；
用户确认官方网页端和 App 的聊天列表都显示正确的 @昵称。** 保留现有播报写法，
没有证据要求增加 `reply_type`、在正文里带昵称或借用观众最近一条弹幕的 id。

客户端显示依据是用户现场确认，Agent 没有独立看过截图。两端截图尚未贴到 #65，
因此功能验证已有结论，截图归档验收项仍待完成；#65 保持开启。

## 版本、操作和采集方式

- 分支 `issues-65`；运行的产品源码为 `567c3393ffd6969ba151b15b2ab42e1e11fe54e1`，
  已包含实现 #63 的 [PR #66](https://github.com/cyaoc/aether/pull/66) 及 #64 的发送失败处理。
- 用户事先确认总预算上限 60 元，实际只送心动盲盒 1 个，投入 150 电池（按项目换算为 15 元），
  开出棉花糖 1 个，价值 90 电池，亏 60 电池。没有为扩大样本追加送礼。
- 使用本地临时采集入口调用原有 `AetherClient.WatchAsync`，完整经过盲盒记录、3 秒静默窗口、
  发送队列和 `BilibiliApi.ReplyAsync`，没有用独立脚本替代 bot 发送播报。
- 入口向现有公开构造函数注入 Trace logger 和 HTTP handler：logger 记录收到的直播间消息；
  handler 仅额外记录 `/msg/send` 的表单和返回，不改变表单或响应。请求记录排除 `csrf`、
  `csrf_token`，不记录 Cookie 或其他请求头；服务端响应和直播间原始消息只留本地。
- `blind_box.enabled`、`blind_box.announce` 使用默认 `true`，发送间隔使用默认 5 秒。
  Trace 由临时 logger 提供，未把持久日志级别改为 Trace。
- 初次 WebSocket 连接被当前代理以 403 拒绝。仅对本次采集进程设置弹幕域名的 `no_proxy`，
  随后认证成功并正常接收消息；未更改系统代理。失败连接未收到礼物，也未发出弹幕。

## 同一次送礼的证据链

时间均为 UTC+08:00，表格保留到毫秒；原始时间精度保留在本地记录中。

| 时间 | 事件 | 核对结果 |
| --- | --- | --- |
| 16:02:30.835 | 收到 `SEND_GIFT_V2` | 1 个心动盲盒，投入 15000 金瓜子，开出价值 9000 金瓜子 |
| 16:02:33.836 | 发出 `/msg/send` | 距礼物接收日志约 3.001 秒，正文 `本次投入150电池 亏60电池` |
| 16:02:35.027 | 接口返回 | HTTP 200，`code=0`，`message=""` |
| 16:02:36.266 | 收到 `DANMU_MSG` 回显 | 正文相同，`extra.id_str` 与接口响应中的 id 一致 |

整个成功连接只捕获到 1 条礼物消息、1 次播报请求、1 次接口返回和 1 条对应播报回显。
本地独立解码礼物 protobuf，核对其 uid 与请求、响应、回显中的回复对象一致。
下文用“观众 A”代替真实 uid 和昵称，不提交原始个人信息。

| 字段 | 请求表单 | 接口响应 `data.mode_info.extra` | 回显 `info[0][15].extra` |
| --- | --- | --- | --- |
| `reply_mid` | 观众 A 的 uid | 同一 uid | 同一 uid |
| `reply_uname` | 空字符串 | 观众 A 的完整昵称 | 同一完整昵称 |
| `reply_attr` | `0` | 本次不据此解释含义 | 本次不据此解释含义 |
| `replay_dmid` | 未发送 | — | — |
| `reply_type` | 未发送 | — | — |
| `show_reply` | — | `true` | `true` |
| `reply_type_enum` | — | `1` | `1` |

用户现场反馈：网页端和 App 均显示 `@观众A 本次投入150电池 亏60电池`，@ 后面的昵称正确。
这里的“观众A”是报告脱敏替换，不是实际显示文字。没有验证画面上滚动弹幕的显示。

## 验证与收尾

- 现场操作前，`dotnet build --no-restore --disable-build-servers` 通过，0 警告、0 错误；
  `dotnet test --no-build` 共 528 项通过，0 失败、0 跳过（macOS arm64）。
  测试最初被沙箱禁止创建通信管道，移至沙箱外后完整通过；这不是产品测试失败。
- 临时 HTTP 采集入口自检通过：请求凭据字段不落盘，中文正文和 uid 保留，响应正文可被 Core 继续读取。
- 本地断言核对消息数量、盲盒金额、请求字段缺失、业务成功返回、礼物与两处回复信息的匹配、
  响应与回显的消息 id 匹配。它们验证实际记录，不替代用户对官方客户端显示的确认。
- 收到用户反馈并提取证据后已停止采集，直播间连接结束，待发弹幕丢弃数量为 0。
  `Settings.Load` 自动补入的默认设置分组已撤回；设置文件恢复为采集前的完整字节。
  核对源码和设置哈希一致，产品源码无修改。正常记录下来的本次盲盒保留在本地数据库。
- 本次仅验证一个直播间、一次心动盲盒播报；不证明所有客户端版本、神秘人场景或协议未来行为。
  不实现退路，也不把 #49 中其他发送限制问题算作本次已验证。
