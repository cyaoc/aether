# 欢迎动画由 bot 内置的动画页播放，经推流软件的浏览器素材叠加到直播画面

指定观众进场时要在直播画面上播放视频，而画面是推流软件（直播姬、OBS）合成的，bot 只能想办法让推流软件把视频叠上去。直播姬基于 OBS 32.0.4，但没有带 obs-websocket，也没有别的外部控制接口（2026-10-15 查安装目录确认）。所以 bot 在本机开一个只读的网页服务，即动画页，用 SSE 推送"播放某个视频"；主播在推流软件里把 `http://localhost:端口/` 加成浏览器素材。直播姬和 OBS 共用这一套。

考虑过但没有采用的做法：

- **直播姬的多媒体素材**：能播本地 MP4，但什么时候播只有直播姬自己决定，bot 触发不了。
- **obs-websocket 控制 OBS 的媒体源**：只适用于 OBS，直播姬没有这个接口；主播还要把 WebSocket 密码交给 bot。等 OBS 的浏览器素材被证明播不了 H.264 时再考虑。
- **GUI 自己开窗口播放，推流软件用窗口捕捉**：Avalonia 没有视频控件，要引入 LibVLC（原生库几十到上百 MB）；窗口不能最小化；CLI 做不了。
- **让推流软件直接打开本地 HTML 文件**：好处是启动顺序无所谓。但发布包是带版本号的目录，每次升级路径都会变，主播每次升级都得改直播姬里的地址。
- **模拟快捷键切场景**：没有能单独显示或隐藏某个素材的快捷键，每位观众要一个场景，还会打断主播的操作。

动画页只监听本机，检查 Host 必须是 `localhost:端口`（默认 HTTP 端口 80 也接受浏览器省略 `:80` 的等价写法）。页面和视频接口只读；`POST /report` 接收播放结果，只推进内存中的播放队列，不修改设置或视频文件。服务端用 BCL 的 `HttpListener`，不用 Kestrel，因为需运行时版只要求装 .NET Runtime。

## Consequences

- 直播姬只在启动或刷新素材时加载一次页面，加载失败就一直空白，不会自己重试（实测）；页面加载成功以后，bot 重启时能自动重连。所以 GUI 只要开着、欢迎动画开关打开，就一直运行动画页，而不是只在直播间连接期间运行；CLI 的进程本来就只在观看直播间时运行。操作指南要写"先开 Aether 再开直播姬"，GUI 要显示有几个推流软件连着动画页，显示 0 个时主播就知道该去刷新素材。
- bot 和推流软件必须在同一台电脑上。远程服务器上的 CLI 用不了欢迎动画。
- 视频由推流软件内置的浏览器解码。直播姬（CEF 105）实测能播 H.264 + AAC 的 MP4 和带透明的 VP9 WebM，有声音的视频也能自动播放；OBS 官方构建能不能播 H.264 还没测。
- 主播填进推流软件的地址就是对外的接口：换端口、换路径都要主播去推流软件里改。
