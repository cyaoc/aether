# 直播画面上的内容由 bot 内置的网页服务提供，经推流软件的浏览器素材叠加

指定观众进场时要在直播画面上播放视频，而画面是推流软件（直播姬、OBS）合成的，bot 只能想办法让推流软件把视频叠上去。直播姬基于 OBS 32.0.4，但没有带 obs-websocket，也没有别的外部控制接口（2026-10-15 查安装目录确认）。所以 bot 在本机开一个网页服务，用 SSE 推送要显示的内容；主播在推流软件里把其中的页面加成浏览器素材，例如视频页 `http://localhost:端口/video`。直播姬和 OBS 共用这一套。

2026-10-16 修订：最初只有欢迎动画用，叫"动画页"，挂在 `/`、跟着欢迎动画开关启停。后来抽奖也要在直播画面上显示，于是改成一个网页服务提供多个页面：视频页 `/video` 只管收到推送就播一段视频（欢迎动画是第一个用它的功能），抽奖页 `/lottery` 显示抽奖；`/` 不再提供页面。每个页面在推流软件里各加一个浏览器素材，位置和大小分别摆。端口在设置里是 `web_service.port`。

考虑过但没有采用的做法：

- **直播姬的多媒体素材**：能播本地 MP4，但什么时候播只有直播姬自己决定，bot 触发不了。
- **obs-websocket 控制 OBS 的媒体源**：只适用于 OBS，直播姬没有这个接口；主播还要把 WebSocket 密码交给 bot。等 OBS 的浏览器素材被证明播不了 H.264 时再考虑。
- **GUI 自己开窗口播放，推流软件用窗口捕捉**：Avalonia 没有视频控件，要引入 LibVLC（原生库几十到上百 MB）；窗口不能最小化；CLI 做不了。
- **让推流软件直接打开本地 HTML 文件**：好处是启动顺序无所谓。但发布包是带版本号的目录，每次升级路径都会变，主播每次升级都得改直播姬里的地址。
- **模拟快捷键切场景**：没有能单独显示或隐藏某个素材的快捷键，每位观众要一个场景，还会打断主播的操作。
- **所有内容挤在一个页面里**：欢迎动画和抽奖的位置、大小要分别摆，一个浏览器素材摆不出两种布局。

网页服务只监听本机，检查 Host 必须是 `localhost:端口`（默认 HTTP 端口 80 也接受浏览器省略 `:80` 的等价写法）。页面和视频接口只读；页面回报结果的接口（例如视频页的 `POST /video/report`）只推进内存中的状态，不修改设置或文件。服务端用 BCL 的 `HttpListener`，不用 Kestrel，因为需运行时版只要求装 .NET Runtime。

## Consequences

- 直播姬只在启动或刷新素材时加载一次页面，加载失败就一直空白，不会自己重试（实测）；页面加载成功以后，bot 重启时能自动重连。所以 GUI 只要开着就一直运行网页服务，不跟任何功能的开关走，也不只在直播间连接期间运行；功能开关只决定推不推内容，切换时不重启服务，只有改端口才重启。CLI 在观看直播间期间、并且欢迎动画开着时才运行它。操作指南要写"先开 Aether 再开直播姬"，GUI 要按页面显示有几个推流软件连着，显示 0 个时主播就知道该去刷新素材。
- bot 和推流软件必须在同一台电脑上。远程服务器上的 CLI 用不了直播画面上的功能。
- 视频由推流软件内置的浏览器解码。直播姬（CEF 105）实测能播 H.264 + AAC 的 MP4 和带透明的 VP9 WebM，有声音的视频也能自动播放；OBS 官方构建能不能播 H.264 还没测。
- 主播填进推流软件的地址就是对外的接口：换端口、换路径都要主播去推流软件里改。
