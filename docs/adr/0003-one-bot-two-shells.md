# CLI 和 GUI 是同一个 bot 的两个外壳，bot 的行为全在 Core

CLI 给专业用户在服务器上挂机，GUI 给一般桌面用户。曾考虑让 GUI 退化成启动 CLI 的启动器或设置器，但那样要设计进程间协议来传二维码、状态和弹幕，显示逻辑照样要写，代码只多不少；关掉窗口后 bot 继续跑、在桌面远程管理服务器上的 bot，这两种需求都不存在。所以 CLI 和 GUI 各自完整地运行 bot，共用 Core 和同一个 `data/`。

划分界线：凡是改变 bot 做什么、记什么的（规则、统计、读取设置、日志写到哪里），都在 Core；外壳只负责显示和收集输入。检验方法：同样的设置，换一个外壳跑，bot 的行为不能不同。显示不要求对等，每个功能的 spec 写明各外壳显示什么；CLI 是完整入口，每个功能都要能通过命令、stdout 或日志用到。

一个进程只有一个直播间连接。同一个 `data/` 里可以同时跑多个进程连不同的直播间，共用登录凭据、设置和数据库；同一个直播间（按真实房间号）同时只允许一个直播间连接，第二个直接报错。这条用 `data/` 里每个直播间一个、由操作系统持有的锁文件实现，进程崩溃时自动释放；只在直播间连接期间持有，`login`、`logout` 不受限制。

## Consequences

- CLI 要正式支持 Linux（服务器），GUI 只支持 macOS 和 Windows。
- 一个 `data/` 只有一个账号。不同直播间要用不同账号，只能各用一份程序目录。
- 多个进程用同一个账号在不同直播间发弹幕时，如果 B站 的频率限制按账号算，进程之间需要协调发送节奏，直播间锁管不到这一点。做发送队列时再查清楚、再决定。
