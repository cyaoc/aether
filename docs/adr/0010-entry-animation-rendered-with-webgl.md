# 进场动画在视频页里用 WebGL 实时渲染

进场动画要把每位观众的昵称、粉丝团等级和大航海身份放进画面，又要有辉光、冲击波扭曲、放射模糊、色散这些游戏级特效。第一版用 CSS 动画做，用户评价廉价、没有冲击力，而这些特效 CSS 做不了。所以进场动画改用 WebGL 实时渲染，用 PixiJS 加 pixi-filters（都是 MIT），连同素材、字体、音效一起打包进软件，不走网络。它在视频页里播放，和欢迎动画共用播放队列，主播不用再加一个浏览器素材，两种动画也不会同时出现。

## Considered Options

- **CSS 动画**：抽奖页一直是这么做的，但做不出辉光和扭曲，第一版画板已经证明不够。
- **预渲染带透明的视频**：特效质量最好，但昵称要实时写进画面，还得在视频上再叠一层；四种身份乘四档就是 16 段视频，再加隐藏款，体积和制作量都大。
- **Spine / Live2D 骨骼动画**：动作最顺，但要有人拆图层、绑骨骼，做不了。角色动作改用生图出的关键姿势，按动画的一拍二、一拍三切换。
- **单独的进场动画页**：主播要多加一个浏览器素材；它和欢迎动画都按整屏 1920×1080 构图，分开摆没有好处，还得协调两个页面不要同时播。

## Consequences

- 视频页从"收到推送就播一段视频"变成"收到推送就播一段视频或一段进场动画"，网页服务的地址不变（ADR 0006）。
- 推流软件的浏览器必须支持 WebGL。直播姬实测支持（`docs/research/2026-10-15-welcome-animation.md`），OBS 没测；不支持时，像视频播放失败一样回报原因。
- 页面加载时预载、解码所有素材，进场时不再等图片。
- PixiJS 和 pixi-filters 的版本固定在发布包里，升级要重新对照设计包的截图。
