# 一个 `data/` 同时只跑一个进程，要多开就复制程序目录

[ADR 0003](0003-one-bot-two-shells.md) 原来允许同一个 `data/` 里同时跑多个进程连不同的直播间，共用登录凭据、设置和数据库。可发布包里 CLI 和 GUI 是两个包，各自解压、各自一份 `data/`，实际没有人这样用；为它留下的东西却不少：每个直播间一个锁文件，扫码登录时接受别的进程刚存下的凭据，连接期间在别处退出登录的分支，开奖计时器里“直播间可能被别的进程接手”，离开时最多等 1 秒锁库，还有 SQLite 被别的进程锁住时的忙等。按 [ADR 0017](0017-core-state-in-regions.md)，一步里同步读写 SQLite，别的进程锁库会让整个区域停住，最多 30 秒。所以现在 GUI 和 CLI 的 `watch`、`login`、`logout` 一开始、写日志和读设置之前，就锁住 `data/aether.lock`：独占打开、关闭即删，进程崩溃时由系统释放，和原来的直播间锁同一种写法。拿不到时一律最多等 5 秒，还拿不到就是已经有一个在跑：GUI 弹一个只有“知道了”按钮的提示“Aether 已经在运行”，点了退出；CLI 打印同一句话，退出码 1。

## Considered Options

- 保留多进程，只处理 SQLite 忙等：要避开别的进程锁库时整个区域停住，只能把数据库挪到别的线程，ADR 0017 没有走那条路。没有选。
- 第二次打开时把已经开着的窗口叫到前面：要做进程间通信，没有这个需求。没有选。

## Consequences

- 要同时连几个直播间，复制整个程序目录。每份 `data/` 各记各的，收礼记录、盲盒统计、抽奖和礼物榜都不合并；带着 `data/` 复制就沿用原来的登录和设置。两个 GUI 要把网页服务的端口改开。两份连同一个直播间没有东西拦（原来的直播间锁也放在各自的 `data/` 里，本来就拦不住），盲盒查询会回两遍，礼物会各记一遍。
- 同一个程序目录里，CLI 挂着 `watch` 时不能再跑 `aether logout`。
- 数据库只有本进程在碰，不会再被别的进程锁住而忙等。上面那些多进程的分支删掉，直播间锁文件也删掉。
- 等 5 秒是给自动更新重启的：新版本可能在旧进程退干净之前就起来了。不区分是不是更新重启，免得加启动参数；代价是手快重复双击时，第二个要过 5 秒才提示。
- 开发时在仓库里同时跑 Debug 版的 GUI 和 CLI 会互相挡住。测试不经过程序入口，不受影响。
