# 礼物榜像抽奖一样按期运行，只在 GUI 里

礼物榜不是设置文件里的一个开关，而是像抽奖一样由主播在 GUI 里开始和结束：点“开始新一期”开始统计，点“结束这一期”停下，结束了还能“继续这一期”。主播点断开、关掉 Aether 或退出登录时，统计中的一期也跟着结束；为了让设置生效的重新连接、断线后的自动重连不算。只有统计中的一期记录礼物、直播画面上才显示榜；还没开始和结束以后，礼物榜页是透明的。门槛、比法、看板娘、音量跟着期存在数据库里，改了立即生效，开始新一期时沿用上一期的。CLI 不碰礼物榜。不按开播自动换期。

## Considered Options

- 设置文件里的开关，每场开播自动换一期（#296 原来的方案）：要靠 `room_init` 的开播时间分场，短暂断流后它变不变没有验证，变了就会在直播画面上把一场拆成两张榜；开关开着就一直记录。没有选。
- 设置文件里的开关，加手动“开始新一期”：开关和开始新一期都在管“统计不统计”，开着就一直记录，CLI 还要另外一套。没有选。
- 结束以后画面停在最后的结果：主播要的是结束以后榜从画面上收起，结果留在 GUI 里看。没有选。
- 断开、关掉 Aether 时这一期照常统计（最初的做法）：断开期间本来收不到礼物，礼物榜页也已经透明，结束不结束只差在连回来以后；照常统计的话，下一场直播一连上，画面上马上出现上一场直播的榜，要先结束再开始新一期。没有选。
- 直播间连接一结束就结束这一期：设置页的“重新连接”也是结束旧的直播间连接、再开一个新的，改个设置就把榜收起来不对；断线自动重连还算同一个直播间连接，本来就不结束。没有选。
- 统计中也能“恢复上一期”，把两期合并：按状态给按钮（统计中只能结束、结束了才能开始新一期或继续）以后，用不上合并。没有选。

## Consequences

- `gift_board` 设置分组和它的保存、校验、补写都去掉；还没发布，不用写升级步骤。
- 每场直播要主播自己点“开始新一期”；忘了点，画面上就没有榜。断开后连回同一个直播间，要点“继续这一期”才接着统计，点之前收到的礼物不算；做多场的榜，每场连上都要点一次“继续这一期”。程序崩溃时来不及结束，那一期留在统计中。
- 结束以后观众看不到最终排名，结果只留在 GUI 里。
- 选项每个直播间各一份，跟着最新的一期走；没连直播间时不能改。
- 只用 CLI 的主播没有礼物榜。
