# 0.x 期间不保证升级兼容，1.0 起再承诺

取代 [ADR 0005](0005-data-directory-upgrade-compat.md)。v0.1.0、v0.1.1 发布时承诺过：旧版本的 `data/` 拷进新版本目录照常可用。实际还没有用户，这条承诺却让 0.x 阶段每次改设置格式、数据库结构都要兼顾旧格式，例如欢迎语改成多条，就得同时读旧的单条写法。所以改为：整个 0.x 期间不保证新版本能用旧的 `data/`，格式直接改，不写迁移，也不再读旧键名；到 1.0 再承诺升级兼容。

## Consequences

- 设置键改名后，旧文件里的旧键只记警告，值回到默认值；改了类型的键读到旧写法会报错并指出所在行。
- 已有的数据库迁移保留。改表结构照旧在 `Database` 里加一个版本块，手写 SQL 和 `user_version` 在同一事务里提交，新库和旧库走同一条路径（如 v4 的 [#202](https://github.com/cyaoc/aether/issues/202)、v5 的 [#233](https://github.com/cyaoc/aether/issues/233)）；但版本块只做建表、加列这类直接的改动，不为旧数据另写转换，做不到的就让旧库打不开并报错。
- 回滚照旧：旧目录保持不动，直接运行旧程序。升级说明仍写"复制"而不是"移动" `data/`。
