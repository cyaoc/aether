# 配置只放两处：点“保存”才生效的放设置文件，其余放数据库

配置原来散在三处：设置文件 `aether.yml`、数据库 `aether.db`、GUI 设置 `data/gui.yml`，没写明新东西该放哪，每加一样都要重新想一遍。现在只留两处，按怎么生效来分：

- 设置页上点“保存”才生效的，放设置文件。
- 页面上直接改、立即生效的（礼物榜的选项、“只保留最近 1000 条”），和程序自己记下的（登录凭据、最近的房间号、抽奖和收礼记录），放数据库。

设置文件不按外壳拆：直播画面功能（[ADR 0003](0003-one-bot-two-shells.md)）的分组照样写在里面，注释写明只在 GUI 里生效。`data/gui.yml` 去掉：自动更新开关搬进设置文件的 `auto_update` 分组，最近的房间号和“只保留最近 1000 条”搬进数据库只有一行的 `gui_state` 表，上次抽奖的房间不再记。

奖品方案不再按直播间分开，只按抽奖方式分开。当初按直播间分没有记下理由；一般主播只有一个直播间，分开反而让没连直播间时得先知道是哪个房间、换个直播间方案就看不到，还得为此记“上次抽奖的房间”。

## Considered Options

- 保留 `gui.yml`，写明只放 GUI 自己用的：CLI 和 GUI 按类别重新划线以后，设置文件里本来就有只在 GUI 里生效的分组，“是不是只有 GUI 用”定不了放哪，怎么生效定得了。没有选。
- 设置文件按外壳拆成两份：同一个功能的设置要先看在哪个外壳里用，两份各自补写、升级、校验。没有选。
- 自动更新开关留在 `gui.yml` 或放进数据库：它在通用设置页上和其他项一样点“保存”才生效，按上面的规则该进设置文件。[ADR 0015](0015-gui-updates-itself-in-place.md) 当初不放进设置文件的两条理由：一条是 CLI 会看到用不上的分组，现在接受，注释写明只在 GUI 里生效；一条是按 [ADR 0011](0011-data-upgrade-from-0-2-3.md) 升级会写成关，现在旧的效果取自 `gui.yml`，大多数人是开。
- “只保留最近 1000 条”挪到设置页：它在主窗口弹幕列表旁边、一点就生效，挪走反而不顺手。按规则放数据库。

## Consequences

- 以后加东西先问“是不是点保存才生效”：是就进设置文件，不是就进数据库。不再加别的配置文件。
- `gui.yml` 只由 GUI 升级，CLI 不碰：GUI 启动时、检查更新之前，有 `gui.yml` 就读出来，自动更新开关写进设置文件（设置文件里已经有 `auto_update` 分组时照样覆盖），最近的房间号和“只保留最近 1000 条”写进 `gui_state`，上次抽奖的房间丢掉；两边都写成功才删掉 `gui.yml`。任何一边失败就留着、下次启动再试；先写设置文件，成功了才写数据库，设置文件一直写不进时，每次启动才不会拿 `gui.yml` 的旧值盖掉数据库里之后记下的。之后没有任何东西再写 `gui.yml`。
- 自动更新开关的值：`gui.yml` 还在时按它，关掉自动更新的人不会因为设置文件有错被更新；搬完以后设置文件有错、值不能用时，按默认值开。
- 数据库升到 v8：加 `gui_state`；`lottery_prize_set` 去掉 `room_id`，不同直播间有同名同方式的方案时，最近保存的保留原名，其余的名字后面加“（直播间 <房间号>）”，一条不丢。
- 没连直播间时，抽奖历史显示数据库里最近一场抽奖所在的直播间，一场都没有就是空的。上次连的直播间从没抽过奖时，显示的是最近抽过奖的那个直播间。
- 只用 CLI 的人设置文件里也有 `auto_update` 和直播画面功能的分组；CLI 照常读和校验，写错了照样报错。
