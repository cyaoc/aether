# 从第一个 Release 起，旧版本的 data/ 拷进新版本目录必须照常工作

发布包解压出来是带版本号的目录，升级就是把旧目录里的 `data/` 拷进新目录（数据目录见 ADR 0002）。从 v0.1.0 起承诺：这样升级后，登录凭据、设置和数据库照常可用，不用重新扫码或重配。曾考虑 0.x 期间不承诺、让用户升级时删掉 `data/`；但数据库已有 `user_version` 迁移，设置文件也会补写缺失的分组和项（ADR 0004），守住承诺的成本很低，而每次升级都重新扫码、重配欢迎条件对用户很糟。

## Consequences

- 改数据库结构要写迁移并升 `user_version`。
- 设置文件里不认识的键只记警告，所以删掉设置不会让旧文件报错；但改名的键要继续读旧名字，否则用户的值会悄悄变回默认值。
- 只保证升级，不保证降级：新版本迁移过的数据库，旧程序拒绝打开。回滚靠旧目录里原封不动的 `data/`，所以升级说明写"拷贝"而不是"移动" `data/`。
