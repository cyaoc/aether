# 桌宠

直播画面一角的 Q 版看板娘和她的精灵，按直播间里发生的事表演，配气泡和台词，给观众和主播提供情绪价值。
地图和已定的框架在 [#343](https://github.com/cyaoc/aether/issues/343)；角色素材在 `docs/design/mascot/`。本文是演出设计的完整版本，
2026-11-08 在对话里定下；2026-11-09 图、帧和本地画板全部做完，用户认可，之后开 PR、拆票（第 9 节）。
出图、做帧、改演出之前先读 [WORKFLOW.md](WORKFLOW.md)（制作守则：用户的评估标准、踩过的坑、交付前自查清单）。

## 1. 基本

| 项目 | 规格 |
|---|---|
| 形式 | 网页服务里的一个页面，主播加成浏览器素材，透明底；只在 GUI 版有 |
| 推荐尺寸 | 480 × 640：城堡演出时城堡约 340 px 高占上半部，她站在台阶下（`preview/castle-page.webp`）；画板就按这个尺寸做的 |
| 她 | 当前角色的 Q 版：脸、画风、彩铅质感照 `mascot/textures/chibi-sheet.webp`，身体照 `chibi-turnaround.webp`，约 2 头身；站在页面下方正中，平时约 250 px 高（1080p） |
| 精灵 | 当前角色的精灵（`mascot/textures/sprite-*.webp` 和本目录的精灵动作表），平时在她身前低处，位置见第 1.1 节 |
| 朝向 | 一律正面或略侧向镜头，放左下角、右下角都能用，不做镜像 |
| 气泡 | 代码画，见第 7 节 |
| 一位角色要准备的 | 第 8 节的全部动作表、精灵动作、城堡和大航海的道具，加第 7 节的台词，都放在角色文件夹里；代码只认姿势名和事件，不认是谁 |

### 1.1 精灵和她的位置

查过的做法：分镜里忌讳两个角色平行于画框并排（画面会平）；两个角色常用斜线错开、一前一后、靠部分遮挡做出纵深；陪伴型小角色贴着主角动，不在旁边并排站着。上一版精灵在她身侧、肩膀高度，和她左右排开，显得远、显得平行。

定的是**前景低处**：精灵在她身前（画在她前面），比她站的位置低，压住她身体外缘约四分之一个精灵宽，约为她头高的六成（比立绘里的一半略大，靠前显得近）。比较过的三种在 `preview/sprite-placement-options.webp`，定稿的示意在 `preview/sprite-placement.webp`。

| 状态 | 精灵在哪 |
|---|---|
| 平时、多数事件 | 她身前低处，大约在她腰到大腿的高度，在她身体外缘（画面左侧）；在原地做自己的动作（挥小旗、点头、惊讶……） |
| 新的第一名 | 举着王冠飞到她头顶正上方，往下戴到她头上，再飞回原位 |
| 沮丧 | 飞到她头上方摸摸她的头 |
| 犯困 | 落到她抱着的膝盖旁边一起睡 |
| 提督 | 当她的瞭望员：先飞到她望远镜看的方向（画面左边）、挥小旗打信号，再飞回原位陪她敬礼 |
| 城堡 | 飞到她身后变回原型城堡，见第 5 节 |

精灵压在她身上那一侧不能盖住她的手和她拿着的东西（礼物盒、盲盒、王冠、哑铃）：这些动作里精灵往外让开，只压她的裙摆或头发。摇盲盒时它在盒子右边、和盒子一样高的地方侧耳听，盒边的抖动弧线和盒缝透出的光都画在盒子上，光在她身后透出来、不把盒子照白（原来弧线画在她头旁、精灵压在盒子上，用户说抖动的弧线穿模到精灵身上）。立绘里"精灵的脸低于她的下巴"那条（`mascot/README.md`）只管立绘，桌宠按本节。

### 1.2 连贯动作

动作是一串一串生成的帧，不切贴图，交叉淡化也算切贴图。用户看第一版画板时指出"转圈一直正面朝人""安慰和其他动作都没过渡""人物有位移"；看第二版又指出"骑车、走路脚都不动""应该生成连贯的动作、而不是直接切换贴图"。

- **动作本身动**：持续的动作是循环帧（蹬车、迈步、挥手、鼓掌……），一次性的动作播一遍停在最后一帧（抬手敬礼、举起望远镜、屈膝礼、跳上船）。每组 4 帧，清单在第 8 节"动作帧"。
- **换动作有过渡帧**：演出里每一次换姿势都有 codex 画的中间两帧（`tools/inbetween.py`，清单在第 8 节），换的时候按顺序播，反过来走就倒着播。给 codex 的是一张 2 × 2 的格子：第 1 格（左上）是开始的姿势、第 4 格（右下）是结束的姿势，都按看板上的样子摆好（所有表同一个比例、站在同一条地面线上、按重心对齐），中间两格空着让它画，头身、脸和表情就从一头渐渐变到另一头（和 ToonCrafter 这类按两张关键帧补中间帧的做法一样）。四帧只按第 1 帧对上开始姿势的那一次摆放，全都一起挪，不再一帧帧缩放；第 4 帧要落在结束姿势上（身高差不到 4%、脚差不到 6 px、轮廓重合 80% 以上），中间两帧的脸（两只眼睛一起量）要在两头之间（差不到 4%），不合格就重画。codex 画中间帧时会回到它自己习惯的头身比，头比两头小 3–5%，脸缩一下再长回来；所以提示词里写明中间两帧的头和脸要和第 1、4 帧一样大，再量脸把关。中间帧用 codex 自己画的脸，不再贴原图的头或脸：以前保留开始姿势的头，表情到最后一帧才突然换（用户看总督开头：捧脸以后脸回弹）；脸宽统一时又按被手和头发干扰的两颊宽把这些帧的头放大了 5–10%，比两头都大，长大再缩回去。以前分开给两张参考图、写着“一样大、一样的位置”，codex 就把四帧都画成第一张那么高，结束那张最多差 16%。道具也有来路：礼物盒从上面掉进她手里，运动的衣服和道具由精灵转圈换装带出来，自行车是扶着跨上去的。换衣服又换姿势的，第 2 帧还是原来的衣服、已经开始动，第 3 帧已经是新衣服，换在精灵的闪光最亮之后 90 毫秒；两边都是站姿、只换衣服的（站着变舰长、提督的敬礼和举望远镜都从站姿开始，公主装变回校服），或者正转着圈换上公主装的，在闪光最亮那一下直接换；两边是同一张图的（总督跳船从指向前方开始、落地回到指向前方）也直接换（看板 `CUT`，只管写明的那个方向：舰长放下手变回校服有自己的中间帧，`CUT` 曾经两个方向都算，这组中间帧一直没播出来）。从惊讶、喊话回到站姿比进去慢，倒着播进去的那组，平静的脸到最后一帧才出来，所以这两处有自己回来的中间帧（`surprisedOut`、`announceOut`）。放不进开始那格的（滑雪的几组：雪板横出去、毛线帽太高），画在结束那格里、倒着存。事件随时会开始，也会打断低一档的（她正哼着歌、无聊坐着、骑车摔在地上），这些组合大多没有自己的中间帧，看板就按已有的中间帧和直接换连成的路找最短的一条（最多 5 步，先试站姿；正着播的优先于倒着播的，摔倒以后是贴创可贴站起来，而不是把摔倒倒放回去），一段段接着播；全部动作两两之间只有城堡里转圈、背面走路这几个（城堡是最高档，不会被打断）和不同运动摔倒中途之间没有路，那时直接换上新姿势。以前没有中间帧的换姿势走“旧姿势往下一蓄、新姿势长出来拉过头再落定”，整个人跟着挤扁拉长，脸宽 3–8% 再弹回来，已经删掉。
- **她不能平移**：每格按人的重心对齐，不按格子中心。动作表里的人在三等分格子里并不居中（左列偏右、右列偏左约 20 px），按格子中心对齐时，换姿势会左右跳 20–40 px。一组帧都用它出自那一格的对齐点，所以只有动的部位在动。重心算的是整张图，车、哑铃、雪板也算在里面：车在她右边，她就被往左摆，精灵一换衣服、车一消失，她就往右跳（用户看骑车换回校服时指出约 30 px，举哑铃结束也跳 17 px，滑雪抖完雪换回时 19 px）。所以每项运动的第一个和最后一个姿势按她的身体对齐平时站姿（看板 `BODY`，`tools/body-align.py` 量：去掉地上的东西，把这一格左右滑到和站姿重合最多的位置），同一处的姿势（`SAME_SPOT`）跟着一起挪，地上的东西还是不动；滑雪扎进雪堆那格也跟着挪，免得雪堆旁的杖跳一下。原来的位移就挪进了动作里面：砸到脚单脚跳时往旁边跳了一点，摔车后站起来走两步到车旁边把车扶起。换衣服的中间帧另外把关：第 2 帧要站在第 1 帧的位置、第 3 帧要站在第 4 帧的位置（各自同一套衣服，量得准），差 6 px 以上就重画（`inbetween.py --still`）；codex 曾把换好校服的第 3 帧画在它那一格的正中，偏了 70 px，总督、提督换回校服和换上滑雪服的中间帧也偏过 6–19 px，一起重画了。
- **掉在地上的东西不动**：她丢下、摔掉的东西（两只哑铃、雪板和雪杖、登山杖、倒下的自行车）从落地起到她再拿起来，一直在同一个地方、同一个样子。用户看滑雪摔跤、举哑铃时指出地上的东西也在动：原来每格、每帧都是 codex 各画各的，这一格哑铃在脚边、下一格挪开一截，循环里每帧也重画一遍。现在动作表的描述写明每样东西落在她哪一边、离多远、怎么躺（平放，不立着），后面几格照旧；在同一处接着做的姿势（看板 `SAME_SPOT`：砸脚后的揉脚、擦汗，雪堆里钻出来后的甩雪，摔倒后的拍土、贴创可贴）用前一个姿势的重心，地上的东西整块从前一格搬过来（`petlib.carry_props`：和她不相连、超过 400 px 的块算地上的东西，垫在她身后，她身上的像素一点不动）；循环帧和同一处的中间帧也每帧搬原格的，中间帧的描述写明“东西躺在原处、她不碰”，到她真拿起来的那一组（爬山拍完土拿杖、骑车扶车站起来）才动。
- **循环不抖**：codex 每帧都会把整个人重画得略有不同，循环播会“抖”。所以循环只取帧和帧之间真正在动的部位（挥的那只手、蹬车的腿），别处每帧都是原格的像素（`frame-patch.py`）。换姿势的中间两帧只播一次、各 90 毫秒，不抖，整张用 codex 画的。
- **大小在生成时定，不事后拉伸**：她在每个动作、每一帧里脸一样大、身体一样长（除非镜头变化：走进城堡越走越远）。办法是生成时就把尺寸定死，再量，达标留用，不达标重画。每张动作表的第 1 格是同一张定稿的平时站姿，原样按 360 px 高贴进画布、脚踩同一条地面线，codex 照它画其余五格（`tools/gen-sheet.py`），所以所有表是同一个比例，看板不用每张表各自的尺子。出来逐格量：两只眼睛一起当模板找出脸多大（一只眼的模板会被表情、手、头发带偏），站着的再量眼睛离脚多高；脸差 6%、身体差 5% 以上的格就重画，把站姿贴进那一格、让 codex 从它改成要的动作（从空格子画，戴帽子的头总要小 8%；从站姿改，头保持原来大小）。闭眼、转头、背对、捂脸的格量不到眼睛，看图核对；看图也要核对动作对不对（创可贴贴在哪），格子的描述写错了就先改描述再重画。循环帧、中间帧、道具也照这个办法（见下面几条和第 8 节）。以前是事后修：每张表按站姿身高缩放，再一层层按眼距、两颊宽放大头、抬高、贴站姿的头，结果抽奖、运动几张表身体比站姿大 3–10%，滑雪的脸被量小、放大两次后大了 15–20%，害羞循环的头比害羞那格大 5%（用户指出连送 5 份、点名时人放大，滑雪时脸放大）；这些缩放的脚本都已删掉。
- **循环也在生成时定尺寸**：原格原样贴在 2 × 2 格子的第 1 格，codex 画其余三格（`gen-frames.sh`），只取帧之间真正在动的部位；头顶头发没动（挥手、鼓掌、弯举、骑车）就整颗头都用原格的（`frame-patch.py --head`），贴在脸旁、伸到脸前的手照常取生成的帧（用户看挥手时指出每循环一次脸胖一下，是那一帧整颗头用了 codex 画得偏大的头）。头会动的循环（摇摆、单脚跳）用 codex 画的头，每帧量脸，差 6% 以上整组重画（`tools/gen-loop.py`），不再把原图的脸缩放贴回去。
- **睁眼用原格的眼睛、一直在呼吸**：待机眨眼循环的睁眼帧直接用原格（`frame-patch.py --ref-first`），否则一离开待机眼距就跳 1 px。呼吸（整个人上下 ±1.2%）所有姿势、过渡帧都一直在呼吸，原来只在待机时呼吸，一换动作就停，头会跳。
- **精灵转身**：精灵有正面、四分之三、侧面、背面四个视角（`textures/sprite-views.webp`，朝画面左边，往右时镜像）。绕她转圈时按前进方向依次换正面、四分之三、侧面、背面，转到她身后时画在她后面，近的半圈稍大一点。
- **精灵飞行**：去别处时用侧面或四分之三，尾巴摆动（飞行循环帧），身子往前进方向倾；到了才换成要做的动作，落下时压扁再弹一下。它飞得有上限（看板 `SPRITE_SPEED`，每毫秒 0.8 px，绕她转时两倍），远的地方（她肩旁到桅杆顶）是一路飞过去，不会一下就到（用户看提督时说它从桅杆瞬移回来）；转圈换装从它平时待的她左边开始转，不先横穿她到右边。被她抛起时（中礼物、大礼物、揭晓大奖）飞到头顶以后停在气泡上方蹦一会儿再落下（原来抛起只给 350 毫秒，刚飞到顶就往下落，用户说一上头顶就下来了；停住以后又被气泡挡住，所以停得比气泡高，两行的气泡也挡不到）。绕圈也从它现在的位置接进去：开始绕时按它自己所在的位置定圈上的角度（在她身前那半圈），先飞回圈上再从那里转下去；演出交给开心待机这类绕圈的时钟一换，角度也接着转，不跳。离圈还远时按平常的速度飞回去，到了圈上才用绕圈的两倍速度（用户说演出结束后精灵停一下、瞬移、再绕圈：原来角度直接按时钟算，要去的点在圈上任何地方，它一帧冲 27–29 px 过去，看着像瞬移）。顺序要合常理：总督先换装、精灵再飞上桅杆、她再上船（原来精灵先上船再回来换装，用户说意义不明）。举着王冠、发着光这两种飞的时候本身就是动作，不换视角。精灵的每个动作也是循环帧（挥旗、点头、摸头、打哈欠、睡觉呼吸……）。
- **不瞬移**：换场景靠动作连起来。总督时她跳上船、跳下船；城堡演出最后她从城门跑下台阶回来，城堡缩回精灵；换装都由精灵绕她转一圈带出闪光。

### 1.3 精灵和她的互动

精灵是她的伙伴，跟着她的事一起动，不在旁边各演各的（用户指出"小精灵和桌宠互动少了"）：

| 时候 | 精灵 |
|---|---|
| 进场 | 先抬头看她，再和她一起挥小旗 |
| 普通礼物 | 和她一起鞠躬 |
| 连着送 | 飞到她肩旁，学她捂脸害羞 |
| 大礼物 | 趴在礼物盒边偷看；她举起欢呼时被抛过头顶，在气泡上方开心地蹦一会儿（约 1 秒），再落下来绕她转圈 |
| 盲盒 | 凑到盒边和她一起听；开大时被光冲得往后弹，再在她旁边蹦；开亏时躲烟抱头，再飞去摸她的头 |
| 舰长、提督、总督 | 发着光绕她转一圈，带出换装闪光；舰长、提督时换水手领在她身旁敬礼，提督时还去她望远镜的方向瞭望打信号，总督时飞上后桅杆 |
| 抽奖 | 宣布时飞到她举起的拳头旁挥旗；等开奖时抬头看她、发抖；点名时顺着她手指方向冲出去挥旗；大奖被抛过头顶、在气泡上方蹦一会儿再落下来绕圈，二奖跟她的掌声蹦，三奖和她一起点头；抽奖结束时和她一起鞠躬，再挥小旗 |
| 日常 | 健身、登山、骑行、滑雪前后都转圈给她换装；举哑铃时挥旗打拍子；哼歌时跟着摇；爬山时在前面领路；骑车、滑雪时侧身并排飞 |
| 出事 | 先吓一跳再过去：砸到脚就飞到脚边揉，破音就抱头，摔倒就飞回来摸头，贴创可贴时在旁边点头，扎进雪堆就飞过去摸头 |
| 心情 | 平时隔一会儿抬头看她；无聊时懒洋洋地飘、打哈欠；沮丧时摸头；犯困时靠在她膝盖旁睡，她磕醒时一起吓醒 |

## 2. 档位和优先级

按 B 站的价值和难得程度分档（用户定）：总督 20 万电池，最贵、独一档，演出最华丽；城堡只值 22330（心动盲盒的大奖，心动盲盒一个 150 电池），但很难得（天运，或大量叠加后开出来），排第二；提督（约 1.6–2 万）和 1 万电池以上的礼物（最大 3 万，也很难得）一档；舰长和 1000–9999 的礼物差不多；再往下是小礼物。盲盒不只一种（2026-11 在卖的是幸运盲盒 50、狂欢盲盒 90、心动盲盒 150 电池，另有圣诞盲盒 250、大航海盲盒 500），城堡以外的大奖大多 1 万以下；盲盒按这一轮的投入定档位、按盈亏定结局（见下面“送礼按一轮演”），原来按开出礼物的价值算，一次送一批时说不清。

**送礼按一轮演（2026-11-10 用户定）**：一位观众停手 3 秒算这一轮送完，和送礼动画、盲盒播报是同一个“一轮”，演哪一段按这一轮的投入定。这里的一轮只算礼物和盲盒，开通、续费大航海照旧当场演。礼物不干等：第一份到了，就演这一轮到目前为止该演的那段；越送越多，就接上更大的那段（第 5 份接连着送，累计到 1000 电池接中礼物、到 1 万接大礼物，送了城堡接城堡），已经演过的那段不再演；中礼物没演完、这一轮又到了 1 万，就被大礼物打断（高档打断低档）。原来要等这一轮送完才决定，一份小花花也停 3 秒才道谢，用户问为啥停了 3 秒。一轮里既有礼物又有盲盒，各演各的：礼物当场演，盲盒等播报再演，盲盒的档位按盲盒这一部分的投入。一轮还没送完时她不干等：每来一份礼物，一个小礼物盒飞进她怀里，不管她正在做什么；有盲盒就从第一个盒子起一直摇。礼物的那段演完就回到平时，不再捧着礼物盒等这一轮结束（用户问普通礼物结尾为啥还拿着一个盒子：原来演完到停手 3 秒之间，她会捧起中礼物的大礼物盒）。盲盒的结果跟机器人的盲盒播报走（2026-11-10 用户定）：不按桌宠自己数的 3 秒，等这一轮的盲盒播报发出、报了赚、亏或不赚不亏，她就开盒，演的就是播报报的结果；播报还没发出时又送的盲盒并进这一轮，和播报算的一样。主播关了盲盒播报（或没开记录盲盒）时，停手 3 秒算这一轮送完。开盒后演出不再从摇盒演起（原来一轮里摇了、演出开头又摇一遍，用户说摇得过久；中间试过每个盒子只摇 0.7 秒再捧着不动，用户说还是一直摇好）；试演没有这一轮，才从摇盒演起。原来按每条消息、每件开出礼物判断：B 站一次送 10 个盲盒只发一条消息、按开出的礼物分成几项，一次送 100 个会触发好几段演出，排不下的丢掉；亏了还说“运气好好”“欧皇”。连着送原来是“30 秒内 5 份”，也和 Aether 别处的“一轮”不一致。例：连着送 100 个心动盲盒（150 电池一个），投入 15000、开出 13000：演盲盒·大（A 档），结局是亏了；如果其中开出城堡，就演城堡。

**不靠盲盒统计和礼物榜（2026-11-10 用户定）**：桌宠只用直播间推来的礼物、盲盒、大航海、进场消息，主播没开盲盒统计、没开礼物榜也能单独开，它不往数据库写东西，送礼记录记不记还是只看那两个功能。没开盲盒统计（或关了盲盒播报）时，盲盒的赚亏桌宠自己算：每条盲盒消息带着盒子价格和开出的礼物，开出价值减投入，正好相等才算不赚不亏；没有播报可等，停手 3 秒算这一轮送完。这个算法和盲盒播报共用 Core 里同一份，不另写，免得两边算得不一样。礼物榜没在统计（没开，或这一期已经结束）时没有榜，就不演新的第一名；桌宠不自己另记一份榜，免得和礼物榜重复、对不上。GUI 上新的第一名那一行写明“礼物榜在统计时才有”。

**一件事只演一段，按最具体的那一类算：**

| 收到的事 | 演哪一段 |
|---|---|
| 开通或续费大航海 | 舰长、提督、总督之一，不再按价值算 |

## 5. 城堡演出（S 档，约 11.5 秒）

精灵的原型是一座立在浮空云岛上的童话城堡（`textures/castle-closed.webp`、`castle-open.webp`，1024 × 1024 透明底）。Q 版也要大气恢弘：金字塔剪影，底下一圈带门楼的城墙、中间一层宫殿、最上面带挑台的主塔，十几座粉尖塔高低错落往正中收拢；最顶上三座塔就是精灵的王冠（中间最高、插红旗），正门上方一扇大玫瑰花窗，中间是精灵的红蝴蝶结和玫瑰盾徽；主塔两侧有空中廊桥；白石大台阶从下方正中通到红色大门，她沿着它走进去；云岛就是精灵的云身体，两侧有云瀑，背后一道大彩虹。我们自己设计，不照抄礼物美术（不画长桥、马车、路灯）。第一版只有三座塔，用户嫌寒酸（`preview/castle-first-try.webp`）；定稿以设定图 a（`preview/castle-sheet-a.webp`）为底，加上设定图 b 的大玫瑰花窗和空中廊桥。开门那张只重画城门、用 `tools/patch-box.py` 贴回关门那张，两张只在城门附近不同（`preview/castle-gate.webp`），切换时不跳；门里的光束、星星由代码画。

### 7.1 特效

第一版除了几个大奖，特效偏少（用户指出）。按设计技能（ui-ux-pro-max）和游戏手感、漫符的资料补了一套，全部由代码画。

**原则**：
- 强度跟着档位走，越大越隆重；震屏只给大事件的高潮和摔倒、砸脚这种冲击，平常的小事不震。
- 一次冲击是几样小东西在约 0.1 秒内一起出现：闪光、一圈粒子、漫符、轻微震屏。
- 粒子成团爆开、很快消失（6–12 颗，一颗颗错开 20–40 毫秒），不长时间连续喷。
- 出现用减速（弹出带一点回弹），消失用加速；一直循环的特效只留给持续的状态，而且要淡。
- 不挡她的脸和气泡：漫符放在她头顶左上（气泡在右上），光、集中线、速度线、地上的光圈画在她身后。

**出图工具**（`tools/`）：

- `codex.sh <codex exec 的参数>`：所有工具都经它调 codex，模型只在这里定：`gpt-6.1-sol`，推理强度用它的默认值（medium），不跟 `~/.codex/config.toml` 的默认模型走。每次调用约 15 万输入 token（大半是缓存），主要花在读生图技能说明和来回几轮上，推理只占很少；省额度靠少重画，不靠调低推理。
- `gen-sheet.py <表号> <目录> [--tries 3] [--redo 5,6]`：出一张动作表（见第 1.2 节）：第 1 格贴定稿站姿，codex 照它画其余五格，逐格量脸和身体，不达标的格把站姿贴进去让 codex 改成要的动作；目录里已有这张表就接着做，只重画不达标的格，`--redo` 再加上看图发现画错的格。提示词是 `<基础>.txt`（人物、版式、尺寸规则：`pet-base.txt`，公主装 `princess-pose-base.txt`，大航海 `fleet-pose-base.txt`，滑雪 `ski-pose-base.txt`，健身登山骑行 `outfit-pose-base.txt`）、`sheet-<表号>.txt`（六格）、`pet-negative.txt`；参考图是角色设计包的 Q 版九宫格和 Q 版全身、这套衣服的设定图、这张表原来的定稿（照它的动作，不照它的大小）。拼表前，看板 `SAME_SPOT` 里同一处接着做的格，地上的东西从前一格整块搬过来（见第 1.2 节）。出 `sheet-<表号>.png` 和带每格读数的 `sheet-<表号>-check.png`。
- `gen-prop.py <道具> <目录> [--tries 2]`：出一样道具（`props/<道具>.txt`）：她的站姿贴在画布上当尺子，codex 把道具画在她旁边，以城堡为画风参照；她被画大画小 4% 以上、或道具高度不在规定的范围（旗舰是她的 2.0–2.45 倍），就重画；`giftbox-open` 从关着的盒子改出来，只取上半截。目录里的 `<道具>-design.png` 会当设计照着画。

- `gen-castle.sh <目录> <名字> <城堡参考图> <表文件>`：城堡设定图（`castle-sheet.txt`）；`gen-castle-final.sh` 出定稿的透明图（`castle-final.txt`）。提示词是 `castle-base.txt`、`castle-negative.txt`；城堡参考图是礼物截图，不在仓库，只取通用的童话元素。
- `gen-princess.sh <目录> <名字> <表文件>`：公主装设定图（`princess-base.txt`、`princess-sheet.txt`、`princess-negative.txt`）；穿公主装的动作表用 `gen-sheet.py 7`。
- `gen-fleet.sh <目录> <名字> <表文件>`：大航海服装设定图（`fleet-base.txt`、`fleet-sheet.txt`、`fleet-negative.txt`）；穿大航海服装的动作表用 `gen-sheet.py 8`。
- `gen-outfit.sh <目录> <名字> <衣服> [<附加参考图> ...]`：运动服设定图，衣服是 `ski`、`cycle`、`hike`、`gym`，提示词是 `<衣服>-base.txt`、`<衣服>-sheet.txt` 和 `<衣服>-negative.txt`（没有就用共用的 `outfit-negative.txt`）；穿运动服的动作表用 `gen-sheet.py 9`–`12`。
- 运动服（用户要骑车、登山、健身也换上对应的衣服）：骑行服 `textures/cycle-sheet.webp`（选 b：粉色侧片和袖子更像骑行衫）、登山服 `hike-sheet.webp`（选 b：徽章更清楚）、健身服 `gym-sheet.webp`（选 a：b 的眉毛压得太浓，她不喜欢浓眉），两版对比在 `preview/cycle-sheets.webp`、`hike-sheets.webp`、`gym-sheets.webp`；健身时两只哑铃一手一个。
- 动作表 7 的"回头挥手"第一次画成一个肩膀伸出两只胳膊，当时只重画了这一格（`preview/pose-7-wave-fix.webp`），负向词加了这条。
- `patch-box.py <原图> <改过的> <输出> <x0,y0,x1,y1> [羽化] [alpha]`：只把一个方框贴回原图，边缘柔和，框外一个像素不动；加 `alpha` 时连透明度一起取。
- `key-box.py <原图> <绿底上改过的> <输出> <x0,y0,x1,y1>`：改动超出轮廓时用。透明底上直接改，codex 会在周围留一圈半透明光晕；先把原图放到纯绿底上改，再按绿色抠回那个方框。
- `gen-frames.sh <目录> <名字> <原图> [<描述>]`：一组循环帧（一个姿势原地在动）。原图写成 `textures/pose-1-common.webp:2`（3 × 2 表的第 2 格）、`textures/sprite-views.webp:3/4x1` 或单张；原图原样贴在绿底 2 × 2 格子的第 1 格交给 codex（`frame-patch.py --grid`），它照 `frames/<描述>.txt` 画其余三帧，大小跟着第 1 帧；不要画的东西在 `frames-negative.txt`（和 `inbetween.py` 共用）。绿底比透明底干净，codex 在透明底上会留一圈半透明光晕。动作描述要从原图本来的姿势写起：爬山原图是走路迈步，第一次写成原地抬腿，出来的帧把后脚往外踢、鞋底朝前，用户说脚部动作很奇怪；改成走路循环（迈步、两腿交错、换另一只脚迈步、交错），写明脚贴着地、不踢、鞋底不朝前，重出。
- `gen-loop.py <姿势> <目录> [--tries 3]`：看板 `STRIP` 里一个姿势的帧条：`gen-frames.sh` 加 `frame-patch.py`（每个姿势用哪些选项写在 `OPTIONS`），每帧量脸，比原格大或小 6% 以上就整组重画；走路的循环（爬山）腿的轮廓在第 2 帧要和第 1 帧有 25%、第 3 帧有 40% 以上不同，不然也重画（第一次 codex 每帧的腿几乎一样，用户说爬山腿没动；第二次第 3 帧还是和第 1 帧同一只脚在前，用户说不明显）；四分之三视角下 codex 分不清“换另一只脚”，描述改成按近处、远处的腿写：第 1 帧近处的腿在前，第 3 帧远处的腿在前、近处的在后。欢呼整块取上半身（`OPTIONS` 的 `upper`），不然原格的手臂会留在生成的手臂旁边，一帧里出现四只手（用户说像千手观音）；只在 V 里小幅摆又显得不动、手掌长短还跳，所以重新设计成一个欢呼的“耶”：双手举成 V → 两手落到耳边 → 握拳收到肩头 → 又落到耳边 → 举得比 V 还高，看板按 `loop` 这个顺序播，手每帧一样大。擦汗的描述写明毛巾一直在同一只手、同一边额头小幅擦（原来写的是擦到另一边，毛巾左右跳）。出 `<帧条>-strip.png` 和 `-check.png`。
- `frame-patch.py [--from-first | --ref-first] [--box x0,y0,x1,y1] [--take x0,y0,x1,y1] [--head] <原图> <四帧.png> <输出.png> [预览.png]`：把循环的四帧做成不抖的帧条。抠绿、对齐用 `petlib`；只取帧之间真正在动的部位（自动找，或限在 `--box` 里），别处用原图的像素。codex 把不动的部分画得太不一样、接缝对不上时（第一次蹬车时车架出现两根管子），加 `--from-first` 用它的第 1 帧当底。`--head` 头不动就整颗用原图的头（见第 1.2 节），不再缩放贴脸。`--ref-first` 让第 1 帧就是原图，给替代原图播放的循环用（待机眨眼）。`--take x0,y0,x1,y1` 让这一块每帧（连第 1 帧）都整块取生成的帧，给一直在动的部位用（走路的腿）。`--grid <原图> <输出>` 出交给 codex 的格子。
- `inbetween.py <名字> <开始的姿势> <结束的姿势> <目录> [--tries 2] [--end-props]`：换姿势的中间帧（见第 1.2 节；两头在同一处时中间两帧的地上东西搬开始那格的，`--end-props` 搬结束那格的，给第 2 帧就已落地的东西用：从雪堆钻出来时雪板掉下来）：两个姿势按看板的样子放进一张 2 × 2 格子的第 1、4 格交给 codex，它照 `frames/<名字>.txt` 画中间两格；四帧按第 1 帧对上开始姿势一起摆好，第 4 帧落不上结束姿势、或中间两帧的脸（两只眼睛一起量）不在两头之间就重画；出 `<名字>-strip.png`（结束姿势放不进开始那格时存进结束那格、倒着放）和 `<名字>-check.png`（开始、第 2、3 帧、结束并排），最后一行是看板 `TRANS` 里要写的那一条。`--still` 给换衣服的那组用：第 2、3 帧的身体和同衣服那一头差 6 px 以上也重画。
- `body-align.py [<姿势> ...]`：量她的身体离平时站姿的位置差多少（见第 1.2 节）：去掉地上的东西，把这一格按看板的样子左右滑，取和站姿重合最多的位置；每个姿势印出现在的差（看板 `BODY` 对了就是 0）和不算 `BODY` 的差（`BODY` 要填的数，正负相反）。不带参数量每项运动的第一个和最后一个姿势。
- `petlib.py`：各工具共用的部分（看板的 `POSE`、`STRIP`、`TRANS`，各表按看板缩放、地面线、重心，找连通块、皮肤、眼睛，抠绿、对齐 codex 的帧、重采样，`SAME_SPOT` 和 `carry_props` 把地上的东西搬到下一格、下一帧，`BODY` 按身体挪位置），改一处所有工具一起改。
- `add-frames.py <名字>-strip.png ...`：帧条存成 `textures/frames/<名字>.webp`，登记进 `blobs.json` 和画板的 `FRAMES`；`--texture <看板名> <图.png> <textures/文件.webp>` 同样登记一张动作表或道具到看板的 `BLOB`。之后重启 `server.mjs`。
- 切图按每格里的内容切，不按死格子切：4 号"骑车摔倒"的后轮伸进隔壁格约 8 px。
- 平时不贴创可贴；出图后有创可贴的，用角色设计包的 `remove-bandage.sh`、`bandage-patch.py` 擦掉，只留 4 号"贴创可贴"那一格。

## 8.1 画板和本地预览

演出在本地直接看，做法同进场动画设计包：

```
node docs/design/desktop-pet/tools/server.mjs 8820
open "http://localhost:8820/render.html?board=DP-DesktopPet.dc.html"
```

画板 `boards/DP-DesktopPet.dc.html` 画一个 1920 × 1080 的直播画面，虚线框是浏览器素材（480 × 640，页面本身透明）。
图都从设计包的动作表、精灵表和道具里按格裁，不另外切图；`tools/blobs.json` 把 `/_blob/<id>` 对到文件。

参数（URL 里的 `props`，JSON）：

| 参数 | 取值 | 作用 |
|---|---|---|
| `scene` | `手动`（默认）、`演示`、`平时`、`心情`、各个事件、`大礼物+新第一`、`报名抽奖`、`奖池抽奖`、`没人报名` | `手动` 时用页面下方的按钮触发事件；`演示` 是 30 秒循环（进场、普通礼物、大礼物接新的第一名）；其他是固定循环，配 `freeze` 截图 |
| `env` | `右下角`、`左下角`、`小页面` | 页面放在直播画面哪个角；`小页面` 把页面缩到 0.75 倍 |
| `room` | `明亮画面`、`深色房间`、`透明` | 直播画面 |
| `name` | `普通昵称`、`长昵称`、`中英混排` | 气泡里的昵称；超过 8 个字截成 7 个字加"…" |
| `speed` | `1 倍`、`0.5 倍`、`0.25 倍` | 慢放 |
| `caption`、`controls` | `显示`、`隐藏` | 左上角的说明（正在演什么、哪档、排队、心情、抽奖状态、最近的打断和丢弃）；页面下方的按钮条 |

`freeze=<毫秒>` 把时钟钉在那一刻；`tools/cdp-shot.mjs "<地址>" <输出.png>` 用无头 Chrome 截图。
验收用另外两个（都要先开着 `server.mjs`，`tools/cdp-eval.mjs` 是它们共用的无头 Chrome）：
`node tools/check-board.mjs` 把每个事件（盲盒的每种结局都算）、每个日常（含出事版）从站姿进、回站姿出走一遍，列出每处换姿势，看板有没有中间帧、写明的直接换或连成的路，没有路的逐条印出来；事件名从看板文件读、时长从看板本身取，看板改了它跟着改。`node tools/play.mjs <事件[:结局] 或 日常:<项目>[:出事]> <毫秒,…> <输出.png> [--line] [--room 深色房间]` 在看板上触发它、按真实时间播，在这些时刻截页面并排存下，`--line` 在她原位画一条红线；看动作和位置要用它，跳时间的截图会拿到播放时不会同时出现的姿势（看板换姿势按真实时间走）。`node tools/motion-scan.mjs` 把每段演出（盲盒每种结局、每个日常和出事版）从平静、开心各演一遍，逐帧记精灵的位置，一帧挪动超过 20 px 的逐条印出来：精灵瞬移、冲过去这类问题截图看不出来（绕圈的角度原来按时钟算，演出交给开心待机时它一帧冲 29 px）。
`手动` 时按钮条有：全部事件（送礼都按一轮：礼物一份份进来，第一份就演、越送越大就升级；含连送 5 份、大礼物接新的第一名；弹幕不演，只算有事，看犯困用）、盲盒的一轮（小、中、大各自赚了、不赚不亏、亏了，100 个心动盲盒投入 15000 开出 12990，出大奖，开出城堡；盲盒一直摇到机器人播报发出，播报的原文显示在左上角说明里）、两种抽奖的每一步、五个日常小动作和各自出事的版本、快进 10 / 30 分钟（看无聊、沮丧、犯困）。
优先级、排队、连着送、冷场惊醒、抽奖被打断后回到期待，都按第 2、4、6 节在画板里跑，可以连点按钮试。

截图：`preview/board-manual.webp`（手动模式和按钮条）、`preview/board-tiers.webp`（每档演出的几个时刻）。

## 11. 实现要点（2026-11-10 追问后用户定）

- **分工**：Core 只推“发生了什么”：这一轮礼物到目前为止的投入和份数、最贵的礼物、有没有城堡；盲盒这一轮的结果；大航海；进场；弹幕（只算有事）；抽奖状态；礼物榜状态；桌宠的设置；试演。哪些进场算数、一轮在哪里结束、盲盒赚亏，这些事实在 Core 里定、用 C# 测。演哪一段、排队和打断、一轮升级、摇盒等结果、心情、日常、选台词都在桌宠页里，照搬画板的引擎，用 Canvas 2D 照画板画，不改用礼物榜的 PixiJS；新的第一名照礼物榜页用 `changes.mjs` 比前后两次状态。代价：两个推流软件同时连着时各演各的（台词随机、日常不同步），刷新浏览器素材后心情回到平静。
- **盲盒等播报**：这一轮的盲盒播报发送结束时她就开盒，发成功和发送失败放弃都算，演的是它报的那份；排在发送队列后面时她一直摇（两次发送隔 1 秒，前面的欢迎 30 秒过期，最坏约等 30 秒）；发送途中又送来的盒子算下一轮，再演一次，和机器人一样。
- **素材**：保留原图的分辨率（站姿 360 px，画上 250 px 高），页面按浏览器素材的大小等比缩放，2K、4K 画布可以把素材设大而不糊；GUI 安装包约多 33 MB。素材按段加载，不一次全载：全部解码约 574 MB。
- **不出声**：她一直在动，进场挥手、日常每 20–40 秒一次，配声音太吵，送礼动画在视频页也有声音；以后要加再开票，音量照用拉杆。
- **页面和设置**：地址 `/desktop-pet`，总开关关着时全透明。设置放设置文件的 `desktop_pet` 分组，带升级步骤和测试；台词只存改过的类，按角色和演出的英文 id 记。
