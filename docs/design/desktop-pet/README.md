# 桌宠

直播画面一角的 Q 版看板娘和她的精灵，按直播间里发生的事表演，配气泡和台词，给观众和主播提供情绪价值。
地图和已定的框架在 [#343](https://github.com/cyaoc/aether/issues/343)；角色素材在 `docs/design/mascot/`。本文是演出设计的完整版本，
2026-11-08 在对话里定下，图还没出，出图和画板按文末"流程"走。

## 1. 基本

| 项目 | 规格 |
|---|---|
| 形式 | 网页服务里的一个页面，主播加成浏览器素材，透明底；只在 GUI 版有 |
| 推荐尺寸 | 480 × 640：城堡演出时城堡约 340 px 高占上半部，她站在台阶下（`preview/castle-page.webp`）；画板上实测再定 |
| 她 | 当前角色的 Q 版：脸、画风、彩铅质感照 `mascot/textures/chibi-sheet.webp`，身体照 `chibi-turnaround.webp`，约 2 头身；站在页面下方正中，平时约 250 px 高（1080p） |
| 精灵 | 当前角色的精灵（`mascot/textures/sprite-*.webp` 和本目录的精灵动作表），平时在她身前低处，位置见第 1.1 节 |
| 朝向 | 一律正面或略侧向镜头，放左下角、右下角都能用，不做镜像 |
| 气泡 | 代码画，见第 7 节 |
| 一位角色要准备的 | 第 8 节的全部动作表、精灵动作、城堡和大航海的道具，加第 7 节的台词，都放在角色文件夹里；代码只认姿势名和事件，不认是谁 |

### 1.1 精灵和她的位置

查过的做法：分镜里忌讳两个角色平行于画框并排（画面会平）；两个角色常用斜线错开、一前一后、靠部分遮挡做出纵深；陪伴型小角色贴着主角动，不在旁边并排站着。上一版精灵在她身侧、肩膀高度，和她左右排开，显得远、显得平行。

定的是**前景低处**：精灵在她身前（画在她前面），比她站的位置低，压住她身体外缘约四分之一个精灵宽，约为她头高的六成（比立绘里的一半略大，靠前显得近）。比较过的三种在 `preview/sprite-placement-options.webp`，定稿的示意在 `preview/sprite-placement.webp`。

| 状态 | 精灵在哪 |
|---|---|
| 平时、多数事件 | 她身前低处，大约在她腰到大腿的高度，在她身体外缘（画面左侧）；在原地做自己的动作（挥小旗、点头、惊讶……） |
| 新的第一名 | 举着王冠飞到她头顶正上方，往下戴到她头上，再飞回原位 |
| 沮丧 | 飞到她头上方摸摸她的头 |
| 犯困 | 落到她抱着的膝盖旁边一起睡 |
| 提督 | 当她的瞭望员：先飞到她望远镜看的方向（画面左边）、挥小旗打信号，再飞回原位陪她敬礼 |
| 城堡 | 飞到她身后变回原型城堡，见第 5 节 |

精灵压在她身上那一侧不能盖住她的手和她拿着的东西（礼物盒、盲盒、王冠、哑铃）：这些动作里精灵往外让开，只压她的裙摆或头发。立绘里"精灵的脸低于她的下巴"那条（`mascot/README.md`）只管立绘，桌宠按本节。

### 1.2 连贯动作

动作是一串一串生成的帧，不切贴图，交叉淡化也算切贴图。用户看第一版画板时指出"转圈一直正面朝人""安慰和其他动作都没过渡""人物有位移"；看第二版又指出"骑车、走路脚都不动""应该生成连贯的动作、而不是直接切换贴图"。

- **动作本身动**：持续的动作是循环帧（蹬车、迈步、挥手、鼓掌……），一次性的动作播一遍停在最后一帧（抬手敬礼、举起望远镜、屈膝礼、跳上船）。每组 4 帧，清单在第 8 节"动作帧"。
- **换动作有过渡帧**：演出里每一次换姿势都生成了中间两帧（清单在第 8 节），换的时候按顺序播，反过来走就倒着播。道具也有来路：礼物盒从上面掉进她手里，哑铃是弯腰从地上捡起来的，背包是背上去的，自行车是推过来跨上去的。换衣服的那一下由精灵转圈的闪光盖住。新加的组合要是还没补帧，先用老办法过渡：旧姿势往下一蓄，新姿势从旧姿势的高度长出来或沉下去，新图盖上再退旧图。
- **她不能平移**：每格按人的重心对齐，不按格子中心。动作表里的人在三等分格子里并不居中（左列偏右、右列偏左约 20 px），按格子中心对齐时，换姿势会左右跳 20–40 px。一组帧都用它出自那一格的对齐点，所以只有动的部位在动。
- **不抖**：codex 每帧都会把整个人重画得略有不同，直接播会"抖"。所以只取帧和帧之间真正在动的部位（挥的那只手、蹬车的腿），别处每帧都是原格的像素。
- **精灵转身**：精灵有正面、四分之三、侧面、背面四个视角（`textures/sprite-views.webp`，朝画面左边，往右时镜像）。绕她转圈时按前进方向依次换正面、四分之三、侧面、背面，转到她身后时画在她后面，近的半圈稍大一点。
- **精灵飞行**：去别处时用侧面或四分之三，尾巴摆动（飞行循环帧），身子往前进方向倾；到了才换成要做的动作，落下时压扁再弹一下。举着王冠、发着光这两种飞的时候本身就是动作，不换视角。精灵的每个动作也是循环帧（挥旗、点头、摸头、打哈欠、睡觉呼吸……）。
- **不瞬移**：换场景靠动作连起来。总督时她跳上船、跳下船；城堡演出最后她从城门跑下台阶回来，城堡缩回精灵；换装都由精灵绕她转一圈带出闪光。

### 1.3 精灵和她的互动

精灵是她的伙伴，跟着她的事一起动，不在旁边各演各的（用户指出"小精灵和桌宠互动少了"）：

| 时候 | 精灵 |
|---|---|
| 进场 | 先抬头看她，再和她一起挥小旗 |
| 普通礼物 | 和她一起鞠躬 |
| 连着送 | 飞到她肩旁，学她捂脸害羞 |
| 大礼物 | 趴在礼物盒边偷看；她举起欢呼时被抛过头顶，再绕她转圈 |
| 盲盒 | 凑到盒边和她一起听；开大时被光冲得往后弹，再在她旁边蹦；开亏时躲烟抱头，再飞去摸她的头 |
| 舰长、提督、总督 | 发着光绕她转一圈，带出换装闪光；舰长、提督时换水手领在她身旁敬礼，提督时还去她望远镜的方向瞭望打信号，总督时飞上后桅杆 |
| 抽奖 | 宣布时飞到她举起的拳头旁挥旗；等开奖时抬头看她、发抖；点名时顺着她手指方向冲出去挥旗；大奖被抛起绕圈，二奖跟她的掌声蹦，三奖和她一起点头 |
| 日常 | 举哑铃时挥旗打拍子；哼歌时跟着摇；爬山时在前面领路；骑车时侧身并排飞 |
| 出事 | 先吓一跳再过去：砸到脚就飞到脚边揉，破音就抱头，摔倒就飞回来摸头，贴创可贴时在旁边点头 |
| 心情 | 平时隔一会儿抬头看她；无聊时懒洋洋地飘、打哈欠；沮丧时摸头；犯困时靠在她膝盖旁睡，她磕醒时一起吓醒 |

## 2. 档位和优先级

**一件事只演一段，按最具体的那一类算：**

| 收到的事 | 演哪一段 |
|---|---|
| 开通或续费大航海 | 舰长、提督、总督之一，不再算大礼物 |
| 城堡礼物（直接送，或盲盒开出） | 城堡演出，不再算大礼物或盲盒 |
| 盲盒 | 开出城堡→城堡；开出的礼物至少是盒子价格的 2 倍→盲盒开大；开出的比盒子便宜→盲盒开亏；其余照开出的礼物算大礼物或普通礼物 |
| 其他礼物 | 单笔达到门槛（默认 1000 电池）→大礼物，否则→普通礼物 |
| 这一笔让礼物榜换了第一名 | 主演出结束后接一段"新的第一名"，不单独再演 |

**分档：**

| 档 | 演出 | 正在演别的时候来了它 |
|---|---|---|
| S | 总督、城堡 | 打断 A 档及以下；同档排队，永远不丢 |
| A | 提督、大礼物、抽奖 | 打断 B 档及以下；同档排队，最多排 3 个 |
| B | 舰长、盲盒开大 | 打断 C 档及以下；同档排队，最多排 3 个 |
| C | 普通礼物、进场、连着送礼、盲盒开亏 | 打断 D 档；正忙就丢掉 |
| D | 心情、日常小动作 | 随时被打断，不排队 |

- 被打断的那段直接结束，不补演。
- 同一个人连着送同一种礼物，合成一段，台词里的个数是合计。
- 抽奖跟着抽奖的进度走：被 S 档打断后，S 档演完回到抽奖当前的状态（还在开奖就继续"期待"）。

## 4. 抽奖

两种抽奖共用一套反应；揭晓按档次分三种。开奖特效播放时她一直"期待"，等抽奖页揭晓、特效收尾后再做反应，不抢抽奖页的戏
（要查 `LotteryController` 推给页面的状态里能不能知道特效什么时候收尾，不能就按各套主题的时长算）。

| 时机 | 报名抽奖 | 奖池抽奖 | 她 | 台词 |
|---|---|---|---|---|
| 主播新开一场 | ✓ | ✓ | 宣布 | 报名抽奖开场／奖池抽奖开场 |
| 报名截止 | ✓ | | 期待 | 报名截止 |
| 主播点名一位观众 | | ✓ | 点名 | 奖池点名 |
| 转动、开奖特效中 | ✓ | ✓ | 期待 | 奖池转动（奖池抽奖） |
| 揭晓·大奖 | ✓ | ✓ | 欢呼；精灵开心 | 揭晓·大奖 |
| 揭晓·二奖 | ✓ | ✓ | 鼓掌 | 揭晓·二奖 |

| 没人报名就结束 | ✓ | | 失落 | 没人报名 |

## 5. 城堡演出（S 档，约 11.5 秒）

精灵的原型是一座立在浮空云岛上的童话城堡（`textures/castle-closed.webp`、`castle-open.webp`，1024 × 1024 透明底）。Q 版也要大气恢弘：金字塔剪影，底下一圈带门楼的城墙、中间一层宫殿、最上面带挑台的主塔，十几座粉尖塔高低错落往正中收拢；最顶上三座塔就是精灵的王冠（中间最高、插红旗），正门上方一扇大玫瑰花窗，中间是精灵的红蝴蝶结和玫瑰盾徽；主塔两侧有空中廊桥；白石大台阶从下方正中通到红色大门，她沿着它走进去；云岛就是精灵的云身体，两侧有云瀑，背后一道大彩虹。我们自己设计，不照抄礼物美术（不画长桥、马车、路灯）。第一版只有三座塔，用户嫌寒酸（`preview/castle-first-try.webp`）；定稿以设定图 a（`preview/castle-sheet-a.webp`）为底，加上设定图 b 的大玫瑰花窗和空中廊桥。开门那张只重画城门、用 `tools/patch-box.py` 贴回关门那张，两张只在城门附近不同（`preview/castle-gate.webp`），切换时不跳；门里的光束、星星由代码画。

| 时间 | 画面 |
|---|---|
| 0–1.5 秒 | 精灵浑身发光，飞到她身后、放大，交叉淡入成城堡（门关着），升到页面上半部 |
| 1.5–3 秒 | 她转圈变身：闪光里换成公主装（`textures/princess-sheet.webp`：冠冕是城堡顶上那组三塔，珍珠白上衣保留泡泡袖，胸前大红蝴蝶结别着玫瑰盾徽，白手套，及地三层蓬裙白、粉纱、金边带粉玫瑰，腰后大红蝴蝶结垂着飘带） |
| 3–4.5 秒 | 屈膝礼，气泡说城堡台词 |
| 4.5–7.5 秒 | 转身背对镜头走向城堡：背面走路四帧循环（左右脚轮流从裙摆下露出、裙摆跟着摆），代码让她越走越小、往上移，像走进远处 |
| 7.5–9 秒 | 城门打开、透出光，她在门口回头挥手，气泡"欢迎来到我的城堡～" |
| 9–9.8 秒 | 城门关上，她蹦三步跑下台阶回到原位，越来越大 |
| 9.6–10.5 秒 | 城堡缩小、飘到精灵平时的位置，淡出；精灵从里面出来 |
| 10.5–11.5 秒 | 精灵发着光绕她转一圈，闪光里换回平时的衣服 |

## 6. 心情和日常（D 档）

没有事件时，她按冷场时长换心情。计时从上一次有礼物算起，"犯困"从上一次有任何事件算起。

| 心情 | 条件（默认） | 她 | 精灵 | 台词 |
|---|---|---|---|---|
| 开心 | 最近 1 分钟内有 3 件以上事件 | 待机，代码让她轻轻蹦；偶尔哼歌 | 绕着她转 | 不说 |
| 平静 | 其他时候 | 待机；每隔 20–40 秒随机做一个日常小动作 | 在旁边飘 | 日常 |
| 无聊 | 15 分钟没有礼物 | 托腮发呆 | 打哈欠 | 无聊 |
| 沮丧 | 40 分钟没有礼物 | 蹲着画圈圈 | 摸摸她的头 | 沮丧 |
| 犯困 | 60 分钟什么事件都没有 | 打瞌睡 | 睡觉，靠着她 | 犯困（梦话），代码画 Z |

### 7.1 特效

第一版除了几个大奖，特效偏少（用户指出）。按设计技能（ui-ux-pro-max）和游戏手感、漫符的资料补了一套，全部由代码画。

**原则**：
- 强度跟着档位走，越大越隆重；震屏只给大事件的高潮和摔倒、砸脚这种冲击，平常的小事不震。
- 一次冲击是几样小东西在约 0.1 秒内一起出现：闪光、一圈粒子、漫符、轻微震屏。
- 粒子成团爆开、很快消失（6–12 颗，一颗颗错开 20–40 毫秒），不长时间连续喷。
- 出现用减速（弹出带一点回弹），消失用加速；一直循环的特效只留给持续的状态，而且要淡。
- 不挡她的脸和气泡：漫符放在她头顶左上（气泡在右上），光、集中线、速度线、地上的光圈画在她身后。

**词汇**：

| 类 | 有哪些 |
|---|---|
| 漫符 | 感叹号"!"、汗滴、怒气符号、头顶阴影竖线、小乌云下雨、"…"、叹气的一小团烟、头顶冒蒸汽、绕头转的晕星、飞出来的眼泪、惊吓线、裂开的音符 |

| 物件 | 飞进来的小礼物盒、往上飘的小锚、水花、金币、花瓣、飘过的枯叶，加原来的爱心、彩带、气泡、海鸥、烟花 |

**出图工具**（`tools/`）：

- `gen-sheet.sh <目录> <名字> <表号>`：出一张动作表，提示词是 `pet-base.txt`（人物、版式、格子边距）、`sheet-<表号>.txt`（六格）、`pet-negative.txt`；参考图是角色设计包的 Q 版九宫格和 Q 版全身。

- `edit-cell.sh <表> <目录> <名字> <格号> <改成什么>`：只重画一格，再只把这一格贴回原表；贴回要 Pillow，用 `PYTHON=` 指定装了它的 Python。
- `gen-castle.sh <目录> <名字> <城堡参考图> <表文件>`：城堡设定图（`castle-sheet.txt`）；`gen-castle-final.sh` 出定稿的透明图（`castle-final.txt`）。提示词是 `castle-base.txt`、`castle-negative.txt`；城堡参考图是礼物截图，不在仓库，只取通用的童话元素。
- `gen-princess.sh <目录> <名字> <表文件>`：公主装设定图（`princess-base.txt`、`princess-sheet.txt`、`princess-negative.txt`）；`gen-sheet-princess.sh <目录> <名字> <表号>` 出穿公主装的动作表，提示词是 `princess-pose-base.txt`（`pet-base.txt` 换了服装段）。
- `gen-fleet.sh <目录> <名字> <表文件>`：大航海服装设定图（`fleet-base.txt`、`fleet-sheet.txt`、`fleet-negative.txt`）；`gen-sheet-fleet.sh <目录> <名字> <表号>` 出穿大航海服装的动作表，提示词是 `fleet-pose-base.txt`（`pet-base.txt` 换了服装段，每格写明穿哪套）。
- 动作表 7 的"回头挥手"第一次画成一个肩膀伸出两只胳膊，用 `edit-cell.sh` 只重画这一格（`preview/pose-7-wave-fix.webp`），负向词加了这条。
- `patch-box.py <原图> <改过的> <输出> <x0,y0,x1,y1> [羽化] [alpha]`：只把一个方框贴回原图，边缘柔和，框外一个像素不动；加 `alpha` 时连透明度一起取。
- `key-box.py <原图> <绿底上改过的> <输出> <x0,y0,x1,y1>`：改动超出轮廓时用。透明底上直接改，codex 会在周围留一圈半透明光晕；先把原图放到纯绿底上改，再按绿色抠回那个方框。
- `gen-ship.sh <目录> <名字>`：大船，提示词 `ship-base.txt`、`ship-sheet.txt`、`ship-negative.txt`。
- `gen-frames.sh <目录> <名字> <原图> [<结束的那张>]`：一组动作帧。原图写成 `textures/pose-1-common.webp:2`（3 × 2 表的第 2 格）、`textures/sprite-views.webp:3/4x1` 或单张；放到纯绿底上给 codex，按 `frames/<名字>.txt` 出 2 × 2 四帧，第 1 帧就是原图；过渡再附上结束的那张，第 4 帧画成它。绿底比透明底干净，codex 在透明底上会留一圈半透明光晕。
- `frame-patch.py [--from-first] [--box x0,y0,x1,y1] <原图> <四帧.png> <输出.png> [预览.png]`：把四帧做成不抖的帧条。按绿色反解透明度和颜色（篮子细丝、发丝缝隙不留绿边）；先按轮廓（同高、脚底和中线对齐）再细找，把第 1 帧对齐到原图，其余帧同样放；只取帧之间真正在动的部位（自动找，或限在 `--box` 里），别处用原图的像素。codex 把不动的部分画得太不一样、接缝对不上时（第一次蹬车时车架出现两根管子），加 `--from-first` 用它的第 1 帧当底。
- `add-frames.py <名字>-strip.png ...`：帧条存成 `textures/frames/<名字>.webp`，登记进 `blobs.json` 和画板的 `FRAMES`；之后重启 `server.mjs`。
- `sheet-check.py <表> <预览> <六格名字>`：量每格的顶、底、高（和第一格待机比）和是否碰到格子边，出一张带格线、脚底线的预览。
- 切图按每格里的内容切，不按死格子切：4 号"骑车摔倒"的后轮伸进隔壁格约 8 px。
- 平时不贴创可贴；出图后有创可贴的，用角色设计包的 `remove-bandage.sh`、`bandage-patch.py` 擦掉，只留 4 号"贴创可贴"那一格。

## 8.1 画板和本地预览

演出在本地直接看，做法同进场动画设计包：

```
node docs/design/desktop-pet/tools/server.mjs 8820
open "http://localhost:8820/render.html?board=DP-DesktopPet.dc.html"
```

画板 `boards/DP-DesktopPet.dc.html` 画一个 1920 × 1080 的直播画面，虚线框是浏览器素材（480 × 640，页面本身透明）。
图都从设计包的动作表、精灵表和道具里按格裁，不另外切图；`tools/blobs.json` 把 `/_blob/<id>` 对到文件。

参数（URL 里的 `props`，JSON）：

| 参数 | 取值 | 作用 |
|---|---|---|
| `scene` | `手动`（默认）、`演示`、`平时`、`心情`、各个事件、`大礼物+新第一`、`报名抽奖`、`奖池抽奖`、`没人报名` | `手动` 时用页面下方的按钮触发事件；`演示` 是 30 秒循环（进场、普通礼物、大礼物接新的第一名）；其他是固定循环，配 `freeze` 截图 |
| `env` | `右下角`、`左下角`、`小页面` | 页面放在直播画面哪个角；`小页面` 把页面缩到 0.75 倍 |
| `room` | `明亮画面`、`深色房间`、`透明` | 直播画面 |
| `name` | `普通昵称`、`长昵称`、`中英混排` | 气泡里的昵称；超过 8 个字截成 7 个字加"…" |
| `speed` | `1 倍`、`0.5 倍`、`0.25 倍` | 慢放 |
| `caption`、`controls` | `显示`、`隐藏` | 左上角的说明（正在演什么、哪档、排队、心情、抽奖状态、最近的打断和丢弃）；页面下方的按钮条 |

`freeze=<毫秒>` 把时钟钉在那一刻；`tools/cdp-shot.mjs "<地址>" <输出.png>` 用无头 Chrome 截图。
`手动` 时按钮条有：全部事件（含连送 5 份、大礼物接新的第一名）、两种抽奖的每一步、四个日常小动作和各自出事的版本、快进 10 / 30 分钟（看无聊、沮丧、犯困）。
优先级、排队、连着送、冷场惊醒、抽奖被打断后回到期待，都按第 2、4、6 节在画板里跑，可以连点按钮试。

截图：`preview/board-manual.webp`（手动模式和按钮条）、`preview/board-scenes.webp`（城堡四个时刻、总督、沮丧、犯困、左下角长昵称）。
画板上的时长、大小、气泡样式是第一版，看过再改，定了写回本文。
