# 进场动画 · 制作守则

每做一档、一个身份、一款隐藏款之前，从头读一遍本文；给用户看之前，逐项过一遍第六节的自查清单。画面怎么设计看 [DESIGN.md](DESIGN.md)，已有画板的参数看 [README.md](README.md)，生图提示词看 [prompts.md](prompts.md)。

本文由 2026-10-26 做一般人 40 档的会话复盘而来：那一档返工了 4 轮，每一轮都是用户先发现问题。10-26/27 做 50 档又返工了 3 轮（招式太朴素、手背到身后、斩铁的线对不上），复盘补进了第一、四、五、六、七节。目标是让下一档在交付前就把这些问题查出来。

## 〇、一次过：用户的评估标准

2026-10-31 按 60 档返工的全过程总结。生图前读一遍，生图后按这张表逐项查，有一项不过就不给用户看。自查过的图也要先给用户确认，确认后才上画布；设定图确认后才生成动作图。

发现任何问题，不管是自查发现还是用户指出，当场做三件事再修图：记进这一节；**写进 `tools/prompt-negative.txt`，这一步必做，只记在文档里生成时不起作用**，容易错的再写进 `tools/prompt-check.txt`；能量化的加进检查项（“以后发现任何问题、都记下来、并写入规则和负面提示词”“你该把发现的问题都写入负向提示词”）。背景图的问题写进 `tools/prompt-negative-bg.txt`。招式重复、前后衔接这类两张图之间的问题，单张图的负面提示词管不到，写进本节并在设计阶段查。

| 用户看什么 | 用户的原话 | 怎么防 | 怎么查 |
|---|---|---|---|

| 手和手指的形状 | “手和手指错位” | 写清哪面朝外、四指从哪边包、拇指在哪边；空着的手握拳，张开的手容易少手指 | 数五指，指节排列整齐，手不和刀柄错位；一根刀柄上的两只手只有一只露出手背星纹（pose-15 两只都露，手型错） |
| 惯用手 | “人不能一会左撇子一会右撇子” | 全片右手握刀，刀挂左胯，图不镜像（“人物统一优于镜像”） | 每只手追到肩膀，靠护手的必须是右手；朝右时露星纹的手必须贴着护手，这条最容易错（pose-60/67/71/72/78 都有）；数手，pose-30d 多出第三组手指，n61a 鞘口旁多出手指；手型也要对：看拇指朝向、手背还是手心朝外，左臂上画成右手型就是两只右手；刀在鞘里时护手要夹在两手之间，刀柄上不能没有手；朝右时刀鞘挂在靠镜头的胯上就是左撇子，重画 |

| 方向 | “人物的起始位置在左、面向右面的月亮、人物、月亮结束位置可按照动作设计、不固定”“月亮位置随着人物动作变化、不固定、但人又开始就是从左到右对着月亮” | 四档开场都是人物在左，从左往右面向前方的月亮；之后月亮随动作变化 | 每档第一个镜头人物在左、面朝右，月亮在他前方（右边），不在身后 |

| 刀光 | “刀光终点落在刀尖” | 清单写死：拖影是一笔，收在刀尖，不过头、不回钩 | 拖影终点和刀尖重合 |
| 刀的结构 | “刀居然不是直的”“刀刃方向反了” | 提示词清单写死“刀是一根直线”；出鞘的图都用 `tools/paste-blade.py` 带 `pommel=` 重贴刀身，方向取自刀柄，折角从根上归零；刀压在身体上时不能重贴，擦除会在身体上留透明细缝，叠贴会出重影（n23k）：保留原画的刀，用 `tools/shorten-hilt.py` 收短悬空那段；刀长 = 护手直径 × 6.27 | 刀身笔直，刃迎着砍的方向，刀背在拇指一侧，刀尖在刀背一侧；每张图都用 `tools/sword-axis.py` 量柄尾、护手、刀尖的夹角，超过 4° 不给用户看，不靠目测，也不靠读网格（pose-5b 手读 4.5°，实际 9.3°；n23k 手读 3.3°，实际 9.3°），工具和手读不一致时信工具，先查手读的点；银帽被手挡住时工具会找错，要看它标的位置对不对；举过头顶的姿势最容易折（pose-30 三张折 17–20°），提示词要写明整把刀的斜度，拖影帧最好写死柄尾和刀尖在图上的位置；刀柄中段不能多出银环（pose-6e）；拖影里不能有第二把实心刀（pose-25a） |
| 刀的长度 | “刀身长度要统一一致”“刀柄长度不统一” | 刀身同上，世界坐标约 370 px；刀柄按设定图比例，护手中心到柄尾 = 护手中心到鞘尾 × 0.325 | 双手握的图刀柄容易画长，单手和双手的刀柄要一起量；写落点前先算够不够得到：从手到落点的距离不能超过刀长，否则模型只能拉长刀（pose-15 写“刀尖碰到后脚跟后面的地”，刀长到 861 px）；刀压在身体或衣带上的图不能擦除改短，擦掉后下面没有内容，要改提示词重画；贴完看刀头：缩短刀身时旧刀尖要擦净，也不能留细线（`paste-blade.py` 早先漏擦，刀头断成两截）；量每张图的刀身和刀柄：拿护手直径当尺子，刀柄 ÷ 护手直径 = 2.0，超过 2.4 重画（双手图写“留一拳间隙”时到过 2.84）；刀在鞘里、柄尾悬空的图用 `tools/shorten-hilt.py` 收短，不用重画，收完放大看柄尾银帽还在不在（拳头到柄尾只剩 30 多 px 时，羽化曾把银帽融掉，总览图看不出）；刀柄和刀鞘共线，这个比例不随机位变；模型会为了填满画框把刀拉长或压短（同样大小的人物，刀长 283–932 px），放不下时要缩小人物，拖影帧写死刀尖在图上的位置 |
| 刀和手的穿模 | “刀把穿模” | 前臂和刀柄要有夹角，不写“刀和手臂成一条线” | 刀柄穿过拳心，不压手腕 |
| 法相的手 | 自查发现（oni-7b） | 法相两只手都是盔甲手套，照人物姿势图生成时写明不抄人手 | 放大看手套上有没有露出肉色手指 |
| 道具数量 | “刀鞘似乎变成了2把”“出现了2把刀鞘” | 写明只有一把刀、一把鞘；拔刀后鞘是空的，参考空鞘设定图 | 数刀和鞘，刀鞘被身体挡住的两段要在一条线上；空鞘上没有刀柄和护手；红绳只在鞘口一端，鞘尾是银帽（pose-77a/b 红绳跑到鞘尾）；鞘口和鞘尾也要量，两段不在一条线上就读成两把刀鞘 |
| 人物一致 | “检查人物、道具、衣服的一致性” | 每张图以三视图和武器设定图为前两张参考 | 对照设定图：发型、外套、手套、绑带、红靴底、刀镡、刀鞘 |
| 画风 | “day的画风是不是和现有的绘画风格不一样”“风格适配” | 新背景只拿现有背景作参考，只换时间和颜色 | 放到人物后面比过再用 |
| 招式有没有设计 | “太装了”“背对着慢慢走”“新动作为啥出现了硬扛”“起手式动作太平淡、一闪的动作不是这么平淡”“30档的一闪被你做的像飞剑”“30档收尾应该收刀”“40档和50档的收刀动作都改成挥刀入鞘”“站起再收刀再半蹲、很奇怪、应该就着最后一个动作收刀”“40档最后上举着收刀看起来很傻”“40档和50档的收刀能不能换成正常站立收刀” | 动手前先查资料；主角面向对手、一路进攻；起手式要有蓄力感，低、压、绷紧，不能站着；地面招式双脚踩地，靠踏步发力；最后一招要落在低处，上举的招式放中间；收尾站起身正常收刀，站起后不再蹲下 | 每一刀说得出为什么这样动；只看起手那一张也要有张力 |
| 动作衔接 | “动作衔接不合理”“都下劈了为啥后面又来了一次”“动作衔接还是要调整”“动作设计要接近现实、但可以为了表达更高的冲击力适当艺术加工、但动作衔接一定要自然” | 招式以真实动作为骨架，夸张只加在速度、距离、高度上； 上一招收招的刀位、重心、速度方向就是下一招的起点，用惯性接，不重新摆架势；同一档不重复同方向的刀；刀的状态要连续（在鞘、出鞘、入鞘都要有动作交代） | 列出每招的起止刀位和方向，相邻两招接得上，方向不重复；拼连续帧或连续播放看一遍，不只看关键帧 |
| 刀光形状 | “刀光弧线太圆” | 刀光贴着刀尖的真实轨迹，快刀是又长又扁的一道，不画成圆弧 | 看拖影的弧度，居合一闪接近直线 |
| 档位差距 | “重复感官不好”“太写实了就没有了华丽感”“比不上50档次” | 高档不复用低档动作；人体真实，招式夸张 | 空间、规模、出刀、力度都超过下一档，主角在画面里不比下一档小；各档主角在屏幕上要一样大（“50和60的镜头拉远了、显得人小很多、和30/40放一起有点出戏”）：以 30、40 档为准，屏幕上的护手直径约 56 px，全身约 700 px；只有法相亮相和一刀切月这类要看全景的镜头才拉远 |
| 文字 | “只有粉丝名”“b站名字是有中日英文的”“统一字体” | 全程只显示粉丝名，一款字体 | 中文、日文、英文、混排各试一次 |

**我最容易犯的错**

1. **说“都对了”太早**。缩略图看不出手的问题，要放大到单只手。
2. **不先核对设定图**。设定图错了，后面每张都跟着错。设定图要先查刀是否笔直、刃在哪一侧。
3. **绕开问题**。手画不对时把手藏起来，反而更错。
4. **在原图上加东西**。模型会抄现成的部分，加手就成了两只右手。手不对就整张重画。
5. **提示词自相矛盾**。写了不成立的机位，或者写了“刀和手臂成一条线”、刀够不到的落点、两手留一拳间隙（刀柄只够两个拳头）这种画不出来的要求。
6. **只改用户点名的那几张**。同类问题要全部查一遍。
7. **矫枉过正**。用户说人体不对，我把招式也做成写实的。
8. **凭空编招式**。没查资料，说不出为什么这样动。
9. **用镜像省事**。镜像会把右手变成左手，人物一致性优先。
10. **让两条胳膊交叉**。右撇子朝右时胸口一转向镜头，两臂就要交叉才能握对，模型总画成不交叉，左右手就反了（pose-2、pose-21 试跑）。朝右用纯侧面，朝左才转向镜头。
11. **同样的错反复修图，不写进提示词**。“刀把和刀不是一体的、变成了折角、这些反复发生的问题、你应该计入绘画提示词”。出现过一次的问题，当轮写进 `tools/prompt-check.txt` 或 `prompt-negative.txt`，`gen.sh` 自动带上。
12. **只看单张、不做挑选**。同一提示词的结果有随机性，左右手和拖影可能这张对那张错。每张图跑 2–3 次，逐项量过再挑。
13. **规则写了还错，就只加规则**。n2 三张都把星纹手放到护手的刀鞘一侧，这条规则早就写了。规则管不住的姿势，用已合格的图当第三张参考，写明两只手和刀照它画。
14. **拿刀柄偏长的图当参考**。模型连刀柄比例一起抄：n33 参考 pose-9a，改了提示词刀柄还是 3.0 倍护手。参考图本身要先过这张表，用修好的成品图（`final2/`）当参考，不用原始图。
15. **按结束时间判断用了哪版提示词**。提示词在生成开始时读入，结束得晚不代表用了新版。改完提示词后，已经开始的都算旧版。
16. **按图里偏短的部分推算比例**。法相第二张刀柄画短了，我按刀柄算刀长，刀就更短了（“法相第二张的刀短了”）。比例先按护手直径算；护手斜对镜头时直径会变小，这时用同一张图的刀鞘长度核对，刀身略短于刀鞘（法相第二张的刀最后按这条定为 720 px）。
17. **手改生成出来的提示词文件**。模板重跑会把它盖掉（n91 手写的“以底图为准”被盖回站姿版，8 张白跑）。手写的提示词放进模板，或存成模板不生成的文件名。
18. **为了加一个动作，先把人挪到能做它的姿势**。50 档我让人站起再蹲下去收刀，40 档让人从高举压回低弓步，动作是全了，身体却来回折腾。设计收尾时先看最后一招停在哪，从那里出发。
19. **用户问“是不是”“能不能”，我抢先动手**。用户问镜像行不行，我答完就开始改画板，用户连说两次“等等”，最后方案还变了。先答，等用户定，再动手。
20. **把自己加的要求当成用户的要求**。“四档收尾各不相同”是我加的，用户没说过，为了它绕了三轮才回到“正常站立收刀”。方案卡住时先分清哪条是用户定的。
21. **只看截图，不看连贯**。这次衔接问题全是用户看动态时发现的：收刀突兀、站起又蹲下、刀光拖过下一招。交付前把一段动作按每 83 ms 一张拼成连续帧，相邻两帧逐对看，或者自己连续播放一遍。
22. **修图只看目标处，不看修完的整张**。pose-23 擦鞘口时矩形范围切掉了一块身体，贴刀时留过透明细缝和断开的刀头，收刀柄时融掉过银帽。修图后要放大看修过的地方，也要回到全图看一眼。

## 一、用户在意什么

按反馈出现的顺序。每一条都是用户的原话，后面是落到画面上的规则（权威写法在 DESIGN 第二节）。

| 原话 | 当时的画面 | 规则 |
|---|---|---|
| “人物没动作、太幼稚、特效廉价、冲击力差” | 第一版：立绘滑进来，配色带、圆环、卡通闪电 | 主角要真的出招，特效由动作引起 |
| “特效过多、动作过少”“看不到出刀” | 总督只抬手剑自己飞；次元斩一闪就到终点 | 高潮是主角亲手打出来的那一下 |
| “动作和刀光对不上” | 40 档第一版：刀竖着举，刀光却横着甩出去 | 刀光沿拖影帧画出的拖影走，终点落在收招图的刀尖 |
| “人物动作也没逻辑” | 40 档第一版只有各刀的收招图，刀和身体在帧之间跳 | 动作链：每张姿势是上一张的结果、下一张的起点 |
| “这两处修正一下” | 我列出的两个弱点：回身是左右翻面、旧拔刀拖影和收招方向不一致 | 自己看出的弱点交付前就修掉 |
| “30 档也一起换” | 新规则只用在了 40 档 | 规则一改，已做的档一起改 |
| “切割为啥都是弧线、用力不均……刀斩痕迹不都是直线么” | 天空沿弧形刀光裂开 | 刀光是弧，斩痕是直线 |

| “最后画面切割的斩击线和人物之前动作造成的斩击线不是一回事” | 50 档：空中四刀的刀痕落地后只留半截，斩铁时镜头框在地面，刀痕交汇处被上黑边挡住 | 斩铁沿出刀时的刀痕全长裂开；斩铁前镜头回到能看到交汇处、和出刀时同样远近的位置 |

## 三、继续这样做

- 先用文字描述（招式、动作链、分镜、要生成的图），用户说“可以/确认”后才生图。描述用表格，用户看得快、改得准。
- 在姿势图上画网格，量出胯、头、手、刀柄、刀尖和拖影中线上的点。刀光、命中点、斩痕都由这些点算出来，不凭感觉画。
- 每拍按毫秒截图，拼成对照表自己先看。刀光像激光、刀光扫过月亮、昵称压线、多出来的亮边，这些都是这样在用户看到前改掉的。
- 生图结果先在灰底上看透明通道。codex 常回报“背景没有透明”，以实际 alpha 为准。
- 改了规则，同时写进 prompts.md、DESIGN 和记忆。
- 做完一档或改了规则，用第六节的清单把已定稿的档也过一遍。2026-10-26 就是这样查出 30 档残心前刀从举起处直接跳到垂下（用户没提过），补上了甩刀的细刀光。
- 另一档已经解决过的同类问题，直接照搬它的做法，各档才一致：30 档的切入（居合架势滑入）和残心甩刀都照搬 40 档。

## 四、返工的根因

### 40 档（2026-10-26）

1. **只生成收招图**：照 DESIGN 写的“40 档 3 个姿势”只做了冲刺、第二刀、第三刀三张收招图。中间的举刀、出刀都没有，刀光只能凭空画；回身靠左右翻面硬凑。→ 先排动作链，按链补齐预备和拖影帧，张数由链决定。
2. **沿用旧素材没核对**：30 档的拔刀拖影往右下甩，拔刀收招的刀却平举在右边，两张图本来就对不上，我直接拿来用。→ 复用的素材也要量点核对，对不上就在描述里先提出来。
3. **照抄 DESIGN 里的写法**：DESIGN 写“天空沿刀光的弧线裂开”，我没想过刀砍出来是不是弧线。→ 画面要符合刀的物理：直刃砍出直线，力道均匀。
4. **只看最后一帧**：斩痕改成直线后，我只看了三条线都悬着的画面，没在每一刀刚命中时核对刀痕和刀光。→ 每一刀命中后都单独截一帧对齐。
5. **流程上的浪费**：后台先生成的 50 档 5 张姿势没有动作链，只能作废；生图命令引用了还不存在的参考图，白跑一次；几个 Chrome 并行截图钉不住时钟，截错了帧；拖影帧在顿帧里停了约 5 帧，违反 DESIGN 的“只停两帧”，是我自己没对照 DESIGN 查。

### 50 档（2026-10-26/27）

1. **照抄招式表，没和下一档比**：表里写着“滞空约 0.3 秒”，我就排了一个只摆姿势的倒立，出刀比 40 档还少。→ 描述前先列这一档的出刀数和节奏，和下一档比；高光段落必须出刀；拿不准就先查资料（这次查的 God of War 连招节奏、绝区零雅和崩铁黄泉的大招，都是“连斩 → 停顿 → 终结一击”）。
2. **生图后没看手**：只看了转身、刀位，没看手，三张图手背到身后，其中一张是我自己的提示词写的。→ 提示词写死两只手的位置；生成后逐张看手、量刀长（pose-15 第一版刀长是头到胯的 2.7 倍）。
3. **为排版改了因果**：为了给昵称让位置，把空中四刀的刀痕裁成半截、斩铁也不沿它们裂。→ 画面上的东西要和动作的因果一致，排版只能挪昵称和镜头，不能改刀痕。
4. **只在世界坐标里核对，没从观众的画面核对**：刀痕在世界坐标里没变，但最后的镜头把交汇处挡在黑边外，看起来像另一组线。→ 斩铁那一拍和出刀那几拍并排截图，对照刀痕在月亮旁边的位置。
5. **复用的规则没重查**：40 档也有“前两刀半截淡掉”的做法，是这次才一起改的。→ 改了规则，已定稿的档立刻按新规则过一遍（第三节已有，这次又漏了一次）。

### 60 档（2026-10-27）

1. **只查了“手在不在身后”，没查“刀在不在身后”**：第一版 9 张都是三分之四背面，手都在身前，但刀和手横在后腰上、拖影从后腰起，用户一眼看出“背后握刀、在身后拔刀”。→ 腰间佩刀的姿势一律侧身；生成后看刀鞘、刀柄、拖影起点是不是在身前和近处的胯上。
2. **非人物的图没数手**：法相居合图多一只手、法相收招图换了手臂，都是用户先看出来的。→ 法相和主角一样逐张数手；收招图只拿拖影帧作参考生成，相邻帧并排看手臂。
3. **几何先算再生图会白算**：第一版图上做的排版搜索，换成侧身图后刀痕从 22° 变成 37°，月亮、法相、镜头全部重排。→ 先把图生成、看过手和刀，再量点排版。
4. **“手都对”说早了**：连着三次都是用户先看出手和刀鞘的问题。只数手的个数不够。→ 用全尺寸裁图逐只手追到肩膀，刀、鞘也看两端连不连。
5. **藏手臂不是解法**：pose-15 多画手时我改成只画一只手，后来又把 37–45 也写成“另一条胳膊藏在身后”，用户问“42-45怎么只有一只手”。→ 人物始终两条胳膊两只手，手放在真实的位置；多画了手就以这张图为底只改这一处，不靠藏。
6. **把“终结技”想成“少出刀”**：我先往大招前塞连斩，又想减刀，都没抓住要害。用户要的是最高的冲击力、爆发力和华丽度，而且由动作撑起来。→ 高潮里每个大特效都对得上一个身体动作：蹬地炸地、穿屏出月牙、急停擦火花、拍刀炸开世界。
7. **爆裂把主角冲没了**：第一版光晕画在主角前面，全屏过白 200 多毫秒，还违反闪光规则。→ 大光效画在主角后面，主角始终看得清。
8. **刀痕留到了现实世界**：世界碎掉后刀痕还悬在白天的天上，又被冲击波扭弯。→ 刀痕属于被斩的世界，和它一起消失；大冲击波不要盖住长直线。
9. **宽姿势吃掉位移**：居合架势图很宽，放大后穿屏距离不够。→ 要大位移的段落先算姿势宽度，头的大小一致，不按单项指标放大。
10. **招式凭空编**：慢走、背对月亮、硬扛都是我自己想的，没查过资料，连“为什么要这样动”都说不出来。→ 每一刀都要说得出出处：哪只脚踏、胯往哪转、刀从哪到哪。
12. **矫枉过正**：用户说人体不对，我连招式也做成写实的，比 50 档还平。→ 分开看：人体和握刀要真实，招式、规模、镜头要夸张。
13. **设定图也要先过一遍**：刀是弯的、刃在内弧，我没发现就让它当了所有图的基准。→ 设定图是最重要的图，定稿前对照真实物件逐项查：刀身是否笔直（量上下边）、刃在哪一侧、握法是否成立。
14. **合格判定太松**：同一批图我说“都对”，用户又找出六处。→ 用 `qa` 对照表逐只手放大看；凡是“只露手指”“手从身后绕出”都算不合格。
11. **说“看过没问题”太早**：同一批图我连着说手没问题，用户连着找出问题。只看手的个数和连不连肩膀不够。→ 按第六节逐项查：哪只手握什么、两只手是不是一左一右、刀柄穿不穿手腕。

## 五、步骤

### 0. 设定图，等确认

每个新角色、新武器、新法相，开工先出各机位设定图（“先设计人物、武器、法相等各个机位视图、确认后再进入招式设计”）：

- 机位：水平八方向、仰视、俯视。有状态变化的（刀在鞘里、空鞘）每个机位各一份。武器也要有透视机位。
- 自查：量柄尾、护手、鞘尾是否共线，刀柄长 = 护手到鞘尾 × 0.325，手和刀鞘放大看。过了才给用户看。
- 用户确认后才进入招式设计和动作图。设定图改过，已生成的动作图要重新核对。

完成标准：用户确认过所有机位。

### 1. 读

读 DESIGN、README、本文、prompts.md，再按第二节的索引读这一档用得上的设计依据。找到这一档在 DESIGN 招式表里的写法，列出这档要引入的新机制。

完成标准：能说出这档的招式、要复用的素材，以及复用素材里有没有对不上的地方。

### 2. 描述，等确认

回复里要有：

- **动作链表**：每张姿势一行，写身体姿态、刀在哪（从哪到哪）、新图还是复用。每一刀标出预备、拖影帧、收招。
- **每一刀的刀光和斩痕**：刀光从哪划到哪、命中时亮着哪一段、斩痕的方向。
- **镜头**：哪拍抬、哪拍往下甩、刀尖会不会出画（上下黑边各 118 px，姿势图在膝盖处切开）。
- **月亮和天空**：斩痕不能穿过月亮（60 档除外），月亮放在哪；斩铁时镜头框在哪，能不能看到所有刀痕的交汇处。
- **节奏**：按毫秒列每拍；这一档出几刀、每刀的间隔，和下一档比强在哪。
- **要生成的图**：清单和张数；复用素材里发现的不一致和改法。

完成标准：用户回“可以”或“确认”。用户确认前，下一档的图一张都不生成。

### 3. 生图

- 用 `tools/gen.sh` 跑，人体说明、负面提示词和生成前清单（`tools/prompt-check.txt`）自动带上：参考图先拷进生成目录，运行前检查每张都在。需要上一张结果当参考的，串行生成。
- 第一张参考是这个身份的亮相图（定人物），再加动作链里前后相邻的姿势（定动作）。
- 每一刀要有挥到一半的姿势和收招图。图里不画拖影，刀光全部由画板画，这样弧度可控，终点落在刀尖，刀长也统一（图里画拖影时刀长 367–653 px，改不了）。挥到一半的图以收招图为第三张参考生成，保证接得上；挥到一半和收招几乎一样时只用收招图。
- 需要侧身、转身时提示词写死（“clearly NOT a back view”），脸写“covered by hair and deep shadow”。
- 手写死：用 prompts.md「人物图的固定写法」里的句子写清每只手在哪、握什么。生成后按第六节「动作」逐项放大看，并量刀长（刀约为头到胯的 1.1–1.3 倍）。手不对就整张重画，不在原图上补胳膊。
- 全身图要写 FULL BODY 那一句（见 prompts.md）；竖图处理时不要缩到 1200 高，头到胯会只剩 300 px，画板里放大会发虚。
- 没有前后依赖的图可以几张并行生成（codex 各跑各的，互不影响）。
- 处理：`process.py cutout` → 灰底合成检查 → 给用户确认 → 放进 `textures/` → 上传画布 → 写进 `tools/blobs.json` → 重启本地 server。

完成标准：链上每张图都在，灰底看过，把相邻的姿势并排看一遍，动作接得上。

### 4. 量点、算排版

- 每张图画网格，量胯、头、手、刀柄、刀尖；拖影帧在拖影中线上量 6–9 个点。
- 按胯对齐：每张图记胯在原图的位置和缩放，头到胯的长度在画面上约 440 px，前后差不超过 ±20%。
- 先算出三组数字：每张收招图的刀尖在画面上的位置（算上镜头，不能进黑边）；每条斩痕离月亮的距离（大于 50 px，刀光要再算上带宽，拖影帧图里画的拖影也算）；镜头上下甩时膝盖切边会不会露出来。
- 刀多、镜头动得多时，写个小脚本把胯位置、缩放、月亮位置当参数搜一遍，挑各项距离都够的一组（50 档就是这样定的）。

完成标准：三组数字都有，都在范围内；超出的先改镜头或排版。

### 5. 画板

从上一档的画板复制改，画在画布新的一行。刀光是量出的点连成的样条，终点是收招图的刀尖。命中时刀光的尾巴要追到只剩刀尖前近乎直的一段，斩痕取这段的弦，贯穿天空。天空按斩痕分块（每侧是线加一个大圆弧围成的多边形）。命中点、火花、冲击波、集中线都放在刀尖。

### 6. 自查

逐项过第六节，有一项不过就改，改完重新截图。

### 7. 交付

更新画布上的画板和旁边的说明便签。回复里给链接，说改了什么、请看哪几拍。自己知道的弱点先修掉，修不掉的才列出来，并给出改法。

### 8. 定稿后

更新 README、DESIGN、`preview/` 截图、prompts.md、blobs.json，提交推送到 `design/entry-animation`（PR #266），同步 #267（隐藏款同步 #268），更新记忆里的进度。

## 六、交付前自查清单

按实际毫秒逐拍截图，一次只截一张。

**动作**

- [ ] 相邻两张姿势之间，身体和刀的位置是连续的；头的大小变化不超过 ±20%。
- [ ] 每一刀都有预备、拖影帧、收招；拖影帧只停两帧。
- [ ] 转身、侧身真的看得出在转。
- [ ] 刀的状态前后一致：在鞘里、出鞘、举起，不会凭空变化；刀长前后一致。
- [ ] 两只手都在身前，没有手绕到身后，没有多出来的手；每只手都能顺着手臂追到肩膀，全尺寸裁图看，法相等非人物的图也一样。
- [ ] 刀、刀鞘各只有一把，被身体挡住的两段在一条直线上。
- [ ] 和设定图一致：发型、外套、手套、腰带、绑带、靴底颜色、刀镡、刀鞘都对得上；刀柄没有流苏。
- [ ] 刀身长度等于头顶到胯的距离（全身图都要量），只有透视可以变短。
- [ ] 全片同一只手握刀：右手。
- [ ] 刀身、刀鞘笔直，只有一把；每只手都看得到前臂，没有留在刀鞘上的孤立手指；左手不在背后。
- [ ] 脚踝和小腿在一条线上，膝盖和脚尖同向。
- [ ] 哪只手握什么是对的：右手握刀，刀在左胯；拔刀前右手在刀柄上（护手靠刀柄尾的一侧），不在刀鞘上，刀柄不空着。
- [ ] 两只手是一左一右：同一根刀柄上一只看到手背、一只看到指尖；两只都看到手背就重画。
- [ ] 刀柄穿过拳心，不穿手腕、不压前臂；前臂和刀柄有明显夹角。刀身不穿身体。
- [ ] 朝向和身体对得上：朝右时离镜头近的是右半身；膝盖、手肘只往自然方向弯。
- [ ] 主角面向对手；每一刀说得出哪只脚踏进、胯往哪转。
- [ ] 刀挂在腰上的姿势是侧身：刀鞘、刀柄、拖影起点都在身前和近处的左胯，不横在后腰上。

**刀光**

- [ ] 拖影帧那两帧，画板刀光和图里画的拖影重合。
- [ ] 命中那一帧，刀光的头正好在屏上那张图的刀尖；火花、冲击波、集中线的中心在刀尖。

**斩痕和斩铁**

- [ ] 斩痕是直线。
- [ ] 每一刀刚命中、刀痕亮起时各截一帧：刀痕压在刚亮过的那段刀光上，方向一致。
- [ ] 斩痕不穿过月亮（60 档除外）；天空裂开后月亮完整地在一块里。
- [ ] 斩铁裂开的线就是出刀时的刀痕，每条都是全长，不裁、不另画。
- [ ] 斩铁那一拍和出刀那几拍并排截图：刀痕在月亮旁边的位置、交汇处的形状认得出是同一组线，交汇处不被黑边挡住。

**画面**

- [ ] 刀尖、命中点、昵称和它上面的标签都不进上下黑边；膝盖切边不露出来。
- [ ] 全程只有粉丝名。昵称完整：不被截断、不被画面破碎带走（刀痕、刀光从字后面经过可以）；中文、日文、英文、更长的混排昵称都试过。后加的特效也要再查一次。
- [ ] 冲击帧一次最多两帧，全屏闪光一秒内不超过 3 次。

**打击感和节奏**（依据见 DESIGN 第八节、调查记录第一到三节）

- [ ] 每一下重击前都有预备：蓄力姿势或举刀停几帧，光点往兵器收，兵器上一道闪光。
- [ ] 每次命中都有自己的顿帧，顿帧里只有震屏和冲击帧按实际时间走（单刀约 120 ms；40 档前两刀 70 ms、最后一刀 160 ms）。
- [ ] 最重的那一下有一帧白闪和两帧黑白冲击帧，剪影用这一刀的收招图，集中线的中心在刀尖。
- [ ] 镜头跟着刀走：蓄力慢推，出招猛推，顿帧后沿刀的方向震，再慢慢回落。
- [ ] 冲击波、放射模糊、色散只在顿帧之后出现，而且都很短（0.3–0.5 秒）。
- [ ] 有收势：残心、甩刀一闪、斩铁，动作不会突然停住。
- [ ] 节奏有落差（静、蓄、爆、停、余韵）：平时一张画停三帧，出招和命中那几下每帧都换。
- [ ] 比下一档强：出刀更多、落差更大；连斩间隔越来越短，最后一击前停得最久；高光段落里有出刀，没有只摆姿势的拍子。
- [ ] 不显得廉价：刀光有形状变化（变宽、变亮、碎成丝），边缘干净，结尾利落；画面上没有自己乱动的装饰；没有大块饱和色、卡通图形和圆润字体。
- [ ] 声音的点位在说明里标好（实现时配）：蓄力低鸣、拔刀、斩击、顿帧时一声重低音、甩刀、天空裂开、余音。

## 七、工具和坑

- `cdp-shot.mjs` 一次只截一张；几个 Chrome 同时跑会钉不住时钟。
- 批量生图用受跟踪的后台任务跑，`nohup` 加 `&` 脱离的进程会被清掉，看着启动了其实没跑。
- 跑批期间不改 `gen.sh` 和提示词文件：脚本和提示词都在每张图开始时读入，中途改会让同一批用不同版本，甚至跑错。
- 图像模型的安全审核可能拦下武器图（标成 violence）。不换说法绕审核，改用已确认的图做透视变换；变换后直线还是直线，刀也不会折。
- 改了 `tools/blobs.json` 要重启 `server.mjs`，它只在启动时读一次。
- 画布发布被拒、提示“没看过最新版本”时，用 Artifact 的 read（不带 path）读一次画布再发。
- 提示文件在页面上被改过时（打开画布，编辑器会自动规范化便签宽度等），读线上的 `canvas.json`，和自己的副本比对，只把自己改的键套到线上版本上再发，页面上的改动原样保留。
- 画板的特效画布四周要留边（EV2 是左右 300、上下 400），镜头一甩就会露出画布外的区域。
- 胯对齐的姿势图底边渐隐 120 px，镜头往下甩时看不到膝盖切边。
- 镜头只在缩放为 1 的那一刻换轴心，否则画面会跳。EV3 改成用世界坐标的镜头中心加缩放（cx, cy, z），任何时候都能换镜头位置。
- 截图时 `freeze` 是实际毫秒；画板里的时间轴是去掉顿帧的逻辑毫秒，顿帧之后的拍子要加上之前所有顿帧的长度（50 档落地之后加 430）。
- 天空图要补边时，左右可以镜像，上下不行（会镜出第二个月亮）：上下用边缘一条翻过来拉伸，顶上压暗色渐变。
- ShockwaveFilter 的波从中心起时会把中心扭成漩涡；第二道波的 time 从 0.25 起，跳过中心那一段。
- 图里不画拖影后，刀光的控制点就是刀尖的路径：取挥到一半和收招两张图的刀尖，中间补点。弧线太圆时让人物在这一刀向前踏步，把弧拉成斜线，比改控制点有效。
- 辉光阈值 0.6 会吃掉白外套的细节：阈值改 0.9，主角贴图 tint 0xe0e0e0，刀光是纯白仍然发光，衣服不发光。
- 刀痕要在画板里算离月亮的距离，别靠看：写一行 console.error 打印每条刀痕到月亮边缘的距离，cdp-shot 会打出来，确认都是正数再删。
- 色散在明亮的天空上，屏幕左右边缘会露出彩色细线；亮背景的那一拍改成上下错开，边缘藏在黑边后面。
- 拉远镜头前先算特效画布够不够宽：50 档结尾拉到 0.74，刀痕在屏幕右侧提前断掉，因为画布只铺到世界坐标 2380。
- 冲击帧的集中线贴图以击中点为中心，击中点靠近画面边缘时要放大到 4400 以上，否则另一侧铺不满。
