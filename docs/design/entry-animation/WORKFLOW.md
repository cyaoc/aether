# 进场动画 · 制作守则

每做一档、一个身份、一款隐藏款之前，从头读一遍本文；给用户看之前，逐项过一遍第六节的自查清单。画面怎么设计看 [DESIGN.md](DESIGN.md)，已有画板的参数看 [README.md](README.md)，生图提示词看 [prompts.md](prompts.md)。

本文由 2026-10-26 做一般人 40 档的会话复盘而来：那一档返工了 4 轮，每一轮都是用户先发现问题。目标是让下一档在交付前就把这些问题查出来。

## 一、用户在意什么

按反馈出现的顺序。每一条都是用户的原话，后面是落到画面上的规则（权威写法在 DESIGN 第二节）。

| 原话 | 当时的画面 | 规则 |
|---|---|---|
| “人物没动作、太幼稚、特效廉价、冲击力差” | 第一版：立绘滑进来，配色带、圆环、卡通闪电 | 主角要真的出招，特效由动作引起 |
| “特效过多、动作过少”“看不到出刀” | 总督只抬手剑自己飞；次元斩一闪就到终点 | 高潮是主角亲手打出来的那一下 |
| “动作和刀光对不上” | 40 档第一版：刀竖着举，刀光却横着甩出去 | 刀光沿拖影帧画出的拖影走，终点落在收招图的刀尖 |
| “人物动作也没逻辑” | 40 档第一版只有各刀的收招图，刀和身体在帧之间跳 | 动作链：每张姿势是上一张的结果、下一张的起点 |
| “这两处修正一下” | 我列出的两个弱点：回身是左右翻面、旧拔刀拖影和收招方向不一致 | 自己看出的弱点交付前就修掉 |
| “30 档也一起换” | 新规则只用在了 40 档 | 规则一改，已做的档一起改 |
| “切割为啥都是弧线、用力不均……刀斩痕迹不都是直线么” | 天空沿弧形刀光裂开 | 刀光是弧，斩痕是直线 |
| “40 挡斩痕和刀光方向对不上” | 斩痕取整条大弧的弦，离刀光很远 | 斩痕取命中时还亮着那段刀光的弦；弧度大的刀光让尾巴追上来 |

用户的反馈通常很短（“不行”“不对”）。收到后先截图、量数字找出根因，用一两句话说清哪里错、为什么错，再按规则改，并检查同一个问题在其他档有没有。

## 三、继续这样做

- 先用文字描述（招式、动作链、分镜、要生成的图），用户说“可以/确认”后才生图。描述用表格，用户看得快、改得准。
- 在姿势图上画网格，量出胯、头、手、刀柄、刀尖和拖影中线上的点。刀光、命中点、斩痕都由这些点算出来，不凭感觉画。
- 每拍按毫秒截图，拼成对照表自己先看。刀光像激光、刀光扫过月亮、昵称压线、多出来的亮边，这些都是这样在用户看到前改掉的。
- 生图结果先在灰底上看透明通道。codex 常回报“背景没有透明”，以实际 alpha 为准。
- 改了规则，同时写进 prompts.md、DESIGN 和记忆。
- 做完一档或改了规则，用第六节的清单把已定稿的档也过一遍。2026-10-26 就是这样查出 30 档残心前刀从举起处直接跳到垂下（用户没提过），补上了甩刀的细刀光。
- 另一档已经解决过的同类问题，直接照搬它的做法，各档才一致：30 档的切入（居合架势滑入）和残心甩刀都照搬 40 档。

## 四、这次返工的根因

1. **只生成收招图**：照 DESIGN 写的“40 档 3 个姿势”只做了冲刺、第二刀、第三刀三张收招图。中间的举刀、出刀都没有，刀光只能凭空画；回身靠左右翻面硬凑。→ 先排动作链，按链补齐预备和拖影帧，张数由链决定。
2. **沿用旧素材没核对**：30 档的拔刀拖影往右下甩，拔刀收招的刀却平举在右边，两张图本来就对不上，我直接拿来用。→ 复用的素材也要量点核对，对不上就在描述里先提出来。
3. **照抄 DESIGN 里的写法**：DESIGN 写“天空沿刀光的弧线裂开”，我没想过刀砍出来是不是弧线。→ 画面要符合刀的物理：直刃砍出直线，力道均匀。
4. **只看最后一帧**：斩痕改成直线后，我只看了三条线都悬着的画面，没在每一刀刚命中时核对刀痕和刀光。→ 每一刀命中后都单独截一帧对齐。
5. **流程上的浪费**：后台先生成的 50 档 5 张姿势没有动作链，只能作废；生图命令引用了还不存在的参考图，白跑一次；几个 Chrome 并行截图钉不住时钟，截错了帧；拖影帧在顿帧里停了约 5 帧，违反 DESIGN 的“只停两帧”，是我自己没对照 DESIGN 查。

## 五、步骤

### 1. 读

读 DESIGN、README、本文、prompts.md，再按第二节的索引读这一档用得上的设计依据。找到这一档在 DESIGN 招式表里的写法，列出这档要引入的新机制。

完成标准：能说出这档的招式、要复用的素材，以及复用素材里有没有对不上的地方。

### 2. 描述，等确认

回复里要有：

- **动作链表**：每张姿势一行，写身体姿态、刀在哪（从哪到哪）、新图还是复用。每一刀标出预备、拖影帧、收招。
- **每一刀的刀光和斩痕**：刀光从哪划到哪、命中时亮着哪一段、斩痕的方向。
- **镜头**：哪拍抬、哪拍往下甩、刀尖会不会出画（上下黑边各 118 px，姿势图在膝盖处切开）。
- **月亮和天空**：斩痕不能穿过月亮（60 档除外），月亮放在哪。
- **节奏**：按毫秒列每拍。
- **要生成的图**：清单和张数；复用素材里发现的不一致和改法。

完成标准：用户回“可以”或“确认”。用户确认前，下一档的图一张都不生成。

### 3. 生图

- 写成脚本跑：参考图先拷进生成目录，运行前检查每张都在。需要上一张结果当参考的，串行生成。
- 第一张参考是这个身份的亮相图（定人物），再加动作链里前后相邻的姿势（定动作）。
- 每一刀都要拖影帧和收招图，收招图的姿势和刀位要接上拖影帧的末端。对不上时，以拖影帧为参考生成“去掉拖影的同一姿势”（pose-14 就是这样来的）。
- 需要侧身、转身时提示词写死（“clearly NOT a back view”），脸写“covered by hair and deep shadow”。
- 处理：`process.py cutout` → 灰底合成检查 → 放进 `textures/` → 上传画布 → 写进 `tools/blobs.json` → 重启本地 server。

完成标准：链上每张图都在，灰底看过，把相邻的姿势并排看一遍，动作接得上。

### 4. 量点、算排版

- 每张图画网格，量胯、头、手、刀柄、刀尖；拖影帧在拖影中线上量 6–9 个点。
- 按胯对齐：每张图记胯在原图的位置和缩放，头到胯的长度在画面上约 440 px，前后差不超过 ±20%。
- 先算出三组数字：每张收招图的刀尖在画面上的位置（算上镜头，不能进黑边）；每条斩痕离月亮的距离（大于 50 px）；镜头上下甩时膝盖切边会不会露出来。

完成标准：三组数字都有，都在范围内；超出的先改镜头或排版。

### 5. 画板

从上一档的画板复制改，画在画布新的一行。刀光是量出的点连成的样条，终点是收招图的刀尖。命中时刀光的尾巴要追到只剩刀尖前近乎直的一段，斩痕取这段的弦，贯穿天空。天空按斩痕分块（每侧是线加一个大圆弧围成的多边形）。命中点、火花、冲击波、集中线都放在刀尖。

### 6. 自查

逐项过第六节，有一项不过就改，改完重新截图。

### 7. 交付

更新画布上的画板和旁边的说明便签。回复里给链接，说改了什么、请看哪几拍。自己知道的弱点先修掉，修不掉的才列出来，并给出改法。

### 8. 定稿后

更新 README、DESIGN、`preview/` 截图、prompts.md、blobs.json，提交推送到 `design/entry-animation`（PR #266），同步 #267（隐藏款同步 #268），更新记忆里的进度。

## 六、交付前自查清单

按实际毫秒逐拍截图，一次只截一张。

**动作**

- [ ] 相邻两张姿势之间，身体和刀的位置是连续的；头的大小变化不超过 ±20%。
- [ ] 每一刀都有预备、拖影帧、收招；拖影帧只停两帧。
- [ ] 转身、侧身真的看得出在转。
- [ ] 刀的状态前后一致：在鞘里、出鞘、举起，不会凭空变化。

**刀光**

- [ ] 拖影帧那两帧，画板刀光和图里画的拖影重合。
- [ ] 命中那一帧，刀光的头正好在屏上那张图的刀尖；火花、冲击波、集中线的中心在刀尖。

**斩痕和斩铁**

- [ ] 斩痕是直线。
- [ ] 每一刀刚命中、刀痕亮起时各截一帧：刀痕压在刚亮过的那段刀光上，方向一致。
- [ ] 斩痕不穿过月亮（60 档除外）；天空裂开后月亮完整地在一块里。

**画面**

- [ ] 刀尖、命中点、昵称和它上面的标签都不进上下黑边；膝盖切边不露出来。
- [ ] 昵称和标签不压亮线：刀光、甩刀的细刀光、刀痕都算（可以压已经变暗的细线）。后加的特效也要再查一次。
- [ ] 冲击帧一次最多两帧，全屏闪光一秒内不超过 3 次。

**打击感和节奏**（依据见 DESIGN 第八节、调查记录第一到三节）

- [ ] 每一下重击前都有预备：蓄力姿势或举刀停几帧，光点往兵器收，兵器上一道闪光。
- [ ] 每次命中都有自己的顿帧，顿帧里只有震屏和冲击帧按实际时间走（单刀约 120 ms；40 档前两刀 70 ms、最后一刀 160 ms）。
- [ ] 最重的那一下有一帧白闪和两帧黑白冲击帧，剪影用这一刀的收招图，集中线的中心在刀尖。
- [ ] 镜头跟着刀走：蓄力慢推，出招猛推，顿帧后沿刀的方向震，再慢慢回落。
- [ ] 冲击波、放射模糊、色散只在顿帧之后出现，而且都很短（0.3–0.5 秒）。
- [ ] 有收势：残心、甩刀一闪、斩铁，动作不会突然停住。
- [ ] 节奏有落差（静、蓄、爆、停、余韵）：平时一张画停三帧，出招和命中那几下每帧都换。
- [ ] 不显得廉价：刀光有形状变化（变宽、变亮、碎成丝），边缘干净，结尾利落；画面上没有自己乱动的装饰；没有大块饱和色、卡通图形和圆润字体。
- [ ] 声音的点位在说明里标好（实现时配）：蓄力低鸣、拔刀、斩击、顿帧时一声重低音、甩刀、天空裂开、余音。

**最后**

- [ ] 对照 DESIGN 第二节的原则和这一档的招式表各看一遍。

## 七、工具和坑

- `cdp-shot.mjs` 一次只截一张；几个 Chrome 同时跑会钉不住时钟。
- 改了 `tools/blobs.json` 要重启 `server.mjs`，它只在启动时读一次。
- 画布发布被拒、提示“没看过最新版本”时，用 Artifact 的 read（不带 path）读一次画布再发。
- 提示文件在页面上被改过时（打开画布，编辑器会自动规范化便签宽度等），读线上的 `canvas.json`，和自己的副本比对，只把自己改的键套到线上版本上再发，页面上的改动原样保留。
- 画板的特效画布四周要留边（EV2 是左右 300、上下 400），镜头一甩就会露出画布外的区域。
- 胯对齐的姿势图底边渐隐 120 px，镜头往下甩时看不到膝盖切边。
- 镜头只在缩放为 1 的那一刻换轴心，否则画面会跳。
