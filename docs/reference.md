# 行为参考

当前行为的详细说明，从 README 移出。使用方法见 [README](../README.md)，术语见 [GLOSSARY](../GLOSSARY.md)。

## 设置文件

顶层 `format_version` 是程序维护的格式版本，当前为 `1`，不是设置项，GUI 不显示。缺失时按版本 0 检查：0.2.x 的旧分组和大航海身份写法会自动升级，保留用户值、注释、未知键、编码和 BOM；没有旧分组的文件不加版本。缺少的新分组仍自动补写。升级失败时文件不动，日志和设置页显示原因，连接直播间前需修正，下次读取会重试。版本无效或高于当前程序时拒绝读取且不改写，请修正版本或使用更新程序。

CLI 和 GUI 共用 bot 设置文件 `data/aether.yml`（数据目录位置见下文“数据目录与数据库”）。首次运行时自动生成带中文注释的模板，默认值是生效的行：

```yaml
format_version: 1
log:
  retention_days: 30
  level: Information
blind_box:
  enabled: true
  daily_keyword: 今日盲盒
  monthly_keyword: 本月盲盒
  yearly_keyword: 今年盲盒
  announce: true
send:
  interval_seconds: 1
welcome_danmaku:
  enabled: false
  texts: ["欢迎{大航海}{昵称}"]
  uids: []
  fan_club_level: 0
  guard: 1
  wealth_level: 0
entry_animation:
  enabled: false
  fan_club_level: 30
  volume: 80
gift_animation:
  enabled: false
  tier_30_spend: 100
  tier_40_spend: 500
  tier_50_spend: 2000
  tier_60_spend: 10000
web_service:
  port: 17890
entry_animation_viewers:
auto_update:
  enabled: true
```

直播画面功能的分组（`entry_animation`、`entry_animation_viewers`、`gift_animation`、`web_service`）和 `auto_update` 只在 GUI 里生效；CLI 照常读和校验，写错了照样报错（[ADR 0003](adr/0003-one-bot-two-shells.md)、[ADR 0016](adr/0016-config-in-settings-file-and-database.md)）。`auto_update.enabled` 默认 `true`，打开 GUI 时检查并自动更新，在“通用设置”里和其他项一样点“保存”生效。

`log.retention_days` 是日志保留天数，必须为正整数，默认 30；`log.level` 是文件日志最低级别，
可选 Trace、Debug、Information、Warning、Error、Critical，默认 Information。日志设置在进程启动时读取，修改后重启生效。

缺少的项使用默认值；未知键会列在警告中，仍照常运行。设置格式遵循 [ADR 0004](adr/0004-settings-file-line-editing.md)：
英文 snake_case 键，分组下每个设置占一行。有效的多行标量仍可读取，但多行写法、嵌套结构和行内分组标为不能逐行编辑；
日志两项只接受整数或级别名，盲盒开关只接受布尔值，不接受嵌套对象。
已知分组和设置名不能重复，即使键使用了不同的 YAML 标签；错误会定位到重复项，保存时文件保持不变。

每次开始新的直播间连接前，Core 重新读取并校验设置。有错就返回文件路径、行号和设置名，不发起网络请求、不重试；
同一个直播间连接中的重连不重新读取。YAML 语法或整体结构错误标为 `YAML`，文件读写错误标为 `文件`（第 1 行）。
启动时文件有错，日志仍按默认值接入，并在日志中记下错误。CLI 的 `login` 和 `logout` 在 stderr 输出一行警告后照常运行，
`watch` 输出错误并以非零退出码结束；GUI 照常启动，点“连接”时显示拒绝原因。修好文件后可以再次连接。

## 盲盒统计

`blind_box.enabled` 只接受 `true` 或 `false`，默认 `true`，关闭后既不记录，也不回复和播报；下次观看直播间时生效，自动重连不重新读取。
启用时把 V1 `SEND_GIFT` 和 V2 `SEND_GIFT_V2` 的 gold 盲盒记入 `data/aether.db` 的收礼记录（和礼物榜共用，见“礼物榜”），不保存原始消息（要核对金额，把 `log.level` 设为 `Trace`；升级后，旧版本记下的原文会被删掉）；金额为整数金瓜子，
投入按 `total_coin`、开出价值按 `price × num`。相同 `tid` 只记录一次：内容也相同时视为重复推送，警告里带上被忽略的开出礼物、个数和投入；内容不同时警告 `tid` 可能不是按礼物项唯一，金额可从警告补回。数字形式的 `tid` 按其数字文本保存。以下情况都未实测确认，所以在默认日志级别下可见：uid 为 0 的盲盒（可能是神秘人）不记录，记一条 Information；带 `blind_gift` 但不是 gold 的礼物不记录并警告；`switch` 为 false 的盲盒照常记录并警告。
每条消息按 cmd 选择版本，V2 的每个 `gift_list` 项各记一行，兼容 `data.pb` 和 `data.data.pb`；损坏消息写 Warning 后跳过，继续接收后续消息。不累计 `COMBO_SEND` / `COMBO_END`。每条记录的观众、礼物和金额可在 Information 日志中查看。

启用盲盒统计时，观众发送整条关键字（默认“今日盲盒”“本月盲盒”或“今年盲盒”，忽略弹幕首尾空白），bot 会 @回复这位观众在本直播间、
收到关键字时的北京时间自然日、自然月或自然年内的投入与盈亏。本月范围从 1 日 0 点到下个月 1 日 0 点，今年范围从 1 月 1 日 0 点到次年 1 月 1 日 0 点，都不含结束时刻。
只统计连接期间记录的盲盒，日期按固定 UTC+8 和礼物送出时间计算。
今日回复为“今日投入X电池 赚Y电池”“今日投入X电池 亏Y电池”“今日投入X电池 不赚不亏”或“今日没有盲盒记录”，
本月、今年回复分别使用“本月”“今年”前缀，例如“本月投入X电池 赚Y电池”或“今年没有盲盒记录”。
1 电池 = 100 金瓜子，先四舍五入到一位小数，整数不带小数点；盈亏四舍五入后为 0 时写“不赚不亏”。账号自己发关键字也会触发；uid 为 0 时跳过并写 Debug 日志。
`blind_box.daily_keyword`、`blind_box.monthly_keyword` 和 `blind_box.yearly_keyword` 必须为非空的一行文字，不能通过留空单独关闭一种查询；要关闭查询，用 `blind_box.enabled` 全部关闭。
`send.interval_seconds` 必须为正整数，默认 1 秒。关键字和弹幕都先去掉首尾空白再比较；关键字相同时按今日、本月、今年的顺序只回复排在前面的一种。
这些设置均在下次观看直播间时生效。回复在发送时才查询金额，所以排队期间收到的同一天、同一个月或同一年的盲盒也会计入；查询范围仍由收到关键字的时间决定。

`blind_box.announce` 只接受 `true` 或 `false`，默认 `true`，下次观看直播间时生效。开启时，观众停手 3 秒没再送盲盒，
bot 主动 @播报这一轮的投入和盈亏，例如“本次投入300电池 亏50电池”。不同种类的盲盒合并计算，金额口径和取整与查询一致；
只计入新记录的盲盒，重复 `tid` 和 uid 为 0 的礼物不计入，账号自己送的也会播报。只关闭 `announce` 仍会记录和回复查询。
播报和查询共用发送队列，按进入队列的先后发送、遵守相同的发送间隔和失败规则；同一观众最多各有一条今日查询、本月查询、今年查询和播报在排队，互不合并。
播报在每次实际发送前计算金额，排队、等待重试或被重连打断后补发时都会计入新收到的盲盒；成功或最终放弃后，本次报出的金额结束，放弃的金额不进下一轮，发送请求进行中收到的新盲盒按自己的到达时间开始下一轮。
静默等待和排队都跨自动重连保留；主动断开或换直播间时一起清空，未满 3 秒的轮次也计入丢弃条数。
成功日志写“播报观众”，以便与“回复观众”区分；正文超长时按接口失败放弃，不截断。
播报只带观众的 `reply_mid`，不带 `replay_dmid`；网页端和 App 的 @显示已在真实直播间人工验收（[#65](https://github.com/cyaoc/aether/issues/65)）。

## 发送队列

发送队列不阻塞接收和心跳，自动重连时保留待发弹幕，连正在发送、被重连打断的那条也会在重连后重发；直播间连接结束时清空并记录丢弃条数，被打断的那条也计入，不算发送失败。弹幕的 uid 或回复用的 id 读不出时，弹幕照常显示：uid 读不出就不触发回复，id 读不出就不带 `replay_dmid` 回复。
同一观众最多同时排着一条今日查询、一条本月查询和一条今年查询；同一种查询在排队或发送时再次触发会合并，保留第一次触发的信息；查询回复成功后可立即再次触发，照常排队。
发送间隔从上一条发送结束时算起。相同正文（`msg`，不看 @ 的对象）还要距上次发送结束满 5 秒，两条规则取较晚的时刻；5 秒固定，不另设设置项。失败、被限流和被重连打断的尝试也计时，因为请求可能已经到了 B站。等待后重新计算正文，并按新正文再次检查；后面的不同正文不插队。
成功写 Information；遇到频率类失败（code 为 `10031`、`10030`，或 code 为 0 且 message 为 `msg in 1s`、`msg repeat`），写一条 Warning（带 B站 返回的 code、message 和重试等待秒数），这条保留在队首，等一个发送间隔后重试一次，重试也受相同正文规则约束。Warning 的秒数按正文不变计算，即发送间隔与 5 秒中较大的值。重试仍失败则写 Warning 并丢弃，再按两条规则继续后面的弹幕。发送间隔、相同正文计时和重试状态在自动重连后保留，直播间连接结束时清空；被重连打断的尝试不占用重试次数。其他接口拒绝（如 `1003212`）、code 为 0 时的其他非空 message（如 `f`）或网络失败直接写 Warning 并丢弃，不重试。

## 进场欢迎

`welcome_danmaku.enabled` 默认 `false`，开启后，观众进场时满足任意一个欢迎条件就发一条欢迎弹幕：UID 在 `uids` 中、本直播间粉丝团等级达到 `fan_club_level`、大航海身份达到 `guard` 档位，或荣耀等级达到 `wealth_level`。同时命中多个条件也只欢迎一次，日志按 UID > 粉丝团等级 > 大航海身份 > 荣耀等级记录第一个命中的条件。
`uids` 是正整数（int64）的单行列表，例如 `[12345, 67890]`，默认 `[]`，表示不按 UID 欢迎。`fan_club_level` 和 `wealth_level` 是非负整数，达到门槛（含门槛本身）就命中，默认 `0`，表示不按该等级欢迎。粉丝团只认进场时佩戴的本直播间主播的粉丝团，灯牌熄灭也算；戴着别的主播粉丝团的观众不按粉丝团等级欢迎。`guard` 可选 0（关闭）、1（舰长及以上）、2（提督及以上）、3（总督），默认 1。
处理 `INTERACT_WORD_V2`、`ENTRY_EFFECT`、`ENTRY_EFFECT_MUST_RECEIVE` 的进场通知，uid 为 0 时不欢迎。同一直播间连接中，同一位观众的非零 `trigger_time` 和上一次相同时只保留先到的通知，Debug 日志记录丢掉的消息类型；0 不合并，自动重连保留上一次记录，新直播间连接重新开始。合并后的进场同时交给进场欢迎和欢迎动画；不从在线榜推断进场。特效的身份取自 `uinfo`，粉丝团等级只认 `medal.ruid == target_id`（本直播间主播）的粉丝团。进场欢迎或欢迎动画开启时，每个直播间连接首次收到带版本的进场格式、或版本切换时记一条 Information；每种不认识的 cmd 各警告一次“进场消息格式可能变了”；两者都关闭时既不解码进场消息，也不记录或警告进场消息格式。
`welcome_danmaku.texts` 是单行欢迎语列表，例如 `["欢迎{大航海}{昵称}", "{@}欢迎回家"]`，默认 `["欢迎{大航海}{昵称}"]`，只有一条也写成列表。每次欢迎纯随机挑一条，可以和上次重复；每条都必填，列表不能为空，也不能只有 `{@}`。支持 `{@}`（只能放开头，发送时 @观众）、`{昵称}`、`{大航海}`；花括号本身用 `{{` 和 `}}`。每条加双引号，文字里的双引号和反斜杠分别写成 `\"` 和 `\\`。英文、数字、半角符号算 1，其他字符算 2（按 Unicode 码点计数）。上限自动读取账号的：开启进场欢迎时，每次连接直播间（包括重连）从 B站 读取，失败时按 20 处理并记一条警告。`{@}` 不占字数；昵称太长时从尾部按码点截短，不加省略号。昵称截到空后正文仍超过上限，或拼出来的正文为空时（例如只写 `{大航海}` 而观众不是大航海身份），不进入发送队列，记一条警告，“最近欢迎”显示原因，不换一条重试。旧的 `welcome_danmaku.text` 只记未知键警告，欢迎语使用 `texts` 的默认值；不迁移旧值。
已有 `welcome` 分组缺少 `texts` 时沿用 ADR 0004：读取时使用默认值，修改欢迎语并保存时才补写该项；缺整个分组时补写模板。
欢迎在进队时定好正文，和查询、播报按进队顺序发送，沿用发送间隔、同正文 5 秒等待和失败规则；不按观众合并。每次尝试（含重试）前，距进场到达已满 30 秒的欢迎会丢弃并记日志。跨重连保留，直播间连接结束时清空并计数。CLI 的 stderr 日志显示“进场欢迎”和“发送弹幕成功：欢迎观众”；这些设置在下次观看直播间时生效，可在设置文件或 GUI 侧栏的“进场欢迎”页修改。

## 动画

### 进场时播什么

`entry_animation.enabled` 默认 `false`，进场动画和欢迎动画共用这个开关。一次进场只取第一个：

1. UID 在动画名单 `entry_animation_viewers` 里：按这一行的值播。视频文件名播欢迎动画；30、40、50、60 播这一档，不看粉丝团等级；`0` 不播。
2. `entry_animation.fan_club_level` 大于 0，且本直播间粉丝团等级达到它：向下取整到 30、40、50、60，60 封顶。默认 30，0 表示不按等级。
3. 都不是：不播。

舰长、提督、总督这一版都播一般人动画。动画和欢迎弹幕各管各的，同一位观众可以两样都有。`entry_animation.volume` 默认 80，接受 0–100，进场动画、欢迎动画和送礼动画共用，取实际推送时的最新设置。GUI 里的音量都是拉杆，小喇叭加一根 180 宽的拉杆，不显示数字，拉到最左就是 0（不响）；键盘左右键每次调 1，翻页键每次调 10。
推流软件不支持 WebGL 时这一次回报失败，原因是“推流软件不支持 WebGL”；动画的脚本、贴图或声音加载失败、运行出错时也只有这一次失败，下一次重新加载，`<video>` 播放不受影响。

### 视频页和播放队列

网页服务独立使用 `web_service.port`，默认 `17890`，接受 1–65535。
旧键 `welcome_animation.port` 只记未知键警告，不迁移；旧视频目录也不迁移。缺少 `web_service` 整组时自动追加模板，已有分组中缺 `port` 时读取默认值、保存时补写。
`entry_animation_viewers` 的每行是 `UID: 值`；UID 是 int64 范围内的正整数，值是 0、30、40、50、60 或 `.mp4`、`.webm` 文件名，
文件名不能包含路径。文件放在 `data/videos/`；找不到时只警告，该观众不播放。空分组表示没有观众。
无效 UID 或文件名会报告所在行。Core 支持保留周围注释的添加、替换和整行删除。

网页服务提供视频页 `/video`、抽奖页 `/lottery` 和礼物榜页 `/gift-board`，各自在推流软件里添加浏览器素材，独立统计 SSE 连接数；`/` 返回 404。抽奖页显示报名抽奖和奖池抽奖，没有要显示的内容时透明。GUI 打开“常挂到直播画面”后，抽奖页在奖池抽奖待机、或报名抽奖结束并收起画面时，显示当前这一场没标不挂出的常挂结果；开关只在内存里，默认关，重开 GUI 回到关。
GUI 打开就启动网页服务，不需要登录或连接直播间，不跟功能开关启停。CLI 不启动网页服务、不打印视频页地址，开着进场动画或送礼动画也一样；`watch` 只做弹幕、盲盒统计、欢迎弹幕和发送队列。页面使用 SSE 自动重连，每 15 秒心跳一次。
视频页接收视频编号和音量，或动画编号、动画标识、昵称和音量，不接收 UID 或试播标记。视频仍按编号下载文件；回报接口是 `/video/report`。
动画名单里选了视频的观众进场就入队；bot 账号和主播不特殊处理，不受欢迎弹幕条件影响。
一次推一个视频，任意页面回报成功或失败后再推下一个；页面全部断开时不再等，最长等待 2 分钟，这两种都记为“没收到播放回报”。
从进场到轮到播放超过 30 秒就跳过（30 秒整仍可播放）。没有页面时立即跳过，不补播。
同一位观众的进场动画或欢迎动画还在排队或播放时，再次进场记“没播：上一个还没播完”，不再入队；上一个播完、失败、没播或没收到回报以后，再进场立即允许播放，不设时间间隔。
试播走同一个播放队列，不检查也不占用上述观众限制；播放中这一行显示“停止”，点击后视频页立即停止，最近播放记“已停止”，接着播队列里的下一个。真实进场播放中显示不可点击的“播放中”；CLI 不提供试播命令。开关保存为关闭后，还在用旧设置的直播间连接不再交给视频页，也不记跳过。

连接数和播放进展记 Information，播放失败和端口被占用记 Warning；端口被占用不影响直播间连接。
网页服务和状态订阅独立于直播间连接；切换动画开关、修改动画名单都不重启服务，页面保持连接。浏览器会先下载完整视频再播放，因此大视频会占用相应内存；
不转码、不抠图。使用步骤见 [README](../README.md#欢迎动画)，推流软件验证边界见 [研究记录](research/2026-10-15-welcome-animation.md)。

### 送礼动画

普通付费礼物按 `coin_type: gold` 的 `total_coin` 计投入，盲盒按盲盒投入计；免费礼物不计。
每个直播间的观众各自累计，停手 3 秒结束一轮，和一轮盲盒互不影响；自动重连保留，主动断开清空。
uid 为 0 只记录日志；目前不按 tid 去重。大航海开通、续费已接入：按实际付的价格计入一轮送礼的投入，和普通礼物在 3 秒内连着送算同一轮（算法见下一节“大航海开通和续费”）。
V2 已使用本地人气票消息验证；V1 使用 BAC 示例，未实测。批量、折扣、包裹仍缺真实样本，金额待实战 Trace 核对。
V1、V2 礼物消息还解出礼物 id、名称、单价、个数、观众头像地址、礼物图标地址和 `tid`（盲盒取它开出的礼物），供礼物榜使用：V1、V2 缺 `face` 或 `gift_info.img_basic` 都按空地址处理，这样的礼物照常进一轮送礼、盲盒统计和礼物榜，页面用昵称首字画头像。

送礼动画在一轮结束时读取最新开关和门槛，按实际投入取达到的最高一档，不要求粉丝团，也不受进场名单影响。同一观众的多轮送礼分别排队，30 秒排队时限从各轮结束时开始。GUI 可调整四档门槛、试播并查看最近播放；门槛不递增时不能保存。

三种动画试播都不看开关，要求视频页连着；欢迎动画还要求视频已保存。进场动画、送礼动画和欢迎动画共用先来先播的播放队列、30 秒排队时限和结果回报；音量取实际推送时的最新设置。

### 大航海开通和续费

观众开通、续费舰长、提督、总督时，`USER_TOAST_MSG_V2`（JSON）当作一份礼物进入一轮送礼，和普通礼物一样触发送礼动画和隐藏款。读取 `sender_uinfo.uid`、`sender_uinfo.base.name`、`sender_uinfo.base.face`（大航海消息常常不带，为空）、`guard_info.guard_level`（1 总督、2 提督、3 舰长）、`pay_info.num`、`pay_info.price`、`pay_info.unit`、`pay_info.payflow_id`、`gift_info.gift_id` 和 `option.source`。
B站 每次上舰先推一条 `source` 为 0 的、再推一条 2 的，只认 0；`GUARD_BUY` 的 `price` 永远是原价 198 元，不用。除头像外字段缺失都按损坏消息处理，写 Warning 后跳过，继续接收后续消息；`guard_level` 不是 1 到 3、`num` 不是正数、`price` 或 `uid` 为负也一样。uid 为 0 只记录日志，`price` 为 0 的和免费礼物一样不算投入。

`price` 是实际付的价格，已经包含优惠，不用另算折扣：公开抓包里的 138000、168000、198000 都对得上下面的现价，2021、2022 年抓包里的 158000 是 2024 年 7 月调价前的续费价。主播提供的 B站 现价（2026-11，单位电池，10 电池 = 1 元 = 1000 金瓜子）：

| | 1 个月 | 3 个月 | 6 个月 | 12 个月 | 续费 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 舰长 | 1980 | 5340 | 10380 | 20460 | 1680 |
| 提督 | 19980 | 51940 | 99880 | 195760 | 15990 |
| 总督 | 199980 | 519940 | 没提供 | 没提供 | 159990 |

舰长连续包月每月自动扣 1380。续费只能按月买。网上资料里的舰长 1580、提督 15980、总督 159980 电池是调价前的旧价。

`unit` 是“月”时 `num` 是月数，投入按下面算；三档单月原价（舰长 198000、提督 1998000、总督 19998000 金瓜子）是 `UserToastV2` 里的常量，B站 调整原价时要跟着改：

- `price` 不超过这一级的单月原价：`price` 是单价，投入 = `price × num`，个数是 `num`；
- `price` 超过这一级的单月原价：`price` 已经是总价，投入 = `price`，个数仍是 `num`；
- `unit` 不是“月”（例如“5天”）：按一次计，个数 1，投入 = `price`。

单价 = 投入 ÷ 个数（取整）。两种理解能从数值分出来：单月价和多个月折算的每月价都不超过单月原价，多个月的总价都超过它（最低的舰长 3 个月 534000）。推的如果是取整后的单价，乘回去和真实总价最多差几个金瓜子（提督 12 个月：1631333 × 12 = 19575996，真实总价 19576000）。`num` 大于 1 或 `unit` 不是“月”时，把原始的 `guard_level`、`num`、`price`、`unit` 记一条 Information 日志，上实战时核对。

未验证：
- 一次买多个月（`num` 大于 1）时 `price` 是单价还是总价：公开资料里没有抓包，blivechat 按 `price × num` 算，blivedm-go 按总价算，都没给出依据；上面的规则只是按数值区分的兼容办法；
- `unit` 不是“月”的情况：公开资料只说正常为“月”，其他内容以 `unit` 为准，没有抓包。

测试样本是按公开字段名和上面的价格表合成的，不是抓包，见[测试数据说明](../tests/Aether.Core.Tests/Fixtures/README.md#user_toast_msg_v2-合成样本)；字段来自 [blivedm](https://github.com/xfgryujk/blivedm/blob/master/blivedm/models/web.py)、[blivechat](https://github.com/xfgryujk/blivechat/blob/master/frontend/src/api/chat/ChatClientDirectWeb.js)、[sjh8130/bili_danmaku](https://github.com/sjh8130/bili_danmaku/blob/HEAD/Testing.md) 和 [BAC 的 USER_TOAST_MSG](https://github.com/pskdje/bilibili-API-collect/blob/master/docs/live/message_stream.md)，2024 年 7 月的调价见 [IT之家](https://www.ithome.com/0/780/661.htm)。

## 礼物榜

礼物榜是网页服务的 `/gift-board` 页面，只在 GUI 里用，像抽奖一样按期运行（[ADR 0014](adr/0014-gift-board-runs-in-periods-like-a-lottery.md)，见下面的“期”），设置文件里没有它的开关和选项。每一期有自己的选项：上榜门槛（电池，正整数，默认 100）；门槛比什么，`1` 比礼物单价，`2` 比同一观众同一礼物累计的总价，默认 1；是否显示看板娘，默认显示；新的第一名那一声的音量，0–100 的整数，默认 60，0 表示不响。CLI 的 `watch` 不挂礼物榜：不记、不开网页服务、不打印礼物榜页地址。

bot 连着直播间时，V1 `SEND_GIFT`、V2 `SEND_GIFT_V2` 的付费礼物（盲盒按开出的礼物算）和 `USER_TOAST_MSG_V2` 的大航海开通、续费，每一份只在 `data/aether.db` 的收礼记录里写一行，盲盒统计和礼物榜都读这一份（[ADR 0013](adr/0013-one-gift-record-flagged-by-feature.md)）。每行存直播间、观众、昵称、头像地址、礼物 id、礼物名、礼物图标地址、大航海等级、礼物键、个数、投入、价值（金瓜子：开出礼物的单价 × 个数，大航海是这一单的投入）、盲盒那一份（盲盒 id、名称、单价，不是盲盒时为空）、`tid`（大航海是 `payflow_id`）、B站 的送出时间（大航海没有，为空），以及两样标记：收到时盲盒统计要不要，和礼物榜把它算进了哪一期（没算进就为空）。盲盒统计只要盲盒，而且只在这次直播间连接开始时开着才要（它的设置下次连接才生效）；礼物榜要每一份，只在收到时这个直播间有一期正在统计才要，而且只有 GUI 的直播间连接挂着礼物榜。两个都不要就不写：盲盒统计关着、礼物榜没在统计时收到的都不算，开关拨过几次都一样。礼物键是 `gift:<礼物 id>` 或 `guard:<1|2|3>`：盲盒开出的礼物和直接送的同一种礼物合并，大航海按等级一行。
`tid` 在收礼记录里唯一：同一份礼物推两遍只写一行，跨自动重连、重新连接和重启都算，内容相同时记一条 Warning“重复推送的礼物，已忽略”，带上 `tid`、礼物、个数和投入；内容不同时警告 `tid` 可能不是按礼物项唯一，金额可从警告补回；`tid` 为空的不去重。V1 和 V2 同一次送礼多半是同一个号，按重复处理（未实测）。uid 为 0 的礼物（可能是神秘人，未实测）不写，记一条 Information。礼物榜先把礼物加进内存、推给礼物榜页，再写收礼记录，所以画面不等数据库，也不受它影响。写入失败（例如磁盘满、文件只读）时，只有礼物榜要的那份记一条 Error“礼物榜写数据库失败”，礼物照常在榜上，但没存下来，重新连接或重启后就不算了；同一份礼物再推一次，榜上不重复加，数据库恢复了就把它补写进它当初算进的那一期，中间开始了新一期也一样。直播间连接和其他功能照常；连上直播间时读不出礼物榜，记一条 Error“礼物榜读数据库失败”，弹幕照常，礼物榜重连时再读；盲盒统计要的盲盒写不进去时，照旧结束直播间连接，不悄悄丢掉。只有 Aether 连着直播间时收到的礼物才会记下，B站 不补发历史。

礼物榜一行是一位观众的一种礼物：价值和个数把这一期里这位观众这个礼物键的记录各自整数相加，单价是价值除以个数、不另存，所以大航海续费价和开通价不同时，价值仍是实际付的钱，不丢零头；昵称、头像、礼物名、图标以最后一份为准。连上直播间时，按收礼记录把最新这一期相加一次放在内存里，之后每来一份礼物只在内存里加上，不再每次查库，开始、结束、继续一期也不重新读；内存里也记着这个直播间收礼记录里的全部 `tid`（各带着它算进的那一期）和这次连接收到过的，同一份礼物推两遍在榜上只算一次，不管写没写进数据库，也不管第一份是算进了旧的一期、收到时没在统计，还是只给盲盒统计记下的：数据库对它们都只写一行，榜上也就不再算；内存里是这一期的全部行，没到门槛的也在，所以累计到门槛的一行当场就会上榜。

显示时才按这一期的选项筛选，所以改门槛立即生效：比单价时，单价 ≥ 门槛就上榜；比累计总价时，价值 ≥ 门槛就上榜，刚好等于也上榜；1 电池 = 100 金瓜子。上榜的行按价值从高到低排，一样时第一次收到的在前。

`AetherClient.GiftBoard.GetUpdatesAsync` 先给当前状态，之后每次变化给一份完整状态，GUI 和礼物榜页用同一份：按顺序的上榜行（标识、观众 uid、昵称、头像地址、礼物名、礼物图标地址、大航海等级、价值、个数）；`phase`，最新一期的阶段（0 还没开始、1 统计中、2 已结束）；`running`，最新一期正在统计时为真，礼物榜页只在这时显示；这一期的选项 `options`（`threshold`、`thresholdBy`、`mascot`、`volume`），礼物榜页从中读 `mascot` 和 `volume`；`connected`，有没有直播间连接；`period`，最新一期的开始时间 `startedAt` 和结束时间 `endedAt`（统计中为空），这个直播间还没有期或没有直播间连接时整个为空；`fromGift`，只有收到礼物造成的那一份为真，礼物榜页只在这时把变化播成动画，改选项、开始、结束、继续一期、连上或断开直播间，以及订阅者收到的第一份都为假。已结束的一期照样带着它的行，给 GUI 右栏。没有直播间连接（从没连过，或者点了“断开”）时是空列表；断线后自动重连还算同一个直播间连接，重连中状态不变；换到别的直播间时给那个直播间最新的一期。网页服务的 `gift-board` 页面把它当作 SSE 事件 `state` 推到 `/gift-board/events`，同样先推当前状态，再每次变化推一份；网页服务状态和连接日志里带上礼物榜页的推流软件连接数。

### 期

礼物榜按期记，和抽奖一样由主播开始和结束：一期就是一张榜，礼物榜页和 GUI 只显示这个直播间最新的一期。`gift_board_period` 每行存直播间、开始和结束的时间（Aether 的时间）和这一期的选项；一期就是礼物榜算进这一期的那些收礼记录。礼物在加进内存的那一刻就定了属于哪一期，写库晚一点、中间刚好换了期也分得清。一个直播间最多一期在统计。

最新一期有三种状态：还没开始（这个直播间从没开过期）、统计中、已结束。只有统计中的一期记礼物、在礼物榜页上显示；还没开始和已结束时礼物榜页透明，不画也不响，已结束的一期在 GUI 右栏照样显示。礼物榜不会自己开始或换新的一期，跨过零点、下播再开播都不改变状态（[#296](https://github.com/cyaoc/aether/issues/296)：按开播自动换要依赖 B站 断流后开播时间变不变，这一点没有验证，误换了还会把一场直播的榜在画面上拆成两张，所以不做）。主播点“断开”（换直播间也要先点它）、关掉 Aether 或退出登录时，统计中的一期跟着结束，结束时间就是这一刻，再连上要点“继续这一期”或“开始新一期”；设置页的“重新连接”、断线后的自动重连、连接出错都不改变状态（[#309](https://github.com/cyaoc/aether/issues/309)）。先把这个直播间还在排队的操作（改选项、刚点的开始新一期）做完，再按那时的状态决定结不结束；结束时写失败只记一条 Error“断开时结束礼物榜这一期失败”，照常断开，这一期留在统计中。一直不开新的一期，每场连上后点“继续这一期”，就是多场榜、活动榜或总榜。

`AetherClient.GiftBoard.StartNewPeriod(room)` 开始新一期：在当前直播间加一期，之后的礼物从零算起，选项沿用上一期的（第一期用默认值，或者开始前改过的）；统计中时抛 `InvalidOperationException`，要先结束。`EndPeriod(room)` 结束这一期：记下结束时间，不再记礼物，礼物榜页收起；没有统计中的一期时抛。`EndPeriodOnLeaving(room)` 是主播点断开、关掉 Aether、退出登录时用的：这一期在统计就同样结束，不在统计就什么都不做、不写数据库。`ContinuePeriod(room)` 继续这一期：清掉结束时间，接着记、重新显示，结束期间收到的礼物不算；最新一期不是已结束时抛。`SetOptions(room, options)` 改选项：立即作用于礼物榜页和 GUI 右栏，有期就写进最新一期；还没有期时只留在内存里，开始第一期时带上，断开再连或重启前没开始就回到默认值；门槛不是正整数、比法不是 1 或 2、音量不在 0–100 时抛 `ArgumentException`。这几个操作都带上要动的直播间，它不是连着的那个（没连直播间，或者中间换了直播间）时抛 `InvalidOperationException`、什么都不动，所以 GUI 里排着队的操作不会落到换过去的直播间上；只动这个直播间的期，不删任何收礼记录，也不影响盲盒统计，做完推一份新状态。查看历史的期不在范围内。

### 礼物榜页

礼物榜页只有榜本身那么大，推荐浏览器素材 480 × 1000，不铺满直播画面，也不猜自己放在画面的哪里，只按自己的宽高排版：宽度决定缩放，以 480 为设计宽度等比缩放；高度决定行数，前三名固定，剩下的高度能放几行胶囊就放几行，放不下的从第 4 名起循环滚动；看板娘默认显示，占飘带上方 220 的设计高度，关掉后腾出的高度全部用来放行（480 × 1000 从前三名加 6 行变成加 9 行）；页面比设计高度（显示看板娘 820，关掉 608）矮时改按高度缩小、水平居中。所有光效都画在榜的范围里，背景透明。页面用 PixiJS（沿用视频页的 `/video/lib/pixi.js`）画，字体（思源黑体 500、800，Playfair Display Italic 800 的数字）、看板娘和飘带贴图都打包在软件里，授权文件随软件放在 `Fonts/`。头像、礼物图标、大航海头像框和徽章直接用 B站 图床地址（`referrerPolicy` 设为 `no-referrer`、`crossOrigin` 设为 `anonymous`），加载失败的不画，没有头像时用昵称首字画一个；除 B站 图片外页面不访问外网。榜是空的时页面仍显示飘带和看板娘。
页面对比前后两份状态来决定播什么，但只对比 `fromGift` 为真的状态（收到礼物造成的那一份）：多出一行是新上榜，这一行排第一就按新的第一名播，欢呼也响一声，空榜上的第一位也一样（这一行用新上榜的时间轴出现，欢呼那一层用新的第一名的，从同一个事件起点算起，没有旧位置所以没有换位那一段）；名次没变、个数增加是个数增加；升到第一名是新的第一名，其他名次上升是超车；删行、一次变了好几行、开关看板娘、改门槛或比法（上榜的行没变也算），以及不是收到礼物造成的状态（开始、结束、继续一期），即使只变了一行，都直接重画不播动画；只改音量不重画。整榜重画时页面放掉旧榜的昵称、个数贴图，以及新榜不再显示的头像、礼物图标和大航海头像框、徽章；放掉时还没加载完的图片，加载完也不留。每画一份新榜，也放掉上一份用过、这一份不用的昵称和个数贴图，同一期一直累计也不会越攒越多。页面刚连上 SSE（包括自动重连）收到的第一份状态直接画出整张榜，不播动画也不响。收到礼物造成的变化按到达顺序一个一个播，等着的变化超过 3 个就跳到最新状态，中间的不播；不是收到礼物造成的整榜重画（开始、结束、继续一期，改门槛、开关看板娘、断开直播间、SSE 重连后的第一份）立即打断正在播的动画和它的声音（事件播完后还在响的尾音也停），丢掉还在等的变化，马上画出新榜。播事件动画时滚动先停住。只有新的第一名响一声（设计包的 Sparkle，Freesound，CC0），最响的点对准事件开始后 950 ms，关掉看板娘也照样响；音量取最近一份状态里的 `volume`，保存后立即作用于正在响的那一声（包括事件播完后还在响的尾音，下一个新的第一名开始时它停掉）和还在等的事件，0 时不加载也不播；第一份状态和积压时跳过的事件不补响。声音还没加载完时事件照常开始，在响声的时刻之前加载完就照样响，之后才加载完的这一次不响；加载失败的，下一份状态再试。页面的动画时钟是一个 Web Animations 动画，测试可以把它停在任意时刻再单步。

## GUI

GUI 使用 Fluent 主题并跟随系统深色／浅色，默认 1200×720，最小 1040×600。左侧栏放直播间卡片、功能导航和账号。
每次打开窗口先显示插画启动页，至少停留 0.6 秒，账号读取有结果后淡出 150 ms；启动页显示期间不能操作底下的页面。
读到有效账号时直接显示主界面和昵称；没有登录凭据或 B站明确说未登录时直接显示扫码登录页，扫码后才进主界面，二维码过期自动换码，出错时显示原因和“重试”。
账号请求或数据库读取失败、或 3 秒内没有结果时，进入主界面并显示“账号信息读取失败”，可重试、连接直播间、配置和试播；不会因为断网要求重新扫码，超时后的迟到结果不会切换页面。重试读到未登录时切到登录页。
网页服务与账号读取并行启动，在启动页和登录页上也运行，直播姬仍可打开视频页和抽奖页。
版本号（如 `v0.3.0`）固定在窗口底部角落：主界面在左下角、侧栏账号下方，每一页都能看到；登录页在右下角。版本号来自 GUI 程序集的版本，发布时由 `release.yml` 用 tag 写入，本地构建显示 `v0.0.0-dev`。
输入房间号后点“连接”或回车；连接中途登录凭据失效时，内容区显示扫码卡片，
功能导航变灰、不能点；扫码成功后继续连接，扫码结束后导航恢复，停在原来的页。点“断开”可取消扫码或结束连接，再输入新的
房间号；礼物榜有一期在统计时，点“断开”、退出登录、关闭窗口都先结束这一期（见“礼物榜”的“期”）。卡片显示从首次连上开始的分钟数，自动重连不会清零。账号的 ⋯ 菜单里点“退出登录…”并确认后，
先结束当前连接或扫码，再删除凭据，然后回到扫码登录页；关闭窗口也会先取消并等待当前操作结束。
房间号输入框会预填上次连接成功的号码，也可以直接输入新号码。下拉列表按最近连接成功的顺序保留最多 5 个号码，去重后保存到数据库的 `gui_state`；保留输入原文，短号不会换成真实房间号。打开窗口时在后台读，读到之前输入框和下拉是空的。连接失败或连上前取消不记录，断开和退出登录不清空历史。
选中历史项只填入号码，不会连接；列表展开时上下键选择，回车收起，收起后再按回车才连接。启动不会自动连接，没有历史时输入框为空。历史保存失败会显示错误，不影响已经建立的连接。
点每行右侧的 ×，或在列表展开时按 Shift+Delete，可以删除该历史项并保存，框里的文字保持不变。删掉最后一项会收起列表；没有历史时不显示下拉箭头。展开或收起后光标在文字末尾，用 Tab 进入时仍全选文字。
房间号、日志级别和大航海身份使用相同的下拉卡片与选中样式；“添加条件”菜单使用相同的卡片外框、阴影和内边距。
窗口显示错误提示，日志写到文件和调试控制台。列表开启虚拟化，在底部时跟随新弹幕；往上翻看历史时暂停，
滚回底部后恢复。每条弹幕分两行：第一行是昵称、徽章和时间，徽章依次是“账号”、大航海身份、粉丝团等级、荣耀等级，没有的不显示；
第二行是正文，弹幕 @ 了别人时正文前显示 `@昵称`。已知账号 UID 对应的弹幕用强调底色和实心“账号”标签标记，
即使账号有大航海身份也一样；舰长、提督、总督发的弹幕各用一种淡底色。
默认勾选“只保留最近 1000 条”，超出时丢弃最旧的弹幕；取消勾选后保留全部，
重新勾选立即裁剪到最新 1000 条。已丢弃的弹幕不会恢复。
该设置一改就写入数据库的 `gui_state`，重启后恢复；读不出来时最近的房间号和这一项都用默认值，并记日志。
旧版本把最近的房间号、这一项和自动更新开关存在 `data/gui.yml`。GUI 启动时、检查更新之前，有这个文件就搬走：自动更新开关写进设置文件的 `auto_update.enabled`（设置文件里已经有这一项时照样覆盖），最近的房间号和这一项写进 `gui_state`，上次抽奖的房间不搬；先写设置文件，成功了才写数据库，两边都写成功后删掉文件；任何一边失败就留着、记日志，下次启动再试，设置文件写不进时数据库不动，免得每次启动都拿旧值盖掉之后记下的。文件里某一项留空或写错时这一项按默认值，自动更新默认开；整个文件读不出来（例如没有读权限）时也留着，这次按设置文件。文件还在时自动更新按它的值；搬完以后设置文件有错、值不能用时按默认值开。CLI 不碰 `gui.yml`，之后也没有东西再写它（[ADR 0016](adr/0016-config-in-settings-file-and-database.md)）。
macOS / Windows / Ubuntu CI 的 `dotnet build` 都会构建 GUI，`dotnet test` 运行 Core、CLI 和 GUI 无头测试；GUI 不支持 Linux 桌面运行。
`tests/Aether.Gui.Tests` 用 Avalonia.Headless 覆盖登录页、账号读取／重试／标记、退出确认、重连计时、设置页读写、发送队列动态、保留条数和跟随最新弹幕；真实窗口的观感按 [#15](https://github.com/cyaoc/aether/issues/15)（Windows）和 [#121](https://github.com/cyaoc/aether/issues/121)（macOS）手动验收。

GUI 侧栏的设置页有“盲盒统计”“进场欢迎”“送礼动画”“发送队列”“通用设置”；“礼物榜”在“送礼动画”下面，“抽奖”在“礼物榜”下面，两者都直接管理、不用保存，抽奖管报名抽奖和奖池抽奖。奖品和奖项可以存成奖品方案，只按抽奖方式分开，所有直播间看到同一份，没连直播间时也能列出，能改奖品时载入或存为；抽奖历史连着直播间时是这个直播间的，没连时是数据库里最近一场抽奖所在的直播间，一场都没有就是空的；开奖记录和中奖名单的每条结果可以点眼睛标成不挂出，只影响直播画面，记录和历史不变。导航的“开 / 关”显示设置文件里已保存的开关；礼物榜有一期在统计时写绿色的“统计中”。奖池抽奖的喊停观众 UID 可以从在线榜选，没连直播间时不能用。
每页只保存本页改过的值到 `aether.yml`，未修改时“保存”不可用，切换页面保留未保存的修改。
进场欢迎点“＋ 添加条件”选择指定观众、粉丝团等级、大航海身份或荣耀等级；指定观众是一组 UID，一行一个，整组算一条条件，菜单可继续往同组添加。指定观众的 UID 可以从在线榜选，没连直播间时不能用。其余每类只能一条，点 × 删除对应行，UID 删光后指定观众条件消失。满足任意一条就欢迎，没有条件时不会欢迎任何人。输入有误时在对应行提示，修正后才能保存；新加的指定观众行在 UID 框第一次失去焦点之前不提示，之后边改边查。欢迎语可添加多条，每次随机发一条；每行可删除，只剩一行时不能删。插入按钮把 `{@}`、`{昵称}`、`{大航海}` 放到正在或最后编辑的那一行，两条以上时提示“到第 N 条”；每行错误在本行下面提示，新加的欢迎语行在输入框第一次失去焦点之前不提示，点插入按钮不算离开。离开过的行和打开页面时已有的行边改边查；空行或有错时始终不能保存。列表逐项、按顺序和已保存值相同就不算修改。多行写法可读取，但所有欢迎语只读，需去设置文件里修改。
欢迎语和指定观众的 UID 超过 3 条时，默认只显示前 3 条；点“还有 N 条 / 位”展开，点“收起，只看前 3 条 / 位”收起。隐藏行有错时，展开按钮用错误颜色显示其中有几条 / 位有错。新增行会自动展开列表、滚动到新行并聚焦输入框；向隐藏的欢迎语插入占位符也会展开并定位到该行。整个页面一起滚动，欢迎条件整体和欢迎动画的观众列表不折叠。
通用设置顶部的网页服务区块显示服务状态、端口，以及视频页、抽奖页和礼物榜页各自的连接状态、地址和素材宽高。宽高写在页面列表每一行的地址框右边、“复制”左边，各行对齐成一栏：视频页“1920 × 1080”（动画画布固定横屏，只推荐横屏），抽奖页“横屏 1920 × 1080 · 竖屏 1080 × 1920”，礼物榜页“480 × 1000，可以等比放大”；“页面”旁写“宽高照每行写的填”，GUI 里别处不再写尺寸。服务运行中但某页没有连接时，在该页下面提示添加浏览器素材，地址和宽高照这一行填，已经加过的右键素材 → 刷新。地址旁的“复制”点后 2 秒内显示“已复制”。端口被占用时提示端口号和处理办法，其他功能照常使用。改了端口还没保存时，底部提醒直播姬里的地址要跟着改。
进场欢迎的动画分页和送礼动画页顶部只显示视频页连接状态，礼物榜页顶部只显示礼物榜页连接状态，点“地址和宽高在通用设置”跳到通用设置。
“礼物榜”页像抽奖一样，没有开关，也没有保存（画布 GS1–GS13）。标题右边是状态标记，不只靠颜色：绿底实心圆点“统计中”、灰底空心方块“已结束”、灰底空心圆“还没开始”，没连直播间时不显示。最右边按状态只放能用的按钮：还没开始时“开始新一期”，点了直接开始；统计中时“结束这一期”，底部栏先问“结束后不再记录，画面上的榜也会收起，确定吗？”，红底“结束”确定；已结束时“继续这一期”（直接继续）和“开始新一期”，后者先问“开始新一期后，画面上的榜从零算起，确定吗？”；没连直播间时“开始新一期”不可用，左边写“连上直播间后才能开始统计”。问的事做不成了（例如断开了直播间），确认自动收起。动作都在后台写数据库，不卡窗口；做完底部栏写“已为直播间 <房间号> 开始新的一期”“已结束这一期，直播画面上的榜已收起”或“已继续这一期，画面上重新显示榜”，失败时写“开始新一期失败：原因”这样的提示（例如数据库写不进去，或者刚好断开了直播间），连上或断开直播间时清掉。中间一栏依次是礼物榜页状态条、上榜门槛（正整数，单位电池，不是正整数时就地提示、不生效）、两个比较方式（按礼物单价、按累计总价）、“看板娘”开关，以及“新的第一名时响一声”的音量拉杆；这些是这一期的选项，改了立即生效（后台写进最新一期），开始新一期时沿用，底部栏平时写“选项改了立即生效，开始新一期时沿用”；没连直播间时变灰，底部栏写“选项跟着直播间的期，连上直播间后才能改”。右栏“当前榜单”只读，和礼物榜页用同一份状态、同一个顺序，每行是名次、昵称、礼物 × 个数和这一行的价值（电池）；右上角“共 N 位”数的是榜上的观众，同一位观众送了两种上榜的礼物也只算一位；标题下面一行，统计中写“本期从 月日 时:分 开始”，已结束写“本期 月日 时:分 – 时:分，已结束”（跨天时结束也写月日），没连直播间、还没开始时不显示。结束以后直播画面上的榜收起，右栏照样留着这一期的结果。没有内容时按情况提示：没连直播间、还没开始（提示点“开始新一期”）、还没有人上榜、这一期没有人上榜。自动重连中保持不变。
进场欢迎分为弹幕和动画两个分页，分别保留开关、草稿和最近记录。动画保存后下一次进场生效，弹幕仍下次连接生效。
“添加观众”填写 UID 并选择进场档、欢迎动画或不播；只有欢迎动画需要选择视频。观众 UID 可以从在线榜选，没连直播间时不能用。点文件名换视频，× 删除。保存时把新选的视频复制进 `data/videos/`，
文件夹里已有同名文件时加 ` (2)` 等后缀；复制失败不写映射，已复制的文件撤回；不再被任何观众使用的旧副本删除，选中的原文件始终不动。
保存开关和映射后立即应用，不断开页面；只有保存新端口才重启网页服务。在设置文件里改端口，切换页面时也按新端口重启。改端口后所有浏览器素材的地址都要更新。视频已保存、有推流软件连着视频页、文件存在、没有别的在播时才能“试播”，不看开关。
行下提示 UID 没填、不合法或重复，视频文件找不到，上次播放失败（换了视频才消失，只在本次运行内记住），或保存后才能试播。新加的观众行在 UID 框第一次失去焦点之前不提示 UID 错误（空着或填错都不提示），视频文件存在时显示灰色“保存后才能试播”；UID 有错时保存和试播仍不可用。离开过的行和打开页面时已有的行边改边查。
直播间设置在下次连接时生效；动画开关（包括连接中打开）、名单、音量和送礼门槛及网页服务端口在保存后立即应用，通用设置里的日志保留天数和级别在重启后生效。
连接中保存盲盒统计、欢迎弹幕或发送队列时会提示当前连接仍在用旧设置，点“重新连接”会等旧连接结束，再连接同一直播间，保留弹幕列表。
保存前重新读取文件；手动添加的注释、行尾注释、未知键和空行会原样保留。缺少的设置追加到分组末尾，
缺少的分组追加到文档末尾。输入不合法时在该项下显示 Core 的提示并禁用保存；文件有错时各页顶部显示路径和行号。
多行等不能逐行编辑的项显示为只读，可在“通用设置”点“打开设置文件”用系统默认程序手改；修好文件后切换页面重新检查。
文件不是 UTF-8（或带 BOM 的 UTF-16/32）编码时仍能读取，但所有项都只读，另存为 UTF-8 后即可在 GUI 里修改。
“只保留最近 1000 条”仍在主窗口，一点就存进数据库，不走保存栏。

进场欢迎页的“最近欢迎”显示观众、命中的条件、正文和发送结果；盲盒统计页的“最近回复和播报”标出今日、本月或今年查询，在开始发送后显示计算出的正文；
动画分页的“最近播放”显示观众、档位或视频、触发原因和进展（排队中 · 第几个、播放中、已播放、播放失败、没收到播放回报、没播及原因），试播标“试播”。
发送队列页按发送顺序列出“待发”，并显示“最近发送”；侧栏的待发数包含正在发送和等待重试的项。
点“连接”清空这些动态，“重新连接”保留；连接结束时未完成的项标为“连接结束，没发出”。每页保留最近 100 条已结束的项，未结束的全部保留。

GUI 使用蓝白气泡图标：Windows 的窗口、任务栏和发布后的 EXE 使用同一图标；
macOS 在程序运行期间设置 Dock 图标，开发启动和 Release 发布均生效。
图标嵌入程序，不依赖启动时的工作目录。macOS 尚不提供 `.app`、Finder 静态图标
或退出后固定在 Dock 的图标；数据目录仍遵循 ADR 0002。
矢量母版与导出方法见 [应用图标素材](design/app-icon/README.md)。

## 日志

CLI 和 GUI 的文件日志位于 `data/logs/`，默认记录 Information 及以上级别，由 `log.level` 控制。
公共日志写到 `aether-yyyyMMdd.log`，允许多个进程共享写入；解析到真实房间号后，
包括扫码和重连在内的 Core 日志写到 `<真实房间号>/aether-yyyyMMdd.log`。
直播间连接因错误结束时，该直播间的日志记下错误；CLI 或 GUI 另在公共日志记一条，房间号确定前的失败只记在公共日志。
文件按本地日期每天滚动，默认保留 30 天，由 `log.retention_days` 控制：启动时清理所有目录的过期文件，打开或滚动某组日志时再清理该组；
空直播间目录保留，避免与其他进程创建日志文件发生竞态而丢失日志。
每条写完即关闭文件，切换直播间不会积累句柄，其他进程可在断开后接管同一直播间。
每条包含时间、级别、进程号、类别和消息，异常附完整堆栈。日志同步写入，不在内存中缓冲。
进程未处理异常、未观察到的 Task 异常和 GUI UI 线程未处理异常立即记录，不标记为已处理，
仍遵循运行时原本的退出行为（未观察到的 Task 异常默认不终止 .NET 进程）。
跳过无法解析的直播间消息时，警告附原始 JSON；超过 2KB 按 UTF-8 字节截断并注明。
`log.level` 设为 `Trace` 时，每条直播间消息另记一条完整的原始 JSON，不截断，含观众的 uid、昵称等个人信息，
只在抓包时临时开启，步骤见 [测试数据说明](../tests/Aether.Core.Tests/Fixtures/README.md)。
弹幕、礼物、进场三类消息使用同一套格式日志规则：每个直播间连接首次收到带版本的格式、或版本切换时记一条 Information；
收到不认识的 cmd 时，按弹幕、礼物、进场分类警告“收到不认识的{类别}消息 {Command}，{类别}消息格式可能变了”，同一直播间连接中每个 cmd 只警告一次。
礼物格式是 V1（`SEND_GIFT`）或 V2（`SEND_GIFT_V2`），进场格式目前是 V2（`INTERACT_WORD_V2`）；进场只在进场欢迎或欢迎动画开启时记录。
自动重连保留版本和已警告 cmd 的记录，新直播间连接重新开始。

## CLI 与直播间连接

弹幕以 UTF-8 写到 stdout：`[HH:mm:ss] 昵称 [舰长][粉丝团 47][荣耀 45]: @被回复的昵称 内容`；粉丝团等级、荣耀等级、大航海身份没有时不写对应的方括号，大航海身份按实际显示舰长、提督或总督，没有被 @ 的观众时也不加 `@昵称 `。输出不使用 ANSI 颜色；状态和日志写到 stderr。
Ctrl+C 关闭连接并正常退出，错误返回非零退出码。每次 `watch` 开始直播间连接时，
先解析短号或真实房间号，成功后只使用这个真实房间号，重连不再请求 room_init。
解析时的临时网络失败按下面的重连节奏重试；不存在的直播间立即报错，不扫码、不连接、不重试。
随后获取直播间锁，再用保存的 cookie 调 nav 检查登录状态；没有凭据或已失效时，在 stderr 显示二维码，
扫码成功后保存凭据并继续连接，无需先运行 `login`。二维码过期自动换新，扫码期间也可按
Ctrl+C 取消。连接使用 nav 返回的 mid 和凭据中的 buvid3，HTTP 请求携带保存的 cookie，
以接收观众的真实昵称。网络失败、超时、B站 服务器 5xx 或弹幕服务器断开时，`watch`
提示“重连中”，按 1、2、4、8、16、30、30…… 秒自动重试；收到认证成功回复后重置为 1 秒。
60 秒没有收到任何数据也会重连；心跳回复正常的安静直播间不会断开。
每次重连重新获取 wbi key 和弹幕 token，中途凭据失效或被 `logout` 删除时暂停接收弹幕，
显示二维码重新登录，成功后继续连接同一个直播间。等待扫码时也会检查本地数据库，
可在另一个终端运行 `login` 或在 GUI 登录，经 nav 确认有效后恢复连接；新凭据未生效时记一条警告并重新显示二维码。扫码阶段的网络失败仍每 2 秒原地重试，
不提示“重连中”，也不作废已显示的二维码。B站 明确拒绝（错误码含房间号不存在、HTTP 4xx、
弹幕认证失败）、无法解析的 HTTP 或认证响应、损坏的弹幕帧、本地错误（如数据库）和程序缺陷，
重试也不会好转，反复请求还会加重风控，所以直接报错退出。单条直播间消息不是合法 JSON、
缺少有效 cmd，或 DANMU_MSG 取不到昵称或内容时，只跳过该条并记一条警告，能读取 cmd 时一同记录；
后续弹幕继续接收。包头无效、解压失败和协议版本不支持仍直接报错退出。重连等待期间 Ctrl+C 也会立即结束。

## 直播间锁

同一个 `data/` 中，同一个真实房间号只允许一个直播间连接（短号和真实房间号也会冲突）。
Core 独占打开 `data/room-<真实房间号>.lock`，在扫码和断线重连期间持续持有；
第二个 CLI 或 GUI 会在检查登录、显示二维码之前报“直播间 … 已有直播间连接”，不会重试。
CLI 输出“错误：……”并以非零退出码结束；GUI 显示连接错误，状态回到“未连接”。
取消、出错或释放更新流都会释放锁并删除锁文件；进程崩溃时由操作系统释放锁，
留下的锁文件在下次连接同一直播间时复用。不要在连接运行期间删除它。同一目录可同时连接不同直播间；不同数据目录互不影响。
macOS / Linux 上的锁是 flock，`data/` 应放在本地磁盘上，部分网络文件系统不支持。
`login` 和 `logout` 不获取直播间锁，观看期间可在另一个终端执行。

## 登录凭据

`login` 先打开数据库、获取 buvid3，再在 stderr 显示字符画二维码，用 B站 App 扫码并确认。
每两秒轮询一次，过期后自动打印新二维码，成功保存凭据后提示“已登录”。网络错误（连不上、
HTTP 非 2xx、超时）记一条警告，两秒后重试，直到成功或 Ctrl+C；B站返回的错误码直接报错退出。
Ctrl+C 取消并正常退出。`logout` 先调用 B站 退出登录接口，让服务器端的 SESSDATA 失效，再删除本地登录凭据，可重复执行。
B站 端退出失败（网络错误、错误码、cookie 已失效）时记一条警告，仍删除本地凭据；
Ctrl+C 取消则保留本地凭据。

连接、重连前和连接期间，距上次检查满 24 小时才检查是否需要刷新登录凭据；
只在 B站 返回 `refresh=true` 时刷新。新凭据保存后才确认作废旧凭据，确认失败只记警告。
已发出的刷新请求不随直播间连接结束而取消，连接等它保存完再重连。
检查或刷新遇到临时网络错误时保留原检查时间，连接照常，连接期间 30 秒后再试；
`cookie/info` 返回错误码、刷新页面结构变化等其他失败记一条警告，24 小时后再查，连接照常，
凭据是否有效仍由每次连接前的 nav 判断。B站 拒绝刷新请求时删除仍匹配旧 refresh_token 的凭据，
结束当前连接，转入重新登录。连接期间凭据被另一个进程删除（如 `logout`）时停止检查，当前连接照常，
下次重连时要求扫码。刷新结果不会覆盖另一个进程刚保存的凭据，也不会把已经退出的登录写回来。

## 数据目录与数据库

数据目录遵循 [ADR 0002](adr/0002-portable-data-directory.md)：Release 用程序目录下的 `data/`；
Debug 从程序目录向上寻找 `Aether.slnx`，用其所在目录下的 `data/`，找不到则退回程序目录。
与启动命令所在目录无关。SQLite 文件是 `data/aether.db`，使用 WAL；`PRAGMA user_version`
记录表结构版本，当前为 8。升级使用手写 SQL，并与版本号在同一事务中提交。
v2 升级到 v3 保留登录凭据，新增 `blind_box` 表，按真实房间号、观众 uid 和送出时间建立索引。
v3 到 v4 把抽奖表纳入版本号，保留已有表和数据；v0.2.x 已有的抽奖表结构不变。
v4 到 v5 给 `lottery_draw` 加不挂出标记 `hidden_from_stream`（开奖结果的 JSON 不变），新增 `lottery_prize_set` 存奖品方案：按直播间、抽奖方式和名称唯一，内容是一列 JSON。
v5 到 v6 新增盲盒统计和礼物榜共用的收礼记录 `gift_record`，把 `blind_box` 的每一行搬进去（标为盲盒统计要、不在礼物榜的任何一期，头像和图标为空），再删掉 `blind_box`，盲盒不再保存原始消息，已记下的原文随旧表一起删除；新增礼物榜的期 `gift_board_period`，是空的。今日、本月的盲盒金额和升级前一样，其余数据不变。
v7 到 v8 新增只有一行的 `gui_state`，存 GUI 记下的最近房间号（JSON 数组）和“只保留最近 1000 条”；`lottery_prize_set` 去掉 `room_id`，改为按抽奖方式和名称唯一，不同直播间有同名同方式的方案时，最近保存的保留原名，其余的名字后面加“（直播间 <房间号>）”；这个名字已经有方案用了时，依次试“（直播间 <房间号>，2）”“（直播间 <房间号>，3）”……用第一个没人用的。
`credential` 表只存一行，保存完整 cookie 名值 JSON、refresh_token、UTC 保存时间和检查时间 `checked_at`。
v1 升级后保留原凭据，检查时间为空，下次连接立即检查；扫码或刷新保存时检查时间等于保存时间。
凭据暂存明文，`data/` 已被 Git 忽略；连接开启 `secure_delete`，删除或覆盖的凭据不会残留在文件里。
macOS / Linux 上数据库文件（含 `-wal` / `-shm`）权限为 0600，只有当前用户可读写；Windows 依赖目录继承的 ACL。
`login` / `logout` / `watch` 都会打开数据库。CLI 与 GUI 放在同一发布目录时共用这些数据。

## Core 结构与测试

Core 的业务入口都在 `AetherClient`：`LoginAsync` 返回 `LoginQrCode`、`LoggedIn` 更新流；
`LogoutAsync` 删除凭据；`WatchAsync` 返回 `WatchQrCode`（需要登录时）、`Connecting`、`Connected`、`Reconnecting`、`Danmaku`、`SendQueueUpdate` 更新流。
`SendQueueUpdate` 报告盲盒查询、盲盒播报和进场欢迎进入发送队列、开始发送、成功、等待重试、丢弃，以及欢迎命中却没进入发送队列的原因。
每项编号在进程内不重复，自动重连后沿用；连接结束不逐项报告丢弃，由外壳标记未完成的项。CLI 忽略这些更新，继续使用现有日志。
取消或释放更新流会结束对应操作。测试从这些入口驱动，注入假的 HTTP、真实 BCL WebSocket 的本地对端、
`FakeTimeProvider` 和独立临时数据目录，使用真实 SQLite，不访问 B站。真实捕获测试帧的来源与脱敏方式见
[Fixtures/README.md](../tests/Aether.Core.Tests/Fixtures/README.md)。

CLI 和 GUI 启动时各调用一次 `DataDirectory.Locate()`，把路径传给 `AetherClient`。生产环境统一使用 `AetherClient(logger, dataDirectory)` 构造函数组装 HTTP、WebSocket
和系统时间；测试继续使用可注入这些依赖的构造函数。

测试使用 xUnit v3 的 Microsoft Testing Platform 运行器（由 `global.json` 选择）：

```sh
dotnet test --project tests/Aether.Core.Tests --filter-class Aether.Core.Tests.ProtocolTests
```
